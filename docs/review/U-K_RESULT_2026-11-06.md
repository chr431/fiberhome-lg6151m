## 3. 判读：T1 关断与模型终局

1. **链①（内容馈源）证伪**：环冻结时，本地洪水的 λ 仍达 14.2/min（feed-on 的 80%）。
   内容通道既非必要（断供后仍激增）也非充分（U-J：环稳产而 λ 6× 变）。
2. **λ 的真实驱动 = 设备面向的处理活动**：本地 INPUT（内核栈处理/软中断/唤醒）≫ 转发
   （hnat 硬件旁路）≈ 空闲；这同时解释了 U-H/U-I 的"洪水 hot 档"（当时洪水全为本地 INPUT）
   与 U-J 的"环率恒定"——两个观测在一个模型下统一。
3. **T1 作为根治路径关闭**：不存在"断内容通道"的本地措施能让写者饿死；写者的注入调度跟随
   活动模式（与 W1 的 32B-store 捕获签名互补：**靶标捕获=store 形态，注入时机=活动水平**）。
4. **对总路线的落点**：阻断写者写入的本地路径现况——
   - 引擎控制面：EL1/AP 全域关闭（C-266/C-272/C-276/C-277/C-294）；
   - 内容断供（T1）：**本轮关闭**；
   - 放逐（T3）：已关闭；
   - **T5 隐身：唯一设备级验证通过的缓和**（双 boot 0/120，零性能代价）；
   - 后果层（T6）：门禁修复待做（nerepair 重扫）。
   ⇒ 程序重心正式转 **Scheme A 落地（真守护部署）+ 后果层修复**；T2/T4（厂商/boot 链）
   仅存理论价值。
