## A. 与代码实际行为不符（P0）

### G-01 MLO"需重启网关"声明已过期

- 位置：`app.js:217`（选项"MLO 真双链路 (WiFi7并发, 切换后需重启网关)"）、`app.js:286`（toast"需重启网关生效"）
- 实测行为：`wifi_up.sh` v1.23（行 468–478）已实现在线重应用——MLO 下若 `ra0` 已 UP，先把 `ra0/rai0/ra1/rai1` 完整下电回"冷启动等价态"再重建；`api.sh` v2.43（行 684–691）注释明确"撤销 v2.41 的 mlo_reboot 纪律……MLO 下改动恢复即时生效"。`api.sh` 全文**不返回** `mlo_reboot` 字段，故 `app.js:288` 的 1500ms 分支是死代码。
- 建议：选项与 toast 改为"切换后无线会短暂中断并重建（无需重启整机）"；删除 `j.mlo_reboot` 分支。
- 注：`wifi_up.sh:68` 的 v1.19 注释"切换 MLO 后必须 reboot"同样过期，属脚本侧注释，可一并清理。

### G-02 蜂窝状态标签恒显"5G"

- 位置：`app.js:91` `tag("tg-cel","5G","无服务")`；同一文案在 SSE 推送路径 `app.js:193` 复用
- 实测行为：`api.sh:699` 硬置 `CELL_ENGINE=mipc`，且全仓无任何脚本写 `CELL_ENGINE=tree`（`mipc_cellular` 在 `tools/VERSIONS.tsv:81` manifest 行），故设备实际只走 mipc 分支。该分支 `api.sh:702-711` 透传 `mipc_cellular cells` 输出，而 `mipc_cellular.c:191` 的 serving JSON 字段为 `band/arfcn/pci/rsrp/sinr/bw/plmn/tac`——**没有 `rat` 字段**。因此 `cel.serving.rat !== "--"`（`app.js:117`）恒为真，只要有服务小区就显示"5G"。
- 建议：tag 文案改为中性"已驻网/无服务"，或由 band 前缀（N/L）派生制式后再显示。

### G-03 服务小区频段显示为 "BN41"

- 位置：`app.js:119`、`app.js:193`（SSE）、`app.js:747`
- 实测行为：mipc 分支 serving.band 由 `mipc_cellular.c:191` 输出为 `"N%d"`（已是 `N41`），GUI 再前置 `B` → 显示 **`BN41`**（树路径 band 为纯数字 `41`，`B41` 才正确）。
- 建议：频段原样显示（`N41`），或统一为"n41/41"一种格式。

### G-04 状态页"载波聚合"显示 "undefined 个小区"

- 位置：`app.js:121` `` T("cel-n", `${cel.cells.n} 个小区`) ``
- 实测行为：mipc 响应中 `cells` 是**数组**（`mipc_cellular.c:197` `"cells":[...]`，经 `api.sh:711` 透传），`j.cells.n` 不存在 → 模板字符串输出字面 **"undefined 个小区"**。首轮清单仅判为"标签与值语义不符"，实际更严重。
- 建议：改读顶层 `n`（`api.sh:711` 已透传 `"n":N`）。

### G-05 蜂窝页"实时小区列表"恒空、计数恒 0

- 位置：`app.js:754-758`
- 实测行为：GUI 按树形对象读取 `j.cells.band/arfcn/pci/rsrp/sinr`（逗号分隔字符串），而 mipc 下 `j.cells` 为对象数组 → 五个取值全为 `undefined` → `bands` 为空数组 → 表体无行；`T("ce-n", j.cells.n || 0)` → 卡标题恒显"实时小区列表 (0)"。
- 建议：按数组形态渲染（读 `j.cells[i].band/arfcn/...`），保留树形分支为回退。

### G-06 加密方式硬编码 "WPA2-PSK (AES)"

- 位置：`app.js:263`
- 实测行为：只读 `j.secured` 布尔（`api.sh:94` `wifi_state` 仅输出 `secured`），而 `AUTH` 可取 `WPA2PSK|WPA2PSKWPA3PSK`（`api.sh:668` 白名单，`app.js:210` 也提供该选项）。选 WPA2+WPA3 时界面仍显示 WPA2-PSK。
- 建议：从 `wifi_adv` 的 `auth` 字段派生显示。

### G-07 页头副标题尾部悬空分隔符

- 位置：`app.js:135`

- 建议：改 `j.agg.wanmode`，并按 G-13 做文案映射。

### G-08 PIN 操作 toast 尾部悬空冒号

- 位置：`app.js:807` `toast("PIN 操作已下发: " + (j.ubus || ""))`
- 实测行为：`j.ubus` 只在树回退路径返回（`api.sh:356-359`），而默认 mipc 路径返回 `{"engine":"mipc"}`（`api.sh:341`）→ 实际提示为 **"PIN 操作已下发: "**（空尾）。首轮清单称"直出 ubus JSON 原文"，在默认引擎下不成立（该分支不可达）。
- 建议：改为固定文案"PIN 操作已下发"。

### G-09 引擎/开关状态缺失时误报

- 位置：`app.js:124`
- 实测行为：`j.agg.engine === "vendor" ? "quecadp (原厂)" : "iptables"`——`/tmp/wan_engine` 缺失时 `engine=""`（`api.sh:1009`），仍落到 `"iptables"`；同一行的 `on` 判定为 `grep -q '^off' /tmp/wan_mode`，文件缺失时 `grep` 失败回 `1`（`api.sh:1009`）→ 标签显示"运行中"。即引擎与运行状态**未知时都按"正常"呈现**。对照聚合页 `app.js:638` 对空值显示 `"--"`，两页口径不一致。
- 建议：空值统一显示 `"--"/未知`。

### G-10 "异常"为死文案

- 位置：`app.js:608` `tag("ag-on","运行中","异常")`，`app.js:634` 恒 `setTag("ag-on", true)`
- 实测行为：off 文案永不出现；同一语义在状态页写作"未启用"（`app.js:93`）。
- 建议：删除该 tag 或按真实状态判定，并与状态页统一用词。

### G-11 "自动加频段后缀"条件不成立

- 位置：`app.js:208` "WiFi 名称 (统一名称, 自动加频段后缀)"

### G-12 "同名单频(漫游)"措辞错误

- 位置：`app.js:217`

## 部署后抽检补充发现（G-47，api.sh v2.46 修复）

**2026-10-06 部署后浏览器抽检抓获，审计与术语表均未覆盖（属 api.sh 数据面 bug，非文案）**：

- **现象**：蜂窝页"4G 频段 / 5G 频段"输入框显示字面量 `${LTE_MASK:-}` /
  `${NR_MASK:-}`；`bandlock.enable`/`celllock.enable` 恒为 `${BAND_EN:-0}` 字面量
  （GUI 侧 `=== "1"` 恒假 → 频段锁定/小区锁定 tag 永远显示"已关闭"，
  与实际锁定状态无关）；mipc 分支 `celllock.entries` 恒 `[]`（已加的小区锁
  在 GUI 表中永远不出现）。
- **根因**：`api.sh` v2.45 `get_cellular` mipc 早退分支把 `bandlock`/`celllock`
  对象写进 printf **单引号格式串**——shell 变量不展开，原文直出（正是术语表
  T-30 禁止的"内部标识外泄"的设备侧变体）；entries 则硬编码空数组。
- **修复（v2.46）**：bandlock/celllock 六值改经 `%s` 参数展开（source
  cellular.conf 后的 `BAND_EN/LTE_MASK/NR_MASK/CELL_EN`）；entries 复用树路径
  同款 `CELL_i` 回读循环构造。本地 JSON 合法性模拟验证通过。
- **复验**：部署后蜂窝页输入框显示真实掩码/空值+占位符，锁定 tag 反映真实状态。
