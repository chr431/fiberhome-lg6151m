## 1. PIT_NAT 设备闭环

### 1.2 条目结构（解码）

```
offset 0x2920: 000001410003004b 0000009400000a48 909c0040001d0a48 0000009500000000
按 16B×2 拆（LE u32）:
  描述符1: hdr=0x0003004b(seq 0x300..) len=0x141(321B) bat_off=0x0a48 idx=0x94
  描述符2: bat_off2=0x1d0a48  DRAM_PA=0x909c0040  ...
```
- 相邻条目 len = 0x140,0x141,0x142,0x143 → **包长连续递增**（320..323B），与洪水包 321B 完全吻合；
- `DRAM_PA` 落在 0x8xxxxxxx/0x9xxxxxxx（真实物理地址），`bat_off` 每 8 递增 = BAT 环槽位；
- **全环搜索 IPv4 字节型（c0a80901）与逆序（0109a8c0）：0 命中**（524 条非空 ×8 词全覆盖）。

## 2. 32B 拆宽工程

### 2.1 站点普查修正（本轮最大坑）

- 初版掩码 `(w & 0xFF800000) == 0xAD000000` 同时命中：
  - `stp q,q,[xN{,imm}]`（0xAD0xxxxx，bit22=0）——真目标；
  - `ldp q,q,[xN{,imm}]`（0xAD4xxxxx，bit22=1）——**加载**，被误当 STP；
- 后果：trampoline 把"加载 va_list 到 q0/q1"改写成"把垃圾 q0/q1 存入 va_list"→ 程序崩溃，
  且因调试样本恰为 LDP 站点（0x4e6e58 实为 `ldp q0,q1,[x21]`），一度误判"trampoline 机制
  本身不可用"；
- 修正：`0xFFC00000 == 0xAD000000`；objdump 真值 **372 条 stp q**（sp 内 10、非 sp **362**），
  与 U-T 的 363 口径吻合；142 条 LDP 排除后全部 trampoline 行为正常。

### 2.2 变换与编码

- 站点 `stp qA,qB,[xN{, #imm}]`（N≠31，imm 可负）→ 1:1 `b tramp_i`（4B 换 4B，无原地扩展）；
- trampoline（12B/站点，全 362 条 = 4344B ≤ 8KB 块）：
  ```
  str  qA,[xN,#imm]      ; 正偏移：0x3D800000|(imm/16<<10)|(Rn<<5)|Rt
  str  qB,[xN,#imm+16]
  b    site+4             ; 0x14000000|((site+4 - here)>>2)
  ```
  负偏移改 `stur qA,[xN,#imm9]`（0x3C800000）。`b` 不碰 x30/栈/flags ⇒ 叶子/非叶子皆安全；
- 布局：tramp 块放文件 0x126000（PT[0] va 连续 ⇒ va 0x526000），PT[0] filesz=memsz 扩到
  0x128000（< PT[1].va 0x531b10，无 VA 重叠；同一文件字节在 PT[1] 的 va 另映射，合法）；
- 产出：`bb_split32_v7` md5 **7f4f4ee93f60f35ebec7b61d048e257d**；脚本重跑逐字节一致；
- 剩余 32B 面：sp 类 10 条 stp（FP save area，按设计不动）+ 162 条 `str q→[sp]`（16B，非 32B
  对）+ 142 条 LDP（加载，无写指纹）。

## 3. 三栏

**[A] 已核实**
1. PIT_NAT 环 live dump：524/5450 非空；条目 {hdr,len,bat_off,idx|bat_off2,PA}；len 连续
   0x140..0x143；**无 IP 字段**（0 命中）。
2. STP 真值 372/非 sp 362；LDP 142 条误判是本轮全部 trampoline 崩溃假象的根因；掩码应为
   0xFFC00000。
3. 362 站点拆宽二进制功能等价（qemu 10/10；真机 50 help 逐字节；功能全等；3500 调用零塌）。
4. 效果阴性：v7 洪水窗同族命中（同历史 PC），p11 对照 0/700 与 v7 二臂 0/1300 ⇒ 无收益；
   与 C-329 一致。
5. 设备终态：p11 生产挂载恢复；v7 清出 /data；pit_reader permanent 待重启自清。

**[B] 未核实/边界**
1. PIT_NAT 环与家族 B 记录的关系只剩"len 语义相同"；记录的 ip 字段出处与消费者仍未定位。
2. A/B 统计量小（单窗 700 轮、2 起 vs 0 起），只能判"无差别"，不能排除 <2× 的效应。
3. 拆宽覆盖的是静态 busybox；libc/动态 busybox/wpad 未拆（但受害者家族主要在静态件）。
4. sp 类 10 条 stp 与 162 条 str q 未拆（按 U-H 指纹定义不是 32B 对事务）。

**[C] 下轮入口**
1. B 家族消费者最后候选：flow/route key 描述符（含 {len, ip} 的 32B 结构）——在内核
   netfilter/route 路径与 modem PDN 侧继续找；或接受"消费者不可达"结论。
2. 若坚持隐身线：只剩"编译器级重建"（musl/busybox 源码层消除 q-pair va_list 拷贝），
   代价高、且按本轮结论**预期同样无收益**（32B 宽度非键）。
3. 引擎侧仍是唯一真路径（T7 厂商；T4 位定义依赖外部）。
