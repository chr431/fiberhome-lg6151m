# U-A1 · RO-PTE 哨兵：写入者定向方式判决（2026-11-04 夜间轮）

> 目的：判定 32B 记录写者是否**绕过 MMU**（非 CPU / DMA 类）还是**遵守 PTE**（CPU/uaccess 类）。
> 装置：scanary_ro（scanary 1.2 的 RO 扩展），在受害者的**活 va_list 页**上做整页 PROT_READ，窗内用扫描器命中 + 页级 changed-byte map 判读。
> 判据：skeptic 预注册 §6.11（λ 表）、§6.12（事后代理阈值）、§6.13（事前裁定：guard band 200 ms、页归属、inj=0、carry-over）、§6.14（TLS 精确判据 amend）。
> 纪律：每窗先过装置自检（单实例 / 停放 / 活栈守卫 / 逐线程 altstack / 先恢复后 dump），任一红即作废；不读 kmsg（nerepair 在役时结构缺席）。

## 0. 结论（**已被决定性对照推翻，本版为修正版**）

**最终结论：本版"停放 + RO"设计被混杂废掉 —— 0 命中不能归因于 PTE；今晚未获得 CPU/非 CPU 判决。但对照本身给出了一个机制线索：写者依赖受害者运行。**

决定性对照（perf-reviewer，2026-11-04 01:50–02:00，同 victim/同 D 0x1000/页保持可写，只把受害者停放 600 s）：
- **停放 600 s 内自然命中 = 0 条**（同页、inj=0、含 guard）；
- `RO_END`（600.03 s）后 **3.9 s 起、29 s 内 5 条命中**（同页 poff=0x290，≈**10.2/min**）；
- 与 clean RO 臂的窗后速率（≈18/min）同量级。
- ⇒ 若写者与受害者状态无关，停放窗期望 ≈100 条，观测 0 ⇒ P(0)≈e⁻¹⁰⁰ ≈ 0 ⇒ **写者只在受害者运行时写**。
- ⇒ 本版 RO 窗的 0 命中由"受害者停放"解释，**与 PTE 无关**；§0.0 原"未判定（≤E1）"的定性**作废**（那是基于"停放态与运行态同率"的假设，该假设已被证伪）。

### 0.0 仍成立的部分

- 装置本身：停放/守卫/页级判据/恢复顺序/单实例/TLS 排除全部可签收（缺陷 5 项已修）。
- 机制线索（非判决）：**写者的写与受害者执行强相关** ⇒ 不是"对所有映射页无差别扫写"的被动 DMA 行为，更接近与受害进程执行上下文绑定的路径（uaccess/GUP 类）；但这是相关而非因果，需下一轮判决。

### 0.0 最终分类（skeptic §6.15 改判）

**INVALID-by-confound（方法被混杂、无判决力）** —— 比"未判定"更准确：未判定 = 设计对但功效不足；混杂 = 设计**无法回答该问题**。

**连带结论**：**所有停放态 RO 窗（540 s、1200 s D=0、1800 s clean）对层 2 均无判决力**。§7 的层 2 行改为「**无判决性证据（RO-长窗 + 停放路线被证伪为混杂）**」。

可保留的状态性事实（降级）：**停放态 1800 s 内该页 0 条写（≤0.1/min）** —— 由"写者不写停放受害者"解释，**与 PTE 无关**。

**设计级前置（下一版预注册必含，非判读表条目）**：
1. 开 RO 窗前**先测同状态 RW λ**；**λ < 10/600 s ⇒ 直接判"该设计无功效"，不开 RO 臂**（省设备与时间）。
2. 混杂变量清单第一项：**受害者停放态 vs 运行态**；λ 臂与 RO 臂必须**同状态**。
3. 一句话判据：`同状态 RW λ<10/600s ⇒ INVALID-by-confound，不得写阴性/未判定/PTE-aware`。

### 0.0a 混杂的正面价值：写者与受害者执行同步（E1，相关非因果）

- 反对 H1a/H1b/H3/H4（陈旧 PA DMA / 直映射 / HW 描述符异步写回）——那些与受害者是否在跑无关；
- 支持 H2/H6 一类**在受害者上下文/系统调用路径上发生的写**；
- 相容解释还包括：写发生在 hold_sleep 的 nanosleep 系统调用进入/退出附近（每轮一次机会）。
- **探针 ①（2026-11-04 02:02，8 s 全速循环）**：iters=8,554,917（≈1.07 M 轮/s）、passes=1542、**命中 0** ⇒ 每轮命中概率 **<3.5e-7**（rule of three）。**结论：写者不与"每轮 va_list 调用"绑定**（否则会是洪水）；速率是**墙钟/流量驱动**。限制：记录寿命 ~0.9 µs ≪ 扫描 5 ms ⇒ 该臂对"是否存在写"无功效，只对"是否每轮"有功效。
- **探针 ②（引用 docs/SIGSEGV/05_LOG/2026-11-02-03-d14-h6-sp.md 的预注册旧数据，省 600 s）**：同会话 A/B/A，sleep 臂 555/1200 s = **0.463/s**，busy 臂（用户态自旋、不进内核）639/600 s = **1.065/s**，R_A/R_B=0.43；预注册判决 **WEAKEN H6**（busy 不低反高）。⇒ **写者不需要内核进入**。
- **两条合起来**：写者要求受害者在**用户态执行**（不是"在 syscall 里"、也不是"每轮调用"） ⇒ **H2（uaccess-in-syscall）与 H6（pt_regs->sp）双双被削弱**；剩余解释倾向于"与受害进程的内存访问/活跃状态相关的写"，但**仍不指名 CPU 或 DMA**。
- **时间相关性臂（2026-11-04 02:0x–02:11，600 s，calltrace：调用窗 ~10.4 ms / 空闲 30 ms）**：14,300 窗 / 584.4 s、占空 **25.5%**；自然命中（HIT_APPEAR+HIT_CHANGE, inj=0）**95 条**。
  - 判据 (a)：窗内 **48/95 = 50.5%**（若与调用无关预期 25.5%）；
  - 判据 (b)：窗外 47 条的「距上次 CALL_END」**0.2–5.0 ms（中位 2.8 ms），全部 ≤5 ms**；而记录驻留实测 ~5 ms（HIT_GONE residency_ms=5）、观测相对写入有 ≤5 ms 滞后 ⇒ **95/95 条都与"写发生在调用窗内"相容，0 条需要 30 ms 空闲期写入**。若写入在 40 ms 周期内均匀分布，应有 ~59 条 gap>5 ms（62.5%）；实测 0 ⇒ **P≈(0.375)^95 ≈ 1e-40**。
  - 窗内延迟（自 CALL_BEGIN）：min 0.06 / p25 1.08 / **p50 2.26** / p75 4.00 / max 4.87 ms ⇒ 写集中在**调用窗前半段**，后半段 5.5 ms 无一条。
  - ⇒ 与「按活帧现场解析目标」（C-171）一致；**与 H7（按进程缓存固定 VA）不一致**（若为固定 VA，空闲期同样会被写 ⇒ 应出现 gap≫5 ms 的命中；实测 **R1 0/95、R2 2/124（最大 10.4 ms）**，按 5 ms 驻留包络基本排除）。
- **同 boot 独立重复 R2（02:1x–02:2x，600 s）**：13,126 窗 / 536.0 s / 占空 25.5%；事件 124（APPEAR 90 + CHANGE 34），窗内 **59/124 = 47.6%**；窗外 65 条 p50 **2.08 ms**，仅 **2 条 >5 ms**（max 10.4 ms）。**pooled（R1+R2）：219 事件，窗内 107 = 48.9%**（vs 25.5%，二项 p≈1e-15），**217/219 与「写发生在调用窗内（滞后 ≤5 ms）」相容**。⇒ 双窗一致，E2。
- **综合（H 层判决）**：**H1a/H1b/H3/H4（异步 DMA/直映射/描述符写回）、H6（内核保存 sp）、H7（缓存 VA）均被今晚数据削弱或否证**；**H2（uaccess 类）是唯一未被削弱的内核侧类别**，但 D14 表明它**不在 syscall 路径**上 ⇒ 若成立，只能发生在中断/异常返回等非 sleep 上下文中（这一分支需要脉冲式缺页归因去证实/证伪，见 0.0b）。
- **机制小结（截至本轮，E1–E2 相关非因果）**：写者要求受害者**在用户态执行**（停放 ⇒ 0；全速/空闲运行 ⇒ 有），**不要求内核进入**（busy ≥ sleep，预注册 D14）、**不绑定每轮调用**（全速 0 命中）、但**在调用相位有 ~2× 富集**。⇒ **H2（uaccess-in-syscall）与 H6（pt_regs->sp）被削弱**；剩余解释倾向于"与受害进程用户态活跃状态相关的写"，**仍不指名 CPU 或 DMA**。

### 0.0b 下一版设计必须解决的核心矛盾

va_list 在 AArch64 是**内存结构**，`va_arg` 消费它会写该页 ⇒ "受害者活跃 + 该页 RO 长窗"**物理上不可能**。skeptic 排序（§6.15 ④）：

1. **（首选）脉冲式 RO + 缺页归因**：短 RO 脉冲（~0.5–1 ms，受害者保持运行）＋ 每次缺页记录 fault PC/comm/时间戳（**内核侧 fixup_exception / do_page_fault 钩子**，即 fxhook 系）＋ 同脉冲内 scanner 命中相关。
   - 判读：脉冲内出现**外部 PC/comm** 的缺页 ⇒ **CPU 写并当场点名**；脉冲内有记录、**无外部缺页** ⇒ **绕 MMU（DMA，E4）**；受害自身缺页按 PC/comm 排除。
   - 注意：**调试寄存器方案被否**——按线程 VA，抓不到别的进程/内核上下文的 CPU 写（skeptic §6.3 已更正）。
2. **时间相关性判决**（次选，廉价低风险）：受害者活跃、页 RW，记录每次 vsnprintf 调用时间戳，检验记录是否只在消费相位出现 ⇒ 可把 0.0a 的 E1 升到 E2，并给脉冲设计定相位窗口；本身不判 CPU/DMA。
3. **双别名页**（建议取消或改用途）：DMA 不认别名（两 VA 同 PA，写一样可见），CPU 走 RW 别名照样成功 ⇒ **不解决 CPU/DMA**，只做 VA/PTE 归因。

- 干净 RO 长窗（v1.18，D=0x1000，1800 s，01:12:33–01:43:33）：`RO_END result=UNCHANGED`、`changed_bytes=0 / runs=0`、`shapes=2`（窗后写入）、`vap_stable=1`；装置计数 `SELFCRASH=0 / INVALID_WOKE=0 / RO_FAULT=0 / RO_INVALID=0 / RO_ERR=0`；TLS 判据 `d=poff+topminusap=0x5d0+0x1590=0x1b60 ≥ 0x12d8`（干净通过）。
- **in-window（RO_ON+200 ms < EV < RO_OFF，va∈守护页，inj=0）= 0 条**；上界 rule-of-three 3/1800 s = **0.1/min**，与 RW 臂 λ=0.1/min 相同 ⇒ **无判别力**，故只能"未判定"。
- **RW 暴露不足**：RW 臂页内命中仅 **1 次/600 s（n=1）** < 10 ⇒ 按预注册**本轮无法给出 PTE-aware 正面结论**（唯一升级出口是 RO≥1 ⇒ 非 CPU 写 E4，本轮未出现）。

### 0.1 非预注册观察（**不得当本轮结论**，skeptic 已裁定其解释）

`RO_OFF`（EV 1,800,035,440 µs）之后 4 s 起，同一守护页在 48 s 内出现 **11 条 `inj=0` 命中**（poff=0x500）⇒ 窗后率 ≈13.7/min。

**skeptic 裁定（§6.15，推翻"RO 解除"解释）**：窗内受害者处于**停放态**（futex），该状态写者率由 RW 臂给出 = **0.1/min**；窗后 helper 唤醒受害者，受害者**恢复运行**，活 va_list 才被 printf 消费 ⇒ 13.7/min **恰好落在 C-204 客户端热态 13.87–20.33/min 区间**。⇒ **这个跳变主要来自"受害者从停放到运行"的状态切换，与 PTE/RO 无关**。必须写进报告的结论句：

> 「窗后 11 命中发生在受害者已恢复运行之后，与窗内停放态不是同一状态；**不得作为 RO/PTE 的证据**。」

### 0.2 本轮最重要的方法学结论：现设计结构性低功效

- RO 臂必须先**停放受害者**（va_list 在活栈页上，不停放就没法整页 RO），而停放态写者率只有 **0.1/min** ⇒ 要凑够 §6.11 的 ≥10 命中需 **≈10,000 s** 的 parked RO 窗。
- **下一轮唯一有功效的路线**："页 RO 且受害者仍活跃"——把 va_list 放进**独立 mmap 专用页**（非栈），受害者保持 printf 循环运行，只把那一页 RO；配套 **active-RW 臂定 λ**（预期 ≈13.7/min）⇒ 1800 s 期望 ≈410，零命中 P ⇒ e⁻⁴¹⁰ ⇒ 可升级 **PTE-aware（E2 上限）**；若出现 ≥1 命中 ⇒ **非 CPU 写（E4）**。
- 两条路线下一轮都必须**预注册**：λ 臂与 RO 臂**同状态**、同 D、页归属过滤、200 ms guard band、单实例 ≥3 次枚举、`d ≥ 0x12d8`。

## 1. 装置与方法

| 项 | 值 |
|---|---|
| 受害者 | `scanary_ro --victim main --depth-list 0x1000`（单帧深、固定） |
| 保护对象 | `page(&ap)`（活 va_list 页，自报 VAP/page/poff/topminusap） |
| 停放 | futex 值语义：受害者发布 seq → FUTEX_WAIT；helper 确认 `/proc/self/task/<tid>/stat ∈ {S,D}` 后才动 PTE |
| 恢复顺序 | 先 mprotect(RW) → 再 dump/比对 → 再发布 g_ro_done → 才唤醒 |
| 页级判据 | PAGEMAP（整页前后快照 → 变更 run/字节数）**降为辅助** |
| 主判据 | 扫描器命中：`va ∈ [page,page+4096)` ∧ `inj=0` ∧ `first_seen > RO_ON+200 ms` ∧ `< RO_OFF` ∧ RO_OFF 后仍见 ⇒ carry-over 不计 |
| TLS 排除 | `top−page_base = poff+topminusap ≥ 0x10d8`（`[0xd8,0x10d8)` ⇒ 未排除、不计入判决；`[0x10d8,0x12d8)` ⇒ 通过但边界） |
| 单实例 | 启动 + 窗内每 60 s 重算（v1.19）；本轮为启动时断言 + Lead 3 次 comm 精确枚举 |

## 4. 暴露（λ）与功效

- RW 臂（v1.18，D=0x1000，600 s）：页内 `inj=0` 命中 **1**（`va=…3cf0, page=…3000, poff=0xcf0, topva=0x1310`，len 1585，ip 36.150.57.69）；另有 4 条 decoy（inj=1）证明检测器存活。
- λ = 1/600 s = **0.1/min**（n=1）；1800 s 期望 **3.0**。
- `p_det` 校正区间：`residency≈5 ms`（n=1）/`scan period 5 ms` ⇒ p_det ∈ [0.25,1] ⇒ λ_true ∈ [1×,4×] ⇒ 期望 **3–12**；暴露论证取上界。
- **结论强度上限**：RW<10 ⇒ 不得给 PTE-aware 正面结论；RO=0 ⇒ 只能"未判定 + 上界 0.1/min"。

## 5. 局限（引用时必须带）

1. **F4 未修**：SHAPE 只覆盖 A0B2（漏 B0A2 36/150=24% 与 q0=0）⇒ 本报告只报**字节变化事件**，不报"记录数"。
2. **两臂串行、未 bracketing**（A→B），写者率小时级可变（C-204）。
3. **λ 来自 n=1**；p_det 为区间先验。
4. **事后代理**：TLS 排除用算术判据（`top−page_base ≥ 0x10d8`），非直接测 `page(TP)`；单实例用启动断言 + 3 次 comm 精确枚举，非持续重算。
5. nerepair 处于 dry 且 attach 期 kmsg 结构性缺席；本实验不依赖 kmsg。

## 6. 下一步（把结论做成可引用）

1. **把 RW 暴露拉够**：同 D、同参数，多窗重复直到页内命中 ≥10（否则永远只能"未判定"）。
2. **挑高流量时段**：按 C-204，WiFi 客户端数据面活跃时写者率可高 1–2 个数量级。
3. **用 v1.19 正式跑**：`PAGE_IS_TLS` + 每 60 s INSTANCES 重算 + 窗口内禁写。
4. 若 RO 出现 ≥1 条窗内命中 ⇒ 直接升级为 **E4 非 CPU 写**，转入 DMA 归因（引擎级）。
