> **历史文档（2026-10-30 归档）**：当前状态见 [docs/SIGSEGV/00_STATE.md](SIGSEGV/00_STATE.md)；结论台账见 [01_CLAIMS.tsv](SIGSEGV/01_CLAIMS.tsv)。本文保留原样，勿据此判断当前结论。

> 本轮只写我亲自实测的东西。凡与 `SIGSEGV_ANALYSIS.md` 冲突处，本文给出原始读数与复现方法。

## 1. 结论摘要

1. **落点被精确钉死**：崩溃不是「写坏栈上某个东西」，而是 32 字节整体覆盖了 printf 正在使用的那个 `va_list` 对象。
   证据两路：(a) 10 份 pfcanary core 里 `x2`（va_list 指针）减 `mm->start_stack` 恒为 **−0xc0**，
   而这 10 份的栈基址、页内偏移各不相同；(b) 抓到一份崩溃瞬间的完整栈镜像：记录所在 32 字节之外，
   紧邻的另一个 va_list 副本完好无损（{栈指针, 栈指针, 栈指针, {gr_offs=−40, vr_offs=−128}}），
   故障地址 0x12c8f 正好等于被覆盖记录的第一个字。
2. **§7.5 的「页尾 0xfc0」模型作废**：落点页内偏移随进程环境/布局变化（实测 0x070、0x0f0、0x270、0x2b0、0x480、0x920、0x940、0xbd0、0xc50），
   它恒等于 va_list 的地址，不是页尾取样偏差。
3. **硬件观察点在本平台完全不可用**（本轮最重要的方法论更正）：自检模块在已知内核地址上编程 `DBGWCR/DBGWVR` 后对该地址执行一次存储 ——
   调试异常从不触发，且回读确认寄存器确实被写进去了（dbgwcr2=0x7001ff3 dbgwvr2=0xffffffc001a40000 mdscr=0x9000，ID_AA64DFR0.WRPs=5）。
   ⇒ §6 的「已排除：CPU 经用户 VA 的 EL1 存储（观察点会命中）」不成立；`wtrap` 的「11 分钟零命中」是零信息量。

## 2. 记录形状（11 份样本）

```
B 型（9/11）：{u64 v0 ∈ [0xf000,0x23000], 0, u64 {hi32≠0, lo32 ∈ [0x600,0x2000]}, 0}
A 型（2/11）：{r180|r094, r1e0, bat_va, bat_pa+8}   ← 含 AP 内核内部 dpmaif 活值
```

同一时刻多个进程共享 hi32（例 0x1c28416e 同时出现在 27830/27832/27836），
但 0x0109a8c000000641 又跨 8 小时、跨两次开机复现 —— 既不是纯随机也不是每 boot 常量。

## 3. 本轮实测排除项

| 项 | 判据 |
|---|---|
| 栈页被内核复用/别名 | anon=1 lru=1 mapcount=1 slab=0 buddy=0；refcount = 1 + GUP pin bias（1024/次，已用 4 次 pin 验证 1025→2049→3073→4097） |
| ptrace 注入 | 全系统 TracerPid 全为 0 |
| KSM 合并 | /sys/kernel/mm/ksm/run = 0，pages_shared=0 |
| 释放路径写页 | 无 CONFIG_PAGE_POISONING、无 INIT_ON_FREE；且受害者页从未被释放（survivor 方案） |
| 内核里有记录的源结构 | 全 System RAM 精确 32 字节模式扫描：只命中受害者自己的栈 + 我自己模块的参数变量 |
| 静态进程被写 | spin（无 printf）外部监视 8 页 90–300 s：0 次 |
| 深层 va_list 被写 | vprobe（va_list 在嵌套帧内、每轮存活约 30 ms、4 实例）：0 次 |

## 4. 仍未闭环：谁写

- 内容含 AP 内核内部的 dpmaif 状态（r180/r094/r1e0/bat_va）⇒ 来源必须是能看见这些值的代理；
- 记录在 AP 侧没有源副本；AP 侧也没有任何可用观测手段（无 perf / 无 kprobe / 无 ftrace / 观察点失效）；
- **最硬的反证**：写入地址恒等于该进程的 live va_list，跨二进制（pfcanary −0xc0、vsurv3 −0x5c0）、跨 ASLR、跨页偏移。
  纯 DMA（按 PA 写）无法解释；能解释的只有「知道该 VA 的代理」。

## 6. 方法论教训（并入 §7）

20. **观察点必须自检**：DBGWCR 写入成功 ≠ 观察点生效。本平台 DBG 被固件禁用，任何「零命中」在自检通过前都不算证据。
    oslar_el1 要写 0（解锁），PAC 位要选对（0b01 = EL0+EL1）。
21. **core_pattern 改成文件 + ulimit -c 0 时不再产生 NE 台账**，会制造「现象消失」的假象；A/B 必须同时用进程退出码（139）做旁证。
22. **现象是阵发性的**：同一套受害者几分钟内可以 5 起/min，也可以 10 分钟 0 起。A/B 判决必须同窗对照。
23. **记录落在 va_list 而不是页尾**：所有只取页尾 0xfc0 的历史仪器（pitctl/buddyscan）对本症候天然失明。
