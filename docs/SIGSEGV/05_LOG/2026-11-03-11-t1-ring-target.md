> ops=mtk_wed+0x3130，~10.7 次/s）、N2-mtkwed-static.md（回调逐字节反汇编，E3）、

## 1. 问题

C-197 已实证 mtk_warp 的两个 tuple 入口（`wifi_tx_tuple_add` / `wifi_rx_tuple_add`）
在中性态以 ~10.7 次/s 调用，且 `ctx+0x700` 指向的 ops 表三项回调 live 解析为
`mtk_wed+0xf8`（tx_fill）/ `+0x374`（rx_fill）/ `+0x3a4`（wo_rxcnt，本 build 为空桩）。
本实验回答：

> **tuple 填充路径的 store 目标（填充回调自身的写入目标，以及填充之后 tuple 消费者
> 写入的环目标）是否被污染成用户页——即是否为「线性别名且其 PA 属于 canary 栈页」
> 或直接的「用户 VA」？** 若是，则环项被写进用户栈页的机制被点名；若全部目标都是
> 内核环区/内核栈，则 H_ring 不成立。

## 2. 静态事实与措辞修正（开窗前已定，N2 E3 + 本机 objdump 复核）

1. **填充回调的自身写入目标是调用者的内核栈 scratch，不是环**：
   - `wifi_tx_tuple_add` @0x735c：`ldr x0,[x0,#0x700]`（ops）→
     `stp xzr,xzr,[sp,#0x40]` / `stp xzr,xzr,[sp,#0x50]`（清零 32B）→
     `add x1,sp,#0x40`（dest）→ `ldr x2,[x0,#0x18]` → `x0=pkt_info` → `blr x2`。
   - `wifi_rx_tuple_add` @0x727c：`add x1,sp,#0x20`（dest）→ 同样经 ops+0x50 调用。
   - `tx_fill`（.text+0xf8，首条 `ldr x2,[x0,#0x10]`=0xf9400802）向 `[x1]` 写
     `+0..0x1d`（30B，`str/strb`，源为 pkt_info 内层结构字段）；`rx_fill`
     （.text+0x374，首条 `ldr x2,[x0,#8]`=0xf9400402）向 `[x1]` 写 `+0..0xa`（11B）。
   - ⇒ **填充回调本身不可能把环项写进用户栈**（它的目标恒为内核栈 scratch）；
     H_ring 的原始措辞（「填充回调把环项写进用户栈」）在结构上不成立。
2. **真正的环写入发生在填充之后的 tuple 消费者**：
   - `wifi_rx_tuple_add` 0x72c4：`x0 = [scratch+0] = B`（B=[pkt_info+8]）→
     `ldp x2,x1,[B,#0xc0]`（cursor/end）→ 在 `[B+0xc0]`、`[B+0xc0]+4` 做 4B RMW，
     另在 `[B+0xc0]+[B+0xbc]-6`、`[B+0xc0]+[B+0xb8]-6` 做 4B RMW。
   - `wifi_tx_tuple_add` 0x739c 同构：B=[[pkt_info]+0x10]，`[B+0xc0]` 为 cursor，
     `[B+0xbc]/[B+0xb8]` 为偏移，`[B+0x74]` 为门控字。
   - ⇒ **环目标 = `[B+0xc0]`**（B 由 pkt_info 派生）；若该指针被污染成用户页的
     线性别名，消费者就会把环项 RMW 进用户栈页——这才是 H_ring 的可测形态。
3. **对任务措辞的修正**：`ctx+0x700` 是 ops 指针（不是环基址）；环基址在
   `[B+0xc0]`，B 在回调入口由 x0=pkt_info 派生（tx: `[[pkt_info]+0x10]`；
   rx: `[pkt_info+8]`）。仪器按此实现（方案 a：回调入口解析，不做 store 点双钩）。

## 3. 假设（先写死）

- **H_ring（主）**：填充回调入口处由 pkt_info 派生的环目标 `ring_ptr=[B+0xc0]`
  是**线性映射别名**（`0xffffff8000000000 ≤ ring_ptr < 0xffffffc000000000`），且
  `ring_ptr - 0xffffff8000000000` 的页号属于**canary 栈页 PA 集合**（patrace 实测）；
  或 `ring_ptr` 直接是用户 VA（`< 2^39`，VA_BITS=39）。⇒ 陈旧/污染环基址点名，
  tuple 消费者的 RMW 写进用户栈页；`ring_ptr` 处 32B 内容应与记录族同族。
- **H_ring_direct（次）**：填充回调自身 store 目标 `dest=x1` 是用户 VA 或
  「线性别名且 PA ∈ canary 栈页」。
- **H_ring_false**：窗内全部目标都是内核页（`dest` = 内核栈/vmalloc；`ring_ptr` =
  内核 linear/vmalloc 环），且没有任何目标的 PA 落在 canary 栈页集合；按
  §6 给出分布与上界。

## 4. 仪器（tuphook v1.6，v1.5 基础上增量）

- **保留** v1.5 的两个 tuple 入口钩（mtk_warp+0x7330/0x7268，记录 x0..x3/skb len/ip/
  cntvct）与全部安全构造（nofault、per-cpu 环、guard、stop_machine 文本窗口）。
- **新增两个填充回调入口钩**：替换 `tx_fill` 首条（0xf9400802）与 `rx_fill` 首条
  （0xf9400402）为 `B` 跳板；跳板保存 x0..x3/x8/x30/x19/x20，调用
  `tuphook_fill_probe(pkt_info, dest, is_rx, slot, lr)`，随后原样执行被替换的
  `ldr` 并跳回入口+4（paciasp 在原位执行，SP 已还原）。
- **每调用记录**（128B/条，per-cpu 256 条，head 仅在记录完整后推进，防撕裂）：
  `pkt_info, dest, lr, B, ring_ptr, ring_end, b8/bc, flag74, q0..q3(ring_ptr 处 32B),
  ts(cntvct_el0), src0..src2(填充将写入的源值), meta(读成功位 + 三类地址分类位)`。
- **地址分类**（VA_BITS=39）：user `< 2^39`；linear `[0xffffff8000000000,
  0xffffffc000000000)`；vmalloc/module `≥ 0xffffffc000000000`；null=0；gap=其余。
- **dryrun=1 正对照**：定位 ops / 三回调；打印 `ctx/ops/tx_fill/rx_fill/wo_rxcnt`；
  断言 tx_fill 首字 0xf9400802、rx_fill 首字 0xf9400402、二者同页、
  `sprint_symbol` 含 `mtk_wed`；**不写一字节**。
- **live 正对照**：`/proc/tuphook` 头 `PATCHED`；两个 tuple 入口读回 = 我们写入的 B；
  两个填充入口读回 = 我们写入的 B；填充记录数在窗内增长 > 0。
- **canary**：`vsurv5`（md5 af0b6f87c5ee17e571d50751ffc4154b）≥4 实例；开窗/收窗各用
  `patrace.ko` 把每个 canary 的 8 个栈页（start_stack−k·4096，k=1..8）翻成 PA，
  形成 canary 栈页 PA 集合；崩溃 h5 dump 的 x2 也翻 PA 复核。

## 4.1 预执行门禁修订（开窗前，2026-11-03 13:0x，dryrun 实测）

- 设备内核的 `sprint_symbol()` **不解析 mtk_wed 的模块符号**（该模块符号被剥，
  实测返回裸地址 `0xffffffc00155f0f8` / `0xffffffc00155f374`，不是 `mtk_wed+0xf8`）。
  因此 §4 的「sprint_symbol 含 mtk_wed」门禁**不可用**，改为等价的静态几何门禁：
  - `ops` 必须可读且位于模块区；
  - `tx_fill == ops - 0x3038`、`rx_fill == ops - 0x2dbc`（即 mtk_wed+0xf8 / +0x374，
    ops=mtk_wed+0x3130）；
  - `tx_fill` 首字 `0xf9400802`、`rx_fill` 首字 `0xf9400402`；
  - 二者同页。
  四条全过 = 正对照通过；任一不符 = 拒绝加载（不 patch）。
- 干跑实测（2026-11-03 13:0x，boot_id `61a96e4b`）：ops=`0xffffffc001562130`，
  tx_fill=`0xffffffc00155f0f8`，rx_fill=`0xffffffc00155f374`，
  两首字匹配，`/proc/tuphook` 头 `dryrun`；**零 patch、零 oops、TRY_A=0**。
- 仪器产物：`out/tuphook.ko` md5 **5c1429e547fcd6def6a961b5bdcff43d**（250784 B，
  v1.6；128 条/CPU 填充环，128B/条；per-cpu 上限 0x4008 < 32KB）。
  首版 256 条环（0x8008）被 `pcpu_alloc` 以「illegal size」拒绝（WARN，非 oops，
  已修正）；该失败不产生任何 patch。

## 5. 窗与有效性门禁（任一不满足 ⇒ 该窗 INVALID）

1. `boot_id` 窗内不变；无 oops/panic/BUG；无计划外重启。
2. dryrun 输出与 §4 的 ops/回调/首字/同页断言逐项一致；不一致 ⇒ 拒绝加载。
3. live `/proc/tuphook` 头 `PATCHED`；填充记录总数 `N_fill ≥ 1000`（按 ~10.7/s ×
   1800s 的期望，功效下限；若实际调用率低，按实测率给出上界，不硬判 INVALID）。
4. canary 窗内 ≥1 实例存活；开窗与收窗的 patrace 栈页 PA 集合非空且可解析。
5. 采样：每 5 s 读一次 `/proc/tuphook`（maxread=64/CPU），PC 侧落原始输出；
   窗起/窗止记 `date +%s`、`/proc/uptime`、`boot_id`。
6. 收窗：`rmmod tuphook` 后两个 mtk_warp 入口与两个 mtk_wed 入口读回原始字
   （0xd503233f / 0xf9400802 / 0xf9400402），`TRY_A=0`，0 个我方模块（dieblx/patrace
   也卸），canary 全部 kill。

## 6. 判据（预写死，不改）

- **命中定义**：某条样本的 `ring_ptr`（主）或 `dest`（次）满足
  ① 类别 = user；或 ② 类别 = linear 且 `(target - 0xffffff8000000000)` 的页号
  在 canary 栈页 PA 集合内。
- **H_ring 成立**：主端点 `ring_ptr` 出现 ≥1 命中。点名样本的 `ts/seq/target/PA/
  canary pid`，并报告 `q0..q3` 是否与记录族同族（A0B2/B0A2）。
- **H_ring_direct 成立**：次端点 `dest` 出现 ≥1 命中。
- **H_ring 不成立**：主端点 0 命中且 `N_fill ≥ 1000`；给出 95% 上界 `3/N_fill`
  与完整分布（user/linear/vmalloc/null/gap/不可读），并分别给 tx/rx 与 dest/ring_ptr。
- **内容对照**：对全部样本与命中样本分别统计 `q1==0 && q3==0 && q0!=0` 且
  `len∈[0x40,0x4000]`、ip 首字节非 0/127/224..255（A0B2），或
  `q0!=0 && q1==0 && q2∈[0x1000,0x100000] && q3==0`（B0A2）的条数。
- **INVALID**：任一 §5 门禁失败；不得用 0 命中下结论。

## 7. 停止规则

1. 仪器缺陷导致崩溃 ≥2 次 ⇒ 弃该路径，停工报告（不第 3 次尝试）。
2. 每次崩溃后先读 `TRY_A`（misc p1 offset 2060，期望低字节 0x0f 且 `[1]=0`）；
   >0 且未清 ⇒ 暂停并报告（不擅自写 misc）。
3. **8 分钟 lgssh 不可达红线** ⇒ 停工，如实报告（不擅自重启、不等待用户）。
4. 窗内非计划重启：该窗 INVALID；恢复后只允许重跑 1 次（同一缺陷计 2 次）。
5. 安全红线：不写 p25/p38/p39；不碰 bootctrl；misc 只读；设备写一律经 deploy.py。
6. 18:45 硬停；18:30 前设备回中性。

## 9. 结果（实验后追加；§1–8 未改动）

### 9.1 窗口与有效性

- 开窗：`insmod tuphook_t1.ko maxread=48`（v1.6，md5
  `5c1429e547fcd6def6a961b5bdcff43d`），`/proc/tuphook` 头 `PATCHED`；
  两个 tuple 入口与两个 fill 入口读回均为我们写入的 `B`。
- 采样：设备侧 `t1_sampler.sh` 每 5 s 读一次 `/proc/tuphook`，落
  `/data/repro/t1/samples.log`。共 **21 个采样、106 s**
  （ts 1793681910..1793682016；h5 640→804）。
- **窗被 healthdog 紧急重启终止**：console-ramoops 尾部
  `healthdog: heartbeat stale >90s (hbs=876) — EMERGENCY RESTART` @uptime
  11214.412s；**不是内核 oops/panic**。sampler 最后写入 13:00:16，
  与 90 s stale 窗口一致。
- ⇒ **1800 s 全窗要求 INVALID**（非计划重启）；106 s 短窗的分布作为
  E2 下界/活体旁证保留。重启后 boot_id `998ca90a…`、TRY_A=0、A 槽、
  0 个我方模块、无 oops。

### 9.2 fill 目标分布（3047 条唯一记录）

| 端点 | 类别 | 计数 | 说明 |
|---|---|---|---|
| `dest`（fill 自身 store 目标 x1） | **vmalloc 100%** | 3047/3047 | 恒为内核栈 scratch，例 `ffffffc00801ba30`（tx）/ rx 同址；0 user / 0 linear |
| `B`（tx `[[pkt_info]+0x10]`；rx `[pkt_info+8]`） | **linear 100%** | 3047/3047 | 内核 kmalloc 对象 |
| `ring_ptr=[B+0xc0]`（consumer RMW 目标，主端点） | **linear 100%** | 3047/3047 | 唯一 rp 1930；PA 页 **0x01bc8000–0x02f37f000**（1205 个唯一页），全部低物理内存 |

- 每 CPU/方向：cpu0 tx 766、cpu1 tx 618、cpu2 rx 799 + tx 175、cpu3 tx 689；
  `lr` 恒为 `ffffffc000aec378`（tx tuple+0x48）/ `ffffffc000aec294`（rx tuple+0x2c）。
- meta：`0x42440`（tx 2248）/ `0x42441`（rx 799）= `RING_OK|DEST_VM|RP_LIN|B_LIN`
  （+RX）；**0 条读失败位**。
- **canary 栈页 PA 集合**（patrace，页对齐修正后，12 页含 top page）：
  `0b4c9e000 0b4e0d000 0b50d6000 0b517b000` 等（top page 为记录落点页）。
- **命中：0**。没有 `dest` 或 `ring_ptr` 是 user VA，也没有任何 linear 目标的
  PA 落在 canary 栈页集合内。主端点 0 命中 / 3047；95% 上界 3/3047 ≈ 0.098%。

### 9.3 内容对照

- `q0..q3`（ring_ptr 处 32B）非零 1406/3047；其中 **0/3047** 满足 A0B2 或
  B0A2 判据。非零样本呈描述符样模式（如 `24380000/67890000`、`36ee80`、
  `2710`、`00000002`），与记录族 `{A,0,{len,ip},0}` 不逐字段对齐。
- fill 自身的源值 `s0..s2`（tx: `[pkt_info]`/`+0x90/0x94/0x96`；rx:
  `+8/+0x16/+0x19`）与记录族无对应；与 T2 的「fill 内无 A/ip 源」一致。

### 9.4 mtk_wed 归属复核（回应「sprint_symbol 不匹配」）

- 重启后 `/proc/modules`：`mtk_wed` base **0xffffffc001549000**，size 0x5000；
  `/sys/module/mtk_wed/sections/.text` = 0xffffffc001549000，
  `.data` = 0xffffffc00154c000。
- `ops = ctx+0x700 = base+0x3130 = 0xffffffc00154c130`（.data 内）；
  `tx_fill = base+0xf8 = 0xffffffc0015490f8`、
  `rx_fill = base+0x374 = 0xffffffc001549374`——**均在 mtk_wed .text 内**。
- 上一 boot base = 0xffffffc00155f000（ops 0xffffffc001562130），偏移相同。
  ⇒ `sprint_symbol` 返回裸地址（`0xffffffc00155f0f8`）是因为 **mtk_wed 的模块符号
  被剥、kallsyms 无法命名**，不是归属漂移；C-197 的「mtk_wed+0xf8/+0x374」按
  **模块内偏移**成立，跨 boot 只漂 base（KASLR）。
- 仪器的正对照已改为 ops 相对偏移门禁（`ops-0x3038` / `ops-0x2dbc`），
  dryrun 通过；**不得再以 sprint_symbol 名字作为 mtk_wed 归属判据**。

### 9.5 healthdog 事故复盘

- 时间线：10993s 启动 4 个 vsurv5 canary；11002s 装 tuphook live；11022s 启动
  sampler；**11022–11128s** 正常采样（21 个）；13:00:16 sampler 停止写入；
  **11214.4s** healthdog 判心跳 stale >90s → EMERGENCY RESTART。
- 10879s 的 `fill cb names not mtk_wed` 是**单次 dryrun 门禁失败**（name 门禁），
  不是失败循环；随后改门禁、重编、10909s dryrun 通过、11002s live 通过。
- 嫌疑排序：①4 个 vsurv5 是**满 CPU 自旋** canary，且窗内 106s 产生 164 个
  h5 dump（~1.5 crash/s），可长时间饿死 userspace 的 healthdog/watchdog 心跳
  循环；②`/proc/tuphook` 每 5 s ~90 KB dump（轻）；③tuphook fill 钩 25 次/s、
  全部 nofault、无锁无睡眠（结构上不应造成 90 s stale）。
- 纪律：此后任何仪器窗必须同时监控 `/proc/healthdog`（或
  `/data/gw/logs/healthdog.log` / `watchdog.beat`），发现心跳 stale 立即收窗；
  canary 数量与 crash storm 需限流（本轮 4 个已足以触发）。

## 10. 判决（短窗，E2）

1. **H_ring 不成立（短窗 E2）**：主端点 `ring_ptr` 3047/3047 为 linear 内核低内存
   （PA 0x01bc8000–0x02f37f000），0/3047 为用户 VA，0/3047 命中 canary 栈页；
   95% 上界 0.098%。**tuple 填充路径的环目标没有被污染成用户页**。
2. **H_ring_direct 不成立（E2）**：fill 自身 `dest` 3047/3047 为内核栈
   （vmalloc），与 T2 的 E3「fill dst 恒为内核栈」一致。
3. 内容侧：ring 32B 0/3047 与记录族对齐；fill 源值无 A/ip 对应。
4. **1800 s 全窗未达成**：本窗被 healthdog 紧急重启终止（非 oops）；
   上述结论只覆盖 106 s 背景态短窗，不外推为全窗率。
5. 残余：真实写者仍在集合外（0x20 步长 DMA 环/表 / FOE 路径为下一靶点，
   见 T2 静态线与后续 T1 转线报告）。
