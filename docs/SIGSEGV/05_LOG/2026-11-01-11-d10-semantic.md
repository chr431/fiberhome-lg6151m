# 2026-11-01 · D10 语义实验预注册（lab 执行 · A8）

> 记分卡排期第 1 位（11_TRANSPORT_SCORECARD §8 序 1；05_LOG/2026-11-01-06 §5/§8 原始规格）。
> 本文件 §1–9 为**实验前预注册**（写于任何设备写入/注入之前）；§10–12 实验后只追加。

## 1. 问题

32B 记录的 `len` 字段是否跟随我们注入的**已知包长**（242 B / 1242 B 两档）、`ip` 字段是
**本机（192.168.9.1）还是对端（注入源 192.168.9.222/.223）** —— 一轮判 H4（硬件描述符写回）死/活，
并给 len 字段定性；顺带检验"写入者的信息源是否看到我们的流"（C1 链方向）。

## 2. 假设

- **H1（=H4 复活）**：记录由硬件 RX 完成路径按描述符/状态写回 ⇒ len 必须是**硬件可见的当包长度**
  （≤RX 缓冲 1536），注入期间 len 分布应跟随注入档位；ip 只能是 L3 头里硬件可见的端点之一。
- **H0（=H4 终判死亡）**：len 是**软件量**（如 GRO 聚合后的 skb->len / 混合位域），与单包注入长度
  无关 ⇒ 注入期间 len 分布不随档位移动（维持 {~1580..1664, 321, …} 族或其它非注入值）。
- 附加判定（ip）：记录 ip 反映**流量构成**（历史：WAN 为主时 WAN 对端、LAN 为主时 192.168.9.1）。
  注入单流成为主导 LAN 流量后，ip∈{.222, .223, .1} 的份额应上升（若写入者的信息源在我们的流上）。

## 3. 预测

- H1 为真：注入臂内 scanary `HIT_*` 记录的 len **大量**落在注入档位换算集合内（见 §4 匹配集），
  且注入臂 M 命中率 ≥ 5× 基线臂 M 命中率；len 值全部 ≤1536。
- H0 为真：注入臂与基线臂的 len 分布无可辨移动（M 集合命中 ≈ 基线水平，多为 0），
  len 主体仍 >1536 或落在历史族。
- 因果链（加分）：注入 242/1242 期间出现 **len==242 或 len==1242 精确匹配**的 inj=0 记录
  （尤其同时 ip==注入源）⇒ 我们的流与写入者之间存在 E3 级联系。

## 4. 判据（数值写死）

**注入定义**：PC 经 LAN 向 192.168.9.1:47913（闭合 UDP 口）发**单流 UDP**；
两档的"包长"指**整以太网帧长**：
- 242B 档：UDP payload=200（IP total=228，Eth=242）
- 1242B 档：UDP payload=1200（IP total=1228，Eth=1242）

**匹配集**（写死，涵盖 payload/IP/Eth 三层换算）：
- M(242) = {200, 208, 228, 242}
- M(1242) = {1200, 1208, 1228, 1242}
- 头条精确匹配 = len==242 或 len==1242。

**观测对象**：scanary v1.2 日志中 `inj=0` 的记录内容行。主终点只用 **HIT_APPEAR**；
HIT_CHANGE/HIT_REWRITE 全量作次终点（同报，不改判决）。len/ip 从 `w=` 四元组解析
（len = w2 低 32 位；ip 四字节 = w2 高 32 的小端序，日志 `ip=a.b.c.d` 打印的是反序，分析必须用 u32）。

**臂结构**（同一 scanary 进程内连续完成，不重启；臂间 ≥60 s 静默）：

| 臂 | 内容 | 源 IP | 帧长 | 时长 |
|---|---|---|---|---|
| B0 | 无注入基线 | — | — | 180 s |
| A1 | 注入 | 192.168.9.222 | 242 | 180 s |
| B1 | 注入 | 192.168.9.223 | 1242 | 180 s |
| A2 | 注入 | 192.168.9.223 | 242 | 180 s（换源对照：解耦 242 签名与 .222） |
| C1 | 注入 | 192.168.9.222 | 1242 | 180 s（换源对照） |
| B0' | 无注入基线 | — | — | 120 s |

速率：1000 pps 恒定（各臂相同；PC 侧实测 pps 落日志）。同一变量一轮只动"档位/源"，其余冻结。

**判决规则**（先写死）：
- **H4 复活（PASS-H4）**：≥3 个注入臂中，`len∈M(本臂档位)` 的 inj=0 HIT_APPEAR 份额 ≥10%，
  **且**该臂 M 命中数 ≥ 5× 基线臂（B0/B0' 合并）M 命中数，**且**注入臂全部 len 值中 >1536 者为 0。
- **H4 死（FAIL-H4）**：全部注入臂 `len∈M(本臂)` 且 `ip∈{.222,.223}` 的记录数为 0
  （报 N 与 LOD=3/N），或虽有 M 命中但份额 <10% 且与基线不可区分（M 命中 ≤ 基线 + 3/√N）。
- **因果链（加分，单独陈述）**：任一注入臂窗口内出现 `len==242 或 len==1242` 的 inj=0 记录 ⇒ 记
  "注入流→写入者因果链迹象（E3 级联系候选）"；同时报该记录的 ip 与臂窗口归属。
- **ip 定性**：按臂统计 ip ∈ {192.168.9.222, 192.168.9.223, 192.168.9.1, 192.168.9.120, 其它}。
  判定"对端可见"= 任一注入臂出现 ip==当时注入源的记录 ≥1 条（报 N/LOD）。
- **INVALID**：scanary 自检失败/进程死/设备重启/注入未到达（设备侧臂内 RX 增量 < 预期 pps×时长×50%）/
  时钟跳变破坏窗口对齐（date +%s 与 /proc/uptime 出现矛盾）。

**窗口对齐**：scanary 启动时记设备 `date +%s`（T0）；scanary 行首 `EV <µs>` 自 T0 映射；
每臂起止由设备 `date +%s` + `/proc/uptime` 双锚（禁心算 epoch）。PC 侧脚本记录本地 monotonic 起止，
与设备锚点线性对齐后才用于交叉核对。

## 5. 样本量/功效

- 历史参照（同仪器 scanary v1.2、同参数、无注入，2026-11-01 13:00 会话）：460 条 inj=0 HIT_APPEAR /
  900 s ≈ 0.51/s ⇒ 180 s 臂期望 ~90 条（非平稳，1..127/min 均有可能；**只做臂内/同会话比较**）。
- 若 H1 真（len 逐包跟随）：注入臂 M 份额应近 100%，10 条记录即可判（二项 p<1e-6）。
- 若 H0 真：0/N 的 95% 上界 = 3/N；N≈400（四注入臂合计）⇒ 单记录匹配概率上界 0.75%。
- 任一臂记录 <20 条 ⇒ 该臂标 underpowered，只并入总 N 不单独下判。

## 6. 混杂与控制

- **背景流量**：设备是活 CPE（WAN 常在）⇒ B0/B0' 臂内对照 + A/B/A/C 交错；ip "其它"份额作背景指示。
- **跨会话不可比**（10 号文档 §2）：全部比较限本次会话；历史 13:00 会话只作"正常范围"参照，不进判决。
- **04:00 定时重启**：实验时刻 ~20:40，距 04:00 >7 h；若 uptime 显示临近 04:00 则中止。
- **慢变状态漂移**：A/B/A（A1 与 A2 同档不同源）+ B0/B0' 首尾包夹。
- **GRO 聚合可能产生 228/1242 的倍数**（如 456、2484）：非预注册主判据，只作探索性记录，不进判决。
- **PC 常驻代理（Mihomo TUN）**：目的 192.168.9.1 在链路上直连（route print 已核），fake-ip 不涉；
  实测 -S .222/.223 ping 通。
- **观测者效应**：scanary 扫描成本 ~1/4 核（历史实测），不动 nerepair/patrace；本轮无内核模块。

## 7. 停止规则

- scanary 自检失败或 EXIT 异常（selfcrash>0 且日志中断）→ 停，保日志，报 INVALID。
- 设备重启（boot_id 变化 / uptime 归零）→ 停；跨代次数据不合并。
- SSH 失联 >2 min → 停注入（PC 侧脚本独立于 SSH，照常发完并落日志），事后按 RX 计数判到达性。
- 任何臂设备侧 RX 增量 <50% 预期 → 该臂 INVALID，不补救重跑（防顺序效应）。
- 安全：PC 只发 ≤1.2 MB/s UDP；设备侧零写动作（除 scanary 自身日志）。

## 8. 分析计划

- 主终点：注入臂 vs 基线臂的 M 集命中率（HIT_APPEAR, inj=0）+ 精确 242/1242 匹配数。
- 次终点：①len 全分布（按臂）；②ip 分类份额（按臂）；③HIT_CHANGE/REWRITE 口径复算；
  ④len∈{M 倍数} 探索性计数。
- 统计：二项精确（0 命中报 rule-of-three LOD）；分布移动用臂间 len 中位数/众数描述性对比
  （样本非 iid，不做参数检验）。
- 多重比较：主终点唯一（M 命中）；其余全部标探索性。

## 11. 判决

- **H4（硬件按描述符写回）：FAIL-H4，未复活，证伪维持并获第二独立证据。**
  预注册判据"全部注入臂 len∈M(本臂) 且 ip∈{.222,.223} 的记录数为 0（报 N 与 LOD）"成立：
  0/46（窗口）与 0/84（全会话），LOD 6.5%/3.6%；且注入臂 44/46 条 len>1536，
  直接与"硬件可见的当包长度 ≤1536"冲突。正对照（匹配器自检 + 注入到达核对）齐备 ⇒ **E2**
  （"在本实验条件下成立"）。与既有字段语义证伪（1601/1664>1536、321 并存）相互独立、方向一致。
  ⇒ 记分卡 §5/§9 的撤回条件（"len 跟随已知包长且 ≤1536 → H4 复活"）**未触发**，§5 判决维持。
- **len 字段定性：与单包注入长度无关的软件量。** 两档注入（242/1242 @1000 pps）下 len 分布
  无移动（{321, 1576–1775, 4394–4416} 族 + 出生窗 192），GRO/软件位域定性不变；
  新增子族 4394–4416（≈3 段聚合，探索性）。
- **ip 字段判定：记录 ip 是"某个端点"且反映流量构成；本机 192.168.9.1 与 WAN 对端出现，
  注入流的两个端点（.222/.223 与 .1）中仅 .1 出现、注入源 .222/.223 从未出现（0/84）**——
  写入者的信息源不跟随/不反映我们的注入流。
- **因果链（加分判决）：未达成。** 注入期间无任何 len==242/1242 记录（0/46，LOD 6.5%），
  也无 ip==注入源记录；slotwatch 3,639 读 0 形状。**我们的流与写入者之间未观察到因果链迹象。**
- 对应 `01_CLAIMS.tsv`：新增 **C-186**；无撤回行（H4 原本已是证伪态）。
- 附带（探索性，E1）：记录率与注入开关/档位无稳定关系（242B 臂最冷、无注入窗活跃），
  与 10 号文档 §5"流量不是决定性因子"一致；本数据为同会话内又一例证。

## 12. 偏差与教训

1. **冷态会话 + 功效扩展（pass 2）**：pass 1 注入臂仅 5 条记录（写入者当小时全局冷：nerepair
   −0x3b0 槽 20 s 内字节不变、dnsmasq 槽无形状）。按预注册 §5"不足则合并/如实报"之外，
   增跑了**声明的扩展**：3 并发 scanary 实例 ×300 s 臂（同一注入定义）。scanary 重启/多实例
   违反"同一进程贯穿"字面（该规则保护的是**速率**可比性；本实验主终点是**内容**，不受栈身份影响），
   速率比较仍只在 pass 内部进行。教训：D10 类内容实验应默认多实例。
2. **设备时钟跳变（重要，后续台架会话必读）**：本轮实测 realtime（date +%s）回跳 ~22 s，
   且 pass 1 中 scanary 的 CLOCK_MONOTONIC 相对 /proc/uptime 有 +45 s 级跳漂（pass 2 仅 ~5 s/27 min）。
   处置：全部时间轴以 /proc/uptime 为主锚 + 每臂 PC↔uptime 锚点对（残差 <0.1 s）+
   EV→uptime 分段线性映射 + 窗口两侧 3 s 裁剪；已验证窗口归属对映射误差不敏感（记录均落段中）。
   **任何跨源对齐禁用 date +%s 单点。**
3. **slotwatch 部署即扩展**：预注册未含 slotwatch（中途加入，只读；deploy.py put + chmod 755 合规）。
   其阴性本身受"写入者当小时不写这些槽"限制，只能作辅助 N。
4. **观测者/判据坑实录**：①pass 1 首次启动误用默认 depth-list（ndepth=5 会轮转 D），30 s 内发现并
   重启为 D=0 固定（预启动期，无数据污染）；②scanary 自检注入（inj=1）与真记录必须按 inj 位过滤，
   否则出生窗"爆发"是假象；③/proc/net/dev 字段序 bytes 在前 packets 在后，逐臂到达核对用字节更稳。
5. **正对照链**：匹配器（4×SELFTEST_OK×4 实例 + 活体探针）与注入到达（字节级）都打出，
   本轮的 0 才可按 E2 口径引用（02_METHOD §1）。
