## 0. 三句话

1. **记录不是 EDMA RX 描述符，也不是 WED TXD**（E3，三条独立否证，§2）。VERDICT 的 C-138/C-145 主支撑**作废**。
2. **写目标只有两个观测值，相距 16 字节**：`top-0x390`（= fault-time x2，A 型，69/117）与 `top-0x3a0`（= x2-0x10，B 型，40/117）；8/117 无记录。`top = mm->start_stack`，"53 种页内偏移"只是 startstack 的 **16B 粒度随机化**，与写入者无关（E3，§3）。
3. **内核里不存在"把目的 VA 算成 startstack-K"的写路径**（E2，§6 逐条列举）：信号帧恒在 sp **以下**（本样本目标在活 sp **以上** 0x22b0），exec 期 `copy_strings` 只写 `bprm->p` 以下。⇒ 目的地址只能是**数据**（用户提供的指针，或一个能解析到该 VA 的 PA），不可能是内核自己"算"出来的。

## 2. (a) RX 描述符写回语义 —— 记录≠RXD（E3）

### 2.1 装填 `mtk_rx_alloc_edma` @0xffffffc0085960f0（576B）

| 事实 | 指令证据 |
|---|---|
| ring 结构体 = ctx+0xad0(edma0) / ctx+0xb30(edma1)，每环 **0x30 B** | `smaddl x19,w1,#0x30,x0` + `add x19,x19,#0xad0/#0xb30` |
| ring+0x18 = u32 **0x0600_0780** → u16@0x18 **buf_size=0x780(1920)**、u16@0x1a **dma_size=0x600(1536)** | `mov w0,#0x780`/`movk w0,#0x600,lsl#16`/`str w0,[x19,#0x18]` |
| 缓冲 = `__netdev_alloc_frag_align(1920)`（**page_frag，无 page_pool**） | `ldrh w0,[x19,#0x18]; bl __netdev_alloc_frag_align` |
| 映射 = `dma_map_single(buf **+0x40**, 1536)` | `add x1,x1,#0x40; ldrh w2,[x19,#0x1a]; bl dma_map_single_attrs` |
| desc 环 = `dma_alloc_attrs(n*32)`，**EDMA0 ring0 = 512 项**（其余环 8 项） | `lsl x1,x26,#5`；`csel w21,w21(0x200),w0(8),eq` |
| `desc->w0 = DMA 地址低 32 位` | 重装填路径：`str w1,[x0,x23]`（w1 = dma addr lo） |
| `desc->w1`：bit31=DD、bit[23:8]=dma_size、bit[29:24]=? | `bfi w1,w3,#8,#0x10; str w1,[x0,#4]; ubfx x1,w1,#0x18,#6; strb w1,[x0,#7]`（把顶字节高 2 位置 0 ⇒ 清 DD） |

### 2.2 消费 `mtk_poll_rx_edma0` @0xffffffc008595548（868B）

| 用途 | 来源字段 | 指令 |
|---|---|---|
| **DD 完成位** | `w1` bit31 | `ldr w28,[x0,#4]` … `tbz w28,#0x1f` |
| **包长** | `w1` bit[23:8]（16 位） | `ubfx x1,w28,#8,#0x10` → `skb_put` |
| L4 校验和有效 | `w2` bit2 | `ldr w0,[desc+8]; tbz w0,#2` |
| **GDM 端口号** | **`w4` bit[29:26]** | `ldr w0,[desc+0x10]; ubfx x0,x0,#0x1a,#4` → `ldr x22,[x21,w0*8+0x940]`（选 netdev） |
| hw_lro 4B tag（**整字写进帧头**） | `w4` 全字 | `ldr w0,[x0,#0x10]; str w0,[x1]`（x1=skb head） |
| `dma_unmap_page_attrs` 的地址 | `w0` | `ldr w0,[sp,#0x78]` = desc->w0 |
| 描述符拷贝 | `mtk_rx_get_desc_ext` @…592dbc：**DD=1 时整字拷贝 w0..w3（16B），不做位域** | `ldr w2,[x1,#4]; str w2,[x0,#4]; tbz w2,#0x1f; … ldr/str ×3` |

**结论**：硬件写回**确实存在**（w1 包长、w2 bit2、w4[29:26] 端口），但
* **描述符里没有任何 L3/L4 地址字段**（全 vmlinux 里唯一"信息字"是 w4，其可解语义只有端口号 + 被当 4B tag 塞进帧头）；
* 描述符的 len 字段只有 **16 位且上限 = 驱动编程的 1536**。

### 2.3 三条独立否证（任一条即足以否掉"记录=RXD"）

1. **w0 对不上**：记录 q0 = 48965…165464，`mod 4096` 分布均匀，而 RXD 的 w0 必须是 page_frag 分片 +0x40 的 DMA 地址 ⇒ `mod 4096 ∈ {0x40, 0x7c0}`（1920 分片只有 0 / 1920 两种页内偏移）。**记录 q0 一次都不在这两个值上**。
2. **w1 对不上**：记录 q1 = 0 ⇒ 作为描述符即 **DD=0 且 len=0**（未武装/未完成），这种条目驱动根本不消费。
3. **len 超限**：实测 len 有 **4416 / 4480 / 1601 / 1609**，全部 **> 1536**（= 驱动编程的 DMA 长度上限）⇒ 单帧 RXD 装不下。附录：1601/1609 与 321/329 成对出现（差 8），4416/4480 差 64。

> **级别**：E3（静态字段级否证 + 118 份观测一致）。**反证条件**：若在 vmlinux 里找到另一条把 `{len,ip}` 写进 32B 描述符的 RX 路径（例如第二个 eth 驱动 / WED RX 环）且其 w0 语义不是缓冲地址，则本条需重审。已排查：`mtk_poll_rx_edma0/1`、`mtk_rx_get_desc_ext`、`mtk_rx_alloc_edma`、`mtk_rx_clean_edma`、`fe_edma_recycle_buf`，未见第二套格式。

## 3. (核心悖论) 拆解：53 种页内偏移不是写入者的属性（E3）

### 3.1 `top` 到底是什么
`vsurv4.c` 的 `read_startstack()` 读 `/proc/self/stat` 第 28 字段（= `mm->start_stack`）；
内核侧赋值点只有 `fs/binfmt_elf.c:1279  mm->start_stack = bprm->p;`，
随机化只有 `fs/exec.c:781  stack_top = arch_align_stack(stack_top);`，
arm64 的 `arch/align` 实现（`arch/arm64/kernel/process.c:551`）是 `sp -= get_random_int()%8192; return sp & ~0xf;`
⇒ **startstack 只有 16B 对齐**，`mod 4096` 有 **256 种可能值**。

因此：`x2 = top-0x390` ⇒ `x2 mod 4096 = (top mod 4096) - 0x390`，
**"53 种 x2 页内偏移" = startstack 随机化的直接投影，不携带任何写入者信息**（E3）。
我在 117 份上复核：`top-x2 = 0x390` **117/117**，`pc=0x01015ccc`、`x30=0x01014768`、`x2-sp=0x22b0` 也是 117/117 恒定
⇒ canary 的调用链深度是确定的，"va_list 在哪"对同一二进制是常数。

### 3.2 三个模型的**分布预测**（Lead 要求，逐条对照 82/112 与本地 117 份）

| 模型 | 对"命中偏移"的预测 | 对 82/112、117 份的相容性 |
|---|---|---|
| **H-PA-fixed**（固定物理页 + 固定页内偏移 f） | 记录页内偏移恒 = f ⇒ **只有 `x2 mod 4096 ≈ f` 的极少数 pid 能崩**（53 种偏移里 1~2 种）。预测崩溃 pid 数 ≈ 总 pid 数 / 256 | **否证**：75 个 pid、53 种 x2 偏移**全部**崩且记录都在 x2/x2-0x10。P(数据|H) ≈ (2/53)^{73} ≈ 0 |
| **H-TOP**（目的 = `startstack - K`，K 常数） | 记录页内偏移**不恒定**，而 = `startstack mod 4096 - K` ⇒ 与观测的"偏移随 pid 变、pid 内恒定"**完全吻合**；且记录出现位置在 `x2`（若 K=0x390）或 `x2-0x10`（若 K=0x3a0） | **相容**（82/112 与 117 份都相容） |
| **H-VA**（目的 = va_list 对象 VA） | 同上：因为 va_list 也在 `startstack-0x390`（帧深确定），**与 H-TOP 在同一二进制上不可区分** | **相容**，同样不可区分 |

⇒ **82/112 与 H-TOP、H-VA 都相容，且无法用同一个二进制区分这两者**。区别只在"把 va_list 挪走之后"：
* H-VA ⇒ 记录跟着 va_list 走，仍然崩；
* H-TOP ⇒ 记录留在 `startstack-K`，va_list 已不在那儿 ⇒ **崩溃率→0**。

**这是唯一能同时否证两条的便宜实验**（见 §9，与 Lead 已交给 lab 的 scanary 深度臂等价）。

### 3.3 A 型 / B 型 = **两个写目标，相距 16 字节**（E3）—— 回答 Lead 的细节提问

| | A 型 | B 型 |
|---|---|---|
| 份数（117 份） | **69（59%）** | **40（34%）**（另 8 份无记录） |
| 写目标 | `top-0x390` = **fault-time x2 本身** | `top-0x3a0` = **x2-0x10** |
| 判别量（可直接照抄） | `word0@x2` 是**小非零值 A**；`word4@x2`=len、`word5@x2`=ip（记录 q0 在 x2） | `word0@x2 == q2 == (ip<<32\|len)`、`word1..3@x2 == 0`，且 **x2-0x10..x2-0x4 四字全 0**（记录整体低 16B） |
| 故障地址 | `fault = A`（va_arg 前）/ `A+8` 是 dump 里的值（C-005 成立） | `fault = tagstrip(q2) - 8`（如 0x1c28416e00000648 → 除最高字节 0x1c → 0x28416e00000640）；C-007 的"tag 截断"成因 = **目标低 16B 后 q2 落在 `__stack`**，不是"错开一个字节" |
| 0x240 下方的第二副本 | **69/69 有**（A 那份 = A，x2 那份 = A+8） | **0/40 没有** |
| 记录内容 | `{A≠0, 0,0,0, {len,ip}, 0}`，len ∈ {321×31, 1600×3, 1601×32, 4416×2, 4480×1} | `{0, 0,0,0, {len,ip}, 0}`，len ∈ {8×23, 329×5, 1608×1, 1609×11}，其中 len=8 的 23 份 ip=0 |
| 是同一 pid 内混着出现的吗 | 是：pid 23648 → BBBBAB；23650 → AABBAAA；23655 → AAAABBBBA |

**第二副本的机制（E2→E3）**：musl 的 `vfprintf` 会 `va_copy(ap2, ap)`（32B 结构整体复制）。
A 型里 `x2`（= 外层 va_list）先被写，随后被复制到 `x2-0x240`（vfprintf 帧），
所以两份内容相同而 **x2 那份多 +8**（= va_arg 对 `__stack` 的自增）——这同时证明
**写发生在 va_copy 之前**、**写目标就是 va_list 对象本身**。

**A/B 两型的判别量里最硬的一条**：`A 型 q0 ≠ 0（69/69）` vs `B 型 q0 == 0（40/40）`，
且 B 型 len = A 型对应 len + 8（321→329、1601→1609、0→8）。
⇒ 两型的**内容与目标同时差 16B/8**，说明写入者手上有一个**16 字节粒度的地址量**在抖动（机制线索，见 §5 W3）。

### 3.4 载荷在 32KB 窗口里的地形（E3，新增）

脚本 `static/payload_scan.py`：在 **118 份 dump × 32KB = 3.8 MB 栈**里，按 **4B 对齐**搜记录载荷字
`q2 = (ip<<32|len)`（判据：`0 < 低32位 < 0x4000` 且 高32位 ∈ 已知本机地址集）。

| 出现位置（相对 x2 / 相对 top） | 次数 | 解释 |
|---|---|---|
| `x2+0x10` / `top-0x380` | 69 | A 型记录自己的 q2 |
| `x2-0x230` / `top-0x5c0` | 69 | A 型那份 va_copy 副本的 q2 |
| `x2+0x00` / `top-0x390` | 17 | B 型记录（写目标 x2-0x10）的 q2 |
| **其它任何位置** | **0** | — |

合计 155 次出现 = 69×2 + 17，**全部落在 3 个 va_list 派生槽位上，其余 3.8 MB 栈里 0 次**
（另有 23 份 B 型 ip=0 因此不进本判据，8 份为下条 Z 型）。
**注意口径**：这是"崩溃后仍存活"的分布，不能直接当"写入者打过哪些地址"的分布
（本 canary 每轮 printf 都会重写 va_list 与 printf_core 的 0x1fa0 帧缓冲，旧记录会被覆盖）
——它只证明**记录从不以"孤立 32B"以外的方式弥散存在**。

**Z 型（8 份，新分类）**：整个 x2±0x240 区间只有 **1 个非零字 = 8**（位置随 A/B 型而变），
`fault = 0`。它可能是"全零记录"（`{8,0,...}` 或 `{0,0,0,0,8,0,...}`）的变体，
也可能是另一种独立写入。**不作机制断言（E1）**，判据：`len==0 && ip==0 && fault==0`。

### 3.5 **+8 归一化**：A/B 两型不是两种载荷，而是"自增前/后"（E3，2026-11-01 定稿）

按 `(ip, form, len)` 交叉（`static/formlen.py`，118 份）：

| ip | A 型 len | B 型 len | 归一化（B 型 len−8） |
|---|---|---|---|
| 0x0109a8c0 (192.168.9.1) | {321, 1601} | {329, 1609} | {321, 1601} |
| 0x1c28416e (110.65.xx.18) | {321, 1600, 1601, 4416, 4480} | {329, 1608, 1609} | {321, 1600, 1601} |

**机制**：va_arg 的自增（+8）作用在 `__stack` **字段**上：
* **A 型**（写目标 = va_list 本身）：`__stack` 落在 **q0** ⇒ dump 里 `q0 = A_写 + 8`，q2 不动；
* **B 型**（写目标 = va_list−16）：`__stack` 落在 **q2** ⇒ dump 里 `q2 = q2_写 + 8`，表现为 **len = len_写 + 8**。

⇒ **lab 的观察（同一 IP 两个 len 差 8）成立，但归因不是"两个独立字段/两个 64 位量的两半"，而是"同一条记录在自增前/后"。**
归一化后：**只有一种载荷** `{q0=A_w; 0; q2={len,ip}; 0}`，`A_w ∈ [48957,165456]`、`len ∈ {321,1600,1601,4416,4480}`；
两份 dump 的唯一差别 = **写目标差 16B**。判定记录时必须把这一步归一化写进脚本（否则会把同一记录算成两条、或把 len 分布算错）。

### 3.6 与历史"16B 槽"家族的收敛（E2，新增）

`SIGSEGV_ANALYSIS.md` 的两条历史事实：
* §14：「**live PIT 表项 16B `{u64 PA, u64 0}`；4KB 页 256 项，最后一项在 0xfc0**」
* §2.1：「**长度型 16B 块 `{small,0}`：small ∈ [0x2710,0x40000] ∪ {0}，非单调**；同页可多块（16B 节距）；页尾 0xfc0 高发」

本轮 `A_w ∈ [0xBF45, 0x28658] ⊂ [0x2710,0x40000]`。
⇒ **今天的 32B 记录 = 1~2 个"16B 槽 `{u64 v, u64 0}`"**（A 型覆盖 2 槽、B 型只覆盖 1 槽），与历史注入家族**同一类对象**。
反面：`scatterlist`/`bio_vec`（第二 qword = offset+len，在用态非 0）、MTK TXD `{addr,ctrl}`（ctrl 非 0）
⇒ 只有"未用项"才整槽为零，与"每槽高 8B 恒 0"矛盾 ⇒ **可排除**。

## 4. (b) A 的来源：排除矩阵（E2）

A 的实测分布（A 型 69 份）：min 48965、max 165464、median 111721、mean 112704、**低位无集中**（`A%32` 28 种、`A%4096` 68 种）；
文档口径的 2322 份全样本：**A < 2^20（1 MiB）无一例外**、1733 个不同值、`%32` 均匀、与 ts 弱负相关（r=-0.27）、**同一 pid 内不单调**（2600：89489/48965/80357）。

| 候选 | 判据 | 判定 |
|---|---|---|
| jiffies / 单调计数器 | 同 pid 内不单调（2600、23650…） | **否证** |
| `ktime`/时间戳低 20 位 | 应近似均匀且中位数 ≈ 2^19；实测中位数 10 万（≈2^17） | **否证（弱）** |
| 32 位 hash（RSS/L4） | 掩到 20 位应近似均匀；实测中位/均值 0.88 且集中在 1 万~16 万 | **不像**（需掩码常量证据，未找到） |
| RX 环槽位索引 | 索引 ≤ 512，实测最大 165464 | **否证** |
| **缓冲区/环内字节偏移（≤1 MiB 区域）** | A<2^20 恒成立、随包变化、非单调 | **首选**（无直接证据，E1） |
| `skb->cb` 内某字段 / `napi_gro_cb` | 需与 {len,ip} 在同一 32B 里且 q0 为 17 位 | 未匹配（5.15 布局见 `include/linux/skbuff.h`，q0/q1 位置是 frag0/frag0_len，无 IP） |
| page_frag 偏移 / 页内偏移 | 只 12 位 | **否证** |

**结构级候选（(c) 三字段指纹）**——粗筛结果（`structsieve.py`，67 个 64B 以内含 ip+len 的结构）里**没有一个**能排出 `{u64 小值; u64 0; u32 len; __be32 ip; u64 0}`：
中间那 8 个 0 字节（+0x08..+0x0f）在自然结构里几乎不可能存在，除非是
**union 里 16B 的 `nf_inet_addr`/`in6_addr` 的剩余 12 字节**、或**表项里未用的空洞**。

⇒ 我给的**分叉判据**（与 lab 的两个语义实验对齐）：
* 若 **len 跟随线上帧长**（777/1234 独特包长）**且 IP 跟随别名**（192.168.9.77）⇒ 该结构在 **L3 之后、按包生成**；则 A 最可能是"每包上下文里的一个 ≤1MiB 偏移/序号"，候选面收窄到 `skb`/GRO/路由缓存，**排除一切硬件描述符**（硬件不可能知道本机 IP、更不可能知道别名）。
* 若 **两者都不跟随** ⇒ 结构在 **驱动/硬件侧**，A 可能是描述符里某个"位置量"，此时必须解释"本机 IP 从哪来"（硬件只可能在 PPE/hw_nat 解封装后拿到 IP）。
* 若 **只跟随 IP 不跟随 len** ⇒ 结构是"接口/地址上下文"（每接口一份），len 是另一来源（如 MTU/聚合上限）。

## 5. 候选写入路径（每条：机制 / 支持 / 反证 / 可证伪预测 / 级别）

### W1 · EDMA RX 完成写回描述符（原 C-138/C-145 主假设）
* **判据已出**：见 §2.3 三条否证。**级别 X（否证）**。
* **可证伪预测（已被用掉）**：若成立，记录 q0 必是 4K 对齐 +0x40/0x7c0 的 PA 形态，且 len ≤ 1536。实际两条都不成立。
* 残余可能：**RX 之外的第二个 32B 描述符环**（WED RX / PPE CDRT）。要否掉它需要一次 ring dump（`/proc/mtkfe/dump_dma` 之外的 WED 环）。

### W2 · 页复用 + stale PA（DMA 写"曾经是 RX 缓冲、现在是用户栈页"的物理页）
* **支持**：C-160（命中页 20/20 固定 PA）；page_frag 复用是事实。
* **反证（决定性）**：见 §3.2 —— 固定 PA + 固定页内偏移 ⇒ 只有 1~2 种 x2 偏移能崩；实测 53 种全崩。
* **级别：X**（作为"唯一机制"）。除非再叠加"页内偏移 = 由 VA 推出的"（那就退化成 W3/W4）。
* **可证伪预测**：若成立，命中页的 PA 应与 `dump_dma` 里某个 DD=0 描述符的缓冲 PA 相等（patrace 已具备该能力，**未做**）；且命中率应与页池状态同步（已观测到跨会话 19 倍漂移，符合但仍不特异）。

### W3 · VA 解析的 32B 写，目标由**数据**提供（uaccess / `put_cmsg` / `copy_to_user` 家族）
* **支持**：§6 的否证 —— 内核没有任何路径把目的 VA 算成 `startstack-K`；因此目标只能来自数据；A/B 两型差 16B 说明地址量是 16B 粒度（ucontext/pt_regs 级别的量）。
* **反证**：C-013/C-034 的 `copy_to_user` 强阴性（但那是"热点/计数器"口径，不是本 32B 载荷）。
* **级别：E2**。
* **可证伪预测**：
  1. 把 canary 的栈页 `mprotect(PROT_READ)` 或 remap 到新 PA 之后，**写入仍落在同一 VA**（uaccess 会写不进去 → canary 不崩；DMA 会照样写 → 崩）。⇒ 这是 fixer 的 remap/RO 实验，能一刀切开 W2/W4。
  2. 若为 GUP 型，`/proc/<pid>/status` 的 `VmLck`/`RssAnon` 与 pin 计数应可观测（C-050 已否掉泄漏 pin，但 use-after-unpin 仍在）。
  3. 载荷内容应与某条 sockopt/netlink 消息的 32B 前缀同构（可用 `SO_TIMESTAMP`/`IP_PKTINFO` 对照实验）。

### W4 · GUP-pinned 页 + 偏移来自用户 VA 的 DMA 写
* **支持**：能同时解释"跟随 VA"与"固定 PA"（pin 期间 PA 固定，C-160 ✓）；且 C-160 的两个 canary 有**各自固定**的 PA（不同 pid 不同 PA）——这正是"每进程 pin 自己那一页"的形态。
* **反证**：C-050 `ref=1025` 没看到泄漏 pin（但只看了 12 个栈页的 pg2）。
* **级别：E2（本轮最强竞争假设）**。
* **可证伪预测**：
  1. 命中页的 `page->_refcount`/`_mapcount` 应比普通匿名栈页**多 1**（pin 位）。patrace 已能拿 PA，再加一个读 `struct page` 的模块即可判决（E3）。
  2. 停止 pin 的来源（例如 unmap/收包结束）后，命中应停止且 PA 变化。
  3. 若为 zerocopy 路径，则必须存在一个"接收方持有用户 iovec"的 socket（本 canary 没有）⇒ 需要先找到"谁把栈地址交给了内核"。

### W5 · 内核把 `sp`/`startstack` 当目的地的写路径
**已逐条排除（§6）**。级别 X。

### W6 · 观察者自污染（nerepair / ptrace / vaguard）
* nerepair 是 ptrace supervisor，会 `PTRACE_GETREGS`/`SETREGS`；**但 h4 的早期样本（10-30）在 nerepair 之前**，且 canary 被显式排除。
* 但这提示一条**新风险**：任何"写 tracee 栈"的调试器都能伪造本签名。**级别 E1（仅提醒）**；判据：停掉全部 ptrace 类工具后独立复测命中率。

## 6. (Lead Q2) vmlinux/源码里"目的地址由用户 sp 派生"的写点清单

| # | 路径 | 目的地怎么算 | 能否产生 `startstack-0x390` |
|---|---|---|---|
| 1 | `copy_strings()`（fs/exec.c） | `bprm->p` 递减，从 `stack_top` 往下搬 argv/env | **能**（同一量级），但**只在 exec 期**；进程运行中 bprm 已释放 |
| 2 | `setup_arg_pages()` + `arch_align_stack()`（fs/exec.c:781 / arm64 process.c:551） | 只决定 `stack_top`（16B 粒度） | 是"K 的随机化来源"，不是写者 |
| 3 | 信号投递 `get_sigframe()`/`setup_rt_frame()`（arch/arm64/kernel/signal.c） | `sp - sizeof(rt_sigframe)`（或 altstack） | **否证**：恒在 sp **以下**；本样本目标在活 sp（`top-0x2640`）**以上 0x22b0** |
| 4 | `restore_sigcontext()` | 写**内核** pt_regs | 否 |
| 5 | ptrace regset / `PTRACE_POKEDATA` | 调用者给 VA | 需要外部进程主动写（W6） |
| 6 | 一切 `copy_to_user/put_user/iov_iter` 用户拷贝 | 来自**系统调用参数**或**用户内存里的结构** | **否**：内核不 invent 该 VA；只能"用户给过" |
| 7 | `userfaultfd`/`handle_userfault` 回填 | 故障 VA（= 用户在碰的地址） | 否（且本机未启用 uffd） |
| 8 | perf/io_uring/vhost 环 | mmap 出来的 ring VA | 否 |
| 9 | `page_frag`/DMA 引擎 | 只有 PA/VMA，没有用户 VA | 只能通过 PA 解析（W2/W4） |

**结论（E2）**：`startstack-0x390` 这个 VA 只能以两种方式成为写目的：
(i) **用户自己把这个 VA 交给过内核**（指针/iovec/msg_control/cmsg/zerocopy），或
(ii) **某个 PA 正好等于该栈页的 PA + 页内偏移**（DMA，且偏移必须与 VA 同步 ⇒ 只能是 W4 型）。
⇒ 下一步的点名手段**不再是"找 ring"**，而是**找"谁持有过这个 VA"**：
`grep` 用户态 → 内核指针传递点（syscall 参数、`put_cmsg`、`sock_recvmsg`、`iov_iter`），或用 patrace 反向"谁 pin 了该页"。

## 7. (缺陷定位 · task-3 第 4 项) 窗口与补丁点（按新证据重述）

原任务假设"RX 缓冲回收/page_frag/unmap 时序"——**该框架随 §2 作废**（记录不是描述符，也不是 RX 缓冲内容）。
按现证据，缺陷窗口收敛为两类，各有明确补丁点：

| 窗口 | 机制 | 补丁点 | 判据 |
|---|---|---|---|
| **P-a：用户 VA 生命周期** | 某内核结构保存了用户栈上的 32B 目的地址（或 8 字节指针），在用户栈被复用/释放后仍写 | 找到持有者后加 ref/pin 或删缓存；通用补丁 = 写前 `access_ok`+页有效性检查 | W3 预测 1/3 |
| **P-b：GUP pin 与 unmap 次序** | pin 页在 `unpin` 后被 DMA 再写（use-after-unpin） | `dma_unmap_*`/`unpin_user_page` 之后**禁止**再投递任何描述符；或在 unmap 前 `dma_sync`+静默硬件 | C-160 的"固定 PA"+"每 pid 各自固定"是它的形状 |
| **P-c：观察者** | ptrace 类工具伪造 | 停工具复测 | W6 |

**注意**：`nerepair` 现有的判据（`w1==0 且 w0==fault/fault+8` 的 32B 形状）**在 A 型成立、在 B 型也成立**（B 型 fault 是 q2 去 tag），
因此它**不会因为 A/B 两型而漏修**；但它**不能区分**"记录在 va_list 上"与"va_list 被 va_copy 复制后带上记录"，
所以若 §3.2 的 H-TOP 成立，nerepair 修的是"巧合命中的副产品"——**这决定了它的长期价值，需要 scanary 结果来定**。

## 9. 下一步实验（判据写死，可直接交给 lab/kdev）

**E-1（最高优先，scanary 深度臂，无需崩溃）**
* 变量：自供栈顶 `top`，深度档 D ∈ {0, 0x100, 0x400, 0x900, 0x1000}（一个窗口只改 D）。
* **判据 H-VA**：命中点 `top-VA` 随 D **等量移动**（`{(0x390+D_i)}` 单调跟随）⇒ 写目标 = 活 va_list。
* **判据 H-TOP**：命中点 `top-VA` **恒 ∈ {0x390, 0x3a0}**（即两个观测写目标，不随 D）⇒ 写目标 = 固定栈顶相对偏移。
  （⚠️ 不得把 `0x5d0` 列为候选写目标：它只是 A 型那次的 **va_copy 副本**位置，见 §3.3 的方向论证。）
* **判据 H-PA**（已被否定，作正对照用）：命中率随 D 变化但命中点**页内偏移**恒定。
* 功效：按同会话 1.2~20 命中/min，每档 10 min 的期望命中 ≥ 12（λ≥1.2/min×10）⇒ P(=0) ≤ 6e-6，足够判"有/无"。

**E-2（切 W2 vs W3/W4，一次 5 分钟实验）**
* 把 canary 的 8 个栈页 `mprotect(PROT_READ)`（或 remap 到新 PA）。
* 预测：uaccess 型 ⇒ 写入失败（`-EFAULT` 或静默丢弃）⇒ **命中→0**；DMA 型 ⇒ **照崩**。
* 这是唯一能在用户态直接切开"VA 写"与"PA 写"的实验，成本低于重编内核。

**E-3（结构身份分叉，lab 已在跑）**
* 独特帧长 777/1234 + 别名 IP 192.168.9.77；判据见 §4 分叉。

**E-4（若 E-1 判 H-VA/H-TOP 之后）**
* 用 patrace 读 `struct page` 的 `_refcount`/`_mapcount` 判 W4 的 pin 位（E3 级）。

## 12. Lead 追加三方向（静态答复）

### 12.1 (a) `put_cmsg` 家族：**字段级否证**（E2）

`put_cmsg` @0xffffffc0087b6e78（0x1e0B）实测：
* `msg_control = [msghdr+0x38]`、`msg_controllen = [msghdr+0x48]`（`cmp x0,#0xf ; b.hi` ⇒ 余量必须 >15）；
* 写入顺序 = `cmsg_len(=len+0x10, 8B)` → `cmsg_level(4B)` → `cmsg_type(4B)` → payload（从 `msg_control+0x10` 起）；
* 布局是 **`struct cmsghdr {size_t cmsg_len; int level; int type;} = 16B` + payload**。

把 32B 记录 `{q0=A; q1=0; q2={len,ip}; q3=0}` 套到这个布局：
| 记录字段 | cmsg 语义 | 是否可行 |
|---|---|---|
| q0 = A（48965…165464） | `cmsg_len` | **否**：真实 cmsg_len ≤ 0x38；A 是 5 万~16 万量级 |
| q1 = 0（高 32 bit 也是 0） | `cmsg_level/low` | level=0 只有 `SOL_IP` |
| q2 低 32 = len(8/320/1601/4416) | `cmsg_level/type` 对 | type=1601/4416 不存在；且 **level=0+type=0 无定义** |
⇒ **cmsg 头部假设否证**。
payload 假设（IP_PKTINFO/ip_pktinfo = `{int ifindex; struct in_addr spec_dst; struct in_addr addr}`=12B）也不匹配：
若 ip 落在 `addr`，则 `spec_dst` 就是记录里的 len（1601 → 0.0.6.65），不是地址。

**"目标地址滞后"问题（机制上仍值得留一条）**：`put_cmsg` 的目标来自**本次 syscall 的 msghdr**，
errqueue/TX-timestamp 都是"在 recvmsg 时重新取 msghdr"，**没有跨 syscall 缓存用户指针**；
`ip_cmsg_recv_offset` @0xffffffc008854e60、`__sock_recv_timestamp` @0xffffffc0087a36f8 均在 recvmsg 上下文内。
⇒ **cmsg 家族既排不出该 32B 布局，也没有"滞后写过期指针"的窗口**（E2，反证条件：找到某驱动缓存 msghdr 的证据）。

### 12.2 (b) A < 2^20 = 硬约束

* 2322 份样本 A < 1 MiB 无一例外（文档口径）；本地 69 份 A ∈ [48965,165464]。
* 候选"1 MiB 为界的量"（按优先级）：
  1. **1 MiB 环/缓冲内偏移**（历史 `SIGSEGV_ANALYSIS.md §16.1`：dpmaif 有 **1 MB 生产环 0x904a0000**，r094 在其中高速回绕）⇒ A 是该环的**写指针/偏移**，这个模型天然满足"<2^20、非单调（回绕）、与包无关"。
  2. `SKB_WITH_OVERHEAD`/`NET_SKB_PAD` 派生：数量级是 KB，不是 10 万量级 ⇒ **否**（除非乘上环深）。
  3. page_frag 上限：1920×512 = **983040 ≈ 960 KiB < 1 MiB** —— 这是"**512 个 1920B 分片 ≈ 1 MiB**"的巧合，值得记一笔（EDMA0 ring0 = 512 项 ×1920B = 983040 B，**恰好 < 2^20**）。
* **可证伪预测**：若 A = 1 MiB 环内偏移 ⇒ A 应**随时间的推进而单调增加并在 2^20 处回绕**（同一 pid 内跨秒的样本应落在环附近）。
  实测 69 份里 A 与 ts 弱负相关（r=-0.27）、同 pid 不单调 ⇒ **"全局单调环指针"不成立**；
  剩下的可能是"**每包独立**的环内位置"（如某个 per-CPU/per-queue 指针的瞬时值）。

### 12.3 (c) 16B 节距 `{u64 v, u64 0}`：与 A 值域合并的结构问题

历史 `§2.1`：长度型 16B 块 `{small,0}`，small ∈ [0x2710,0x40000]；本轮 A ∈ [0xBF45,0x28658] ⇒ **值域重合**。
⇒ 统一假设：**同一个 16B 槽表，本轮记录 = 相邻两个槽（32B）**：
```
槽 n+0 : {u64 A,  u64 0}     ← 计数器/偏移（17~18 位）
槽 n+1 : {u64 (ip<<32|len), u64 0}
```
候选结构（16B 且第二 qword 为 0/未用）：
| 候选 | 大小/布局 | 判定 |
|---|---|---|
| 历史 PIT 表项（dpmaif） | 16B `{u64 PA, u64 0}`，4KB 页 256 项 | **形状完全吻合**，但内容（PA）不符；作为"同一类表"的先例保留 |
| `struct scatterlist` / `bio_vec` | 16B `{page/addr, len, off}` | 第二 qword **不恒 0**（len/off 非 0）⇒ 只有**终止项**才是全 0，与本记录矛盾 |
| MTK TXD（16B `{dma_addr, ctrl}`） | ctrl 在用非 0 | 不符（记录两半的第二 qword 都是 0） |
| DMA 描述符 `{u64 addr, u32 len, u32 flags}` | len 在 +8 | 记录 len 在 +0x10 ⇒ 不符 |
| 任意"每槽一个 16B 状态字"的硬件表 | — | **唯一未被否证的类** |

**判别实验（便宜）**：抓一份 dump，看目标处是否**只出现一个 16B 槽**（`{A,0}` 而 +0x10 为 0）或
只出现 `{{len,ip},0}`。若两者**从不单独出现** ⇒ 写入者一次写 32B（是一条 32B 表项，不是 2×16B）。
本轮 118 份里**没有一例单独出现**（Z 型 8 份是"只有 1 个非零字=8"，见 §3.4），
但样本选择偏倚（只有崩溃进程）⇒ 该判据需 scanary 的非崩溃样本才能定。

## 13. 「W3/W4 vs PA/DMA」可证伪对照表（给 skeptic 的 Transport 记分卡）

| 判据 | PA/DMA（W2：stale PA + 页复用） | VA 派生写（W3：uaccess/GUP 目标来自数据） | 观测值 | 谁赢 |
|---|---|---|---|---|
| 记录页内偏移分布 | **固定**（= 描述符里的固定偏移） | **随 VA**（= 栈 VA 的页内偏移） | 53 种，且随 pid；pid 内恒定 | **VA** |
| 命中点相对 startstack | 随机（页复用无关联） | 固定（0x390 / 0x3a0） | **117/117 固定** | **VA** |
| 命中页的 PA | 可与某描述符 PA 逐一对应 | pin 期间固定，unpin 后变 | C-160：20/20 固定 PA，**但每 pid 不同 PA** | **平**（两者都能解释） |
| `mprotect(PROT_READ)` 后是否仍写 | **仍写**（DMA 不看 PTE 权限） | **不再写**（uaccess 受 PTE 限制） | 未做 | **未决（最便宜的判决）** |
| `mmap` 到新 PA（remap）后命中点 | 跟 PA 走（VA 变了 PA 没变 ⇒ 命中在旧 VA 消失） | 跟 VA 走 | 未做 | 未决 |
| victim 页 `_refcount - _mapcount - 1` | = 0（无 pin） | > 0（GUP/pin） | 未做 | **未决（kdev 已排）** |
| 记录内容 = 硬件可产生的字段 | 需要硬件知道"本机端点 IP" | 软件天然可得 | 若 lab 的别名 IP 跟随 ⇒ 硬件不可能 | **待 lab** |
