# 2026-10-30-02 · vsurv4 首次实战：干净 A0B2 + 随机 VA + cfu 事故

> 状态：进行中（vsurv4 固定栈 fleet 已启动，等待更多 h4）。
> 关联：C-033/C-034/C-035/C-036；P-03/P-05。

## 1. 预注册（实验前）

**问题**：32 字节记录能否在 async-signal-safe 的 vsurv4 上复现？随机 ASLR 的栈是否仍被命中？

**假设**：
- H1：记录是真实的；vsurv4 会写出 A0B2/B0A2 的 h4，fault addr 对齐 word0。
- H2：如果写入者依赖固定 VA（uaccess/陈旧用户指针），随机栈会显著降低命中；如果依赖 PA/GUP/页，随机栈仍会命中。

**预测**：
- H1：h4 头 x2 处的 32 字节为 {A,0,B,0}，addr=untag(w0-8)。
- H2：随机栈 fleet 与固定栈 fleet 都能出 h4；若随机栈 0 命中而固定栈有，则固定 VA 依赖成立。

**判据**：
- PASS：至少 1 份 h4 满足 H1；随机/固定两臂都有命中 → H2 的“非固定 VA”侧。
- FAIL：h4 头/页解析失败，或 0 命中且仪器自检失败。
- INVALID：设备重启/仪器未加载/自检未过。

**样本**：4 个随机栈 + 8 个固定栈（nowrap）vsurv4；观察 10–30 min；每份 h4 32 KB。

**混杂**：设备负载、记录活性阵发、h4 写盘、handler 自身；固定栈用 nowrap(personality) 关闭 ASLR。

## 2. 结果（截至 20:50）

### 2.1 vsurv4 自检（通过）

- kill -11 触发 handler；写出 h4_15765_1.bin，大小 32888 = 120 B 头 + 8×4096；进程继续运行。
- 启动行改为手动格式化后，启动阶段不再创建 va_list；handler 的 g_ready 只在主循环 sigsetjmp 后置位。

### 2.2 第一份真实崩溃（随机栈）

- h4_21610_1.bin，pid 21610，start_stack=0x7fcc6e9900（ASLR 随机）。
- 解析：addr=0xE48F (58511)，x2=0x7fcc...，shape=A0B2，delta_ok=1，w0=0xE497（addr+8），w2=0x109a8c000000641。
- B 解码：len=0x641，ip=192.168.9.1（br-lan）。
- **结论（E2/E3）**：记录在随机 VA 的 live va_list 上复现；fault addr = 记录 word0；不是“固定 0x7ffffff9c0”专属。

### 2.3 固定栈 fleet（进行中）

- 8 × nowrap /data/repro/vsurv4，start_stack=0x7ffffffd40（与旧 vsurv3 相同）。
- 目的：用安全 handler 复现旧 106 份的高命中率；与随机栈臂对照。

### 2.4 事故：cfu 正对照导致内核 Oops/重启

- 时间线：PF 正对照通过（cth: PF#2 far=0x7000000000 ... pc=__arch_copy_to_user+0x94）；随后 rmmod cth; insmod cth hook_cfu=1 hook_pf=0 hook_ac2u=0 hook_c2u=0，运行 probe_selftest_user cfu，SSH 断开；串口 ring 显示 ash: Unable to handle kernel paging request at ffffffff0026e948，pc: _compound_head+0x0，lr: virt_to_head_page+0x24，随后重启。
- 判定：cth_cfu 在 __arch_copy_from_user+0 的 hook 中无条件 dump_stack()，且 cth 没有 per-CPU 递归守卫；最可能是 hook 内 dump_stack/copy_from_user 递归或寄存器/栈扰动导致 Oops。cth_tramp_* 只保存 x0–x9/x18/x29/x30，未保存 x10–x17；入口 hook 对 callee 通常安全，但 c2u（+8）不安全。
- **处置**：cfu 正对照标 **BROKEN**，在修好 cth（递归守卫 + 去掉 cfu 的 dump_stack + 默认关闭 c2u）前不再跑；cfu 的阴性保持 E1。PF 正对照已通过，cth_pf 可用。
- 设备已自动重启恢复；当前 boot 干净（无 cth/uw/ccbscan），vsurv4/h4 文件保留。

## 3. 判决

- **H1 成立（E2/E3）**：vsurv4 干净复现 A0B2；记录真实、因果、当前 boot 活跃。
- **H2 部分成立**：随机栈被命中 → 固定 VA 不是必要条件；这削弱“固定 0x7ffffff9c0 的 uaccess/陈旧用户指针”假设，支持 PA/GUP/页级 或“跟随当前进程 VA 的 GUP-DMA”。
- **cfu**：仪器事故，不是现象；cfu 阴性不可用。

### 9.1 A/B 结果：INVALID

- 结论：WED 写入者不能用 unload 判决；剩余判决只能走 P-C 页级实验（释放+填毒+记录 PA）或静态窗口。



## 10. P-B 静态：page_frag / RX buffer 生命周期（21:30）

- warp_os_alloc_mem（0x1d2c）= __kmalloc；warp_os_free_mem（0x1d68）= kfree；不是 page_frag/dma_free。
- wed_rx_bm_init（0x1c4a8）：0x28/0x30 条目数组 + 0xa20 数据缓冲，全部 warp_os_alloc_mem（kmalloc）；page_frag_alloc_align + dma_map_page_attrs 在 +0x270。
- wed_rx_bm_exit（0x1c338）：逐条目 memset(0x50) → __page_frag_cache_drain（0x1c43c/0x1c468）→ vfree（0x1c47c）→ warp_dma_buf_free（0x1c488）。
- 结论：RX buffer 的 page_frag 页在 exit 时被 drain；exit 路径没有“先 free 后停硬件”的明显倒序；运行期 refill（wed_rx_bm_token_init/wed_acquire_rx_token 回调）仍未闭合。
- 与 P-C 的关系：P-C 应针对 page_frag 页（0xa20 数据缓冲）而不是 kmalloc 条目数组；page_frag 页是硬件 DMA 的真实目标。
