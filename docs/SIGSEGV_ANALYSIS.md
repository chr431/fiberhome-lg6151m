## 1. 机制（已验证）

**蜂窝 MD 固件经 DPMAIF 的 RX DMA，按 MD 侧私有持有的陈旧（stale）缓冲页
列表，持续向 AP DRAM 写 16/32 字节环记录。被写页一旦被复用——用户进程的
anon 页、或已释放回 buddy 的内核页——就成为全家族 SIGSEGV 的注入源。**
printf 家族只是最高频的污染内存解引用路径（选集效应，§5.1），不是缺陷方。

机制链（每一环都有实测锚点，见 §3/§4）：

```
[AP] dpmaif/ccci RX 缓冲池页（4KB/条，环记录 PLEN0=4096 管理）
  → 生命周期事件（队列重建/端口关闭 churn）后页被释放回 buddy，
    但 MD 侧私有持有的缓冲页列表【不失效】（§3-E4：AP 全量不可见）
[MD] MD 经 DPMAIF RX DMA 继续向列表内 PA 写环记录
  → 输出与当前活环内容字节一致（§3-E2：活 PIT 值两次注入用户页）
[受害] 被写页已被复用：用户 anon 页（绊网活捉）/已释放内核页（死后写入）
  → 污染块落在任意数据结构上，按形状表现为 va_list 崩溃/NULL 解引用/
    .bss 指针损坏等不同签名（全家桶"看起来"是多个缺陷，实为一个机制）
[排除] AP 驱动映射路径干净（§3-E5：1465 次映射零坏页）；
  活 BAT/PIT 表与全部 dpmaif 寄存器零陈旧（§3-E4）
```

## 2. 已验证判据（照抄使用，不要自己发明）

### 2.1 注入块签名（识别新 core/现场用）

- 16B 块 `{small, 0}`：small ∈ [0x2710, 0x40000] ∪ {0}，非单调；
- 32B 块 `{small, 0, 0x????????_0000_06xx, 0}`：低 32 位落在 0x6xx/0x1180 族；
- 同页可多块（16B 节距）；页尾 0xfc0 起（word 504+）高发；
- **禁止用 magic 值当指纹**：`0x1c28416e00000680` 等高 32 位在现场间会变，
  只能作个案旁证（曾在 6 处/4 个独立构建重复出现）。

### 2.2 va_list 健康判据

- 三个指针字段（`__stack/__gr_top/__vr_top`）落在用户态可访问范围；
- **`*_offs == 0` 不是坏值**：第 9+ 个变参正常走 `__stack`（musl pop_arg
  0x51e8c：`gr_offs>=0` → 走栈）；旧判据"两个 offs 都为负才健康"会误判合法
  长参数列表；
- 健康基线（实测）：`{栈地址, 栈地址, 栈地址, -48, -128}`。

### 2.4 内核 fault 行读法

arm64 是 `unhandled exception: DABT`，`[base+size]` 是**故障指令所在 VMA**
不是故障地址；dmesg 会被 printk 限流吞行（fault 计数须以 aee 增量为准）。

## 3. 写入者身份（坐实，2026-10-22）

**写入者 = 蜂窝 MD 固件经 DPMAIF 的 RX DMA（活体）**——它参与当前环维护
（输出与活环同源），只是写目标（缓冲页列表）是陈旧的。

| # | 证据 | 结论 |
|---|---|---|
| E1 | injwatch4 全程 38min 报 **21 次命中**，全部页尾 0xfc0/word504-505；受害页实测 `st=1`（PageAnon）、rcnt=1、mapping 带 ANON 位 | 注入持续可复现；受害页是用户页 |
| E2 | 活 PIT 环页尾（0x90800000+0xfc0）内容 `{0x92d7a600,0}{0x92d79e80,0}…` 实测在案；**0x92d7a600 两次被原值注入两个不同用户页** | 写入内容=当前活环记录 ⇒ 写入者是活体环维护者（MD/DPMAIF RX） |
| E3 | 16B 记录 `{0xe7e0f000,0x80000000,0x30000000,0xa}` 持久存在于已释放的 findpa staging 页（其余内容是 ELF 残影）；记录本身引用另一受害页 0xe7e0f000 | **释放页死后写入**；环记录引用已释放缓冲（与 §4-A5 的 `{PLEN0=4096,DONE=0,ptr→受害页}` 环条目同族） |

## 5. 受害者生态与缓解定性

### 5.1 选集效应

污染块落在进程内存任意位置，多数落点无人解引用；printf 的 pop_arg 是全系统
最高频的解引用点，所以全家桶"看起来"是 libc 缺陷。`-l 200` 降幅、纯字面量
不崩、自有可变参数"不崩"（解引用点少一个量级）由此统一解释。

### 5.2 已落地缓解（保留+冻结，§22 口径）

| 项 | 实测效果 | 定性 |
|---|---|---|
| logc v1.4 去 printf | 7 崩/h → 0（A/B 10:0） | 保留：摘掉最高频解引用点 |
| logcut 替换 awk | 18.4/d → 0 | 保留：少 spawn+无大数组堆页 |
| procmatch 替换 pidof/pgrep | 2.7/d → 0 | 保留（另修 busybox pgrep -x 真 bug） |
| P2 静态工具链农场 | **崩溃零改善**（静态件同崩） | 保留但**冻结**（F1：不再为治崩溃扩面）；退役须根修验收后两臂 A/B |
| core_trap/core_meta、watchdog aee 增量判据 | 证据管线有效 | 保留 |
| `ap_auto_logging=0` 护栏 | 防 logread -f 常驻复活 | 保留（红线） |
| hardened vfprintf（guard 拦截） | 技术有效但 guard 误伤 gr_offs=0 合法态 | 归档不部署 |

**冻结规则**：F1 不再为治崩溃新增用户态替换；F3 文档/注册表不得再把 musl/
awk/pidof 写成缺陷根因；gw 侧无崩溃修复主线，主线=§8。

### 5.3 运营注意

- dropbear 高频 spawn 会卡死（accept 后 EOF/无 banner，不可恢复，只能
  `sys_reboot`）——取证脚本限并发、结果落 /data；
- 取证探针自身崩溃会进 ne_events/aee 台账，普查按 §2.3 规则扣除。

## 8. 修复主线：dpquarantine（页隔离内核模块）

### 8.1 设计（为什么是它）

- MD 侧列表 AP 不可达（E4）⇒ **修不了写入者，只能切断"被写页进入复用流"**；
- memmap 预留（LK cmdline）：依赖"失效 PA 跨重启稳定"，与观测（受害页随
  剧集滚动、分布跨 175MB）不符——**降级为兜底**；
- stop-path leak-on-timeout（A6 顺序缺陷）：只覆盖 stop 窗口，实测注入发生
  在无 stop 的稳态（基址 1h 不动）——**单用不足，降为辅助**。

### 8.2 方案

`dpquar.ko`（源码 `gw/src/dpquar.c`，调用点补丁机械与 dphook 同款、已验证）：

1. 钩 dpmaif 的 `dma_unmap_page_attrs` 释放点（6 处，站点表见源码），shim 在
   原调用前对 `dma_addr`（=PA，无 IOMMU）解析页，`get_page_unless_zero` 加
   引用 → 页不回 buddy，入隔离表；
2. 策略：在押 TTL（默认 24h，`hold_s`）+ 总量上限（默认 4096 页/16MB，`cap`），
   FIFO 逐出——**有界**，无 OOM 风险（队列稳态长寿命，隔离事件罕见）；
3. 观测面：每站点计数（调用/隔离/逐出）+ 在押页页尾监视（**writer-hit =
   在押页被写次数——修复有效性与机制命中的直接验收读数**）+ /proc/dpquar；
4. 站点启用按位掩码（`qmask`）：teardown/错误路径（冷站点）默认隔离，每包
   路径（热站点）默认只计数——防隔离洪水；
5. rmmod：先还原补丁、msleep 让在飞 shim 退出、逐出全部在押页。

### 8.3 验收口径（§22.7 原则）

模块在位 + 补丁点命中计数 + **writer-hit>0 证明机制命中**；injwatch4 剧集期
用户页命中 → 0。**装后残余属预期**：已被 MD 列表持有的存量页会继续被写，直到
MD 列表自然失效/MD 重启——残余期"只降不零"，文档化。崩溃率只作旁证（26/d
基线下 7 天期望 182 次，统计判据不敏感）。两臂 A/B（开/关各 7 天）后才谈
农场退役（§5.2）。

### 8.6 活跃源定性（已解决，2026-10-22 深夜轮）

v1.3 实测排除 + 三轮新仪器后，**活跃源已定性并压制**：

**排除**（全部实测锚点）：
- dpmaif 全 10 站点在押零命中时注入仍 ~2/min → 交接不经 dpmaif dma 路径；
- **环本体**：ktext 全文 cci/dpmaif **零 `dma_free_attrs` 调用点**——环只分配
  （bat_init+0x60/late_init+0x348）不释放（每次队列重建泄漏性保留），永远不回
  buddy，当不了受害页；
- **cci_ipc/ILM**：`ccci_ipc_send_ilm` 为拷贝进 skb 路径，不交 PA；
- **端口 churn**：E7 复测撤回（无因果）。

**buddyscan 定性**（自底向上：扫 buddy 页注入签名，buddy 页保留前属主内容）：
- 陈旧列表人口直接可见：**~400 个固定 PA 的 4K 页集合**（6 min 内 distinct=402、
  192 个 ≥5 次重现、单页最高 113 次；45s 窗口 44 进 44 出 ≈1 页/s 被写）；
- 记录形态：**同值记录喷多页**（`{0,0x5e,0}` 族与 `{6,0,…,0x70014,0}` 族），
  非逐槽异值的环游标——状态/广播类写入；
- 成员页除尾部记录外**内容全零**（ex-anon/零填页）；前属主考古因此不可用；
- 4 个稳定成员 findpa 交叉：全部为扫描器自匹配（§3-E6 特征）——**AP 侧零引用，
  列表在 MD 侧私有持有**，与 E4 一致；跨 MD 温复位存活（CFUN=1,1 后 1–2 min 恢复）。

**关键盲区发现（migrate 类型）**：列表成员是 ex-anon 页，位于 **MOVABLE 迁移
链表**；`GFP_KERNEL` 分配只从 UNMOVABLE 链表取页——dpclamp v1.0 用 GFP_KERNEL
**147K 次采样零命中**（同期 buddyscan 每轮 ~47 张签名页）。这是此前一切"抓不到
交接"的分配侧原因。换 `GFP_HIGHUSER_MOVABLE` 后立即命中。

### 8.7 修复栈与字段判决（dpquar + dpclamp）

**完整修复 = 两件**（写入者本身在 MD 侧不可修，AP 侧掐断页面供给）：

| 件 | 作用 | 机制 |
|---|---|---|
| `dpquar` v1.3（§8.2） | **断新漏** | 钩 dpmaif 全 10 个 unmap/还页点，teardown 释放页加引用隔离（实测 49373 调用 15911 页零漏网） |
| `dpclamp` v1.1 | **排存量** | 周期 `GFP_HIGHUSER_MOVABLE` 批量采样 buddy，页尾注入签名**自识别**的列表页 get_page 扣住（cap 8192 页有界），未命中即释放；writer-hit 遥测 |

**字段判决（2026-10-22 21:37–21:57，重启后干净态）**：两件在位，
dpclamp 417K 次采样扣住 18 张列表页（收敛持续），**用户页注入 2/min → 0
（20 min 零命中）**，同期 buddyscan 显示写入者仍以 ~1 页/s 活跃于空闲页
（P(0|无效)=e^-40）——列表成员在到达用户之前被钳制。dpclamp v1.0 事故记录：
`alloc_pages_bulk_array` 在 `__free_pages` 崩溃（21:33 KE，设备自愈重启），
v1.1 改单页循环。

零命中保持）；② rc.extend 开机自载两模块（验收后）；③ 观察 dpclamp 收敛上界
