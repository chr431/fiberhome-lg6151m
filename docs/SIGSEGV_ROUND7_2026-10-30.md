# NE 崩溃调查 · 第七轮（2026-10-30 收尾场）

> **历史文档（2026-10-30 归档）**：当前状态见 [docs/SIGSEGV/00_STATE.md](SIGSEGV/00_STATE.md)；结论台账见 [01_CLAIMS.tsv](SIGSEGV/01_CLAIMS.tsv)。本文保留原样，勿据此判断当前结论。

本轮两个议题：
1. 按「写入可能来自多个不同源」重做取证；
2. 造一个**不预设写入者身份**的陷阱（只读金丝雀页），任何写进去的存储都会留下 pc。

结论：**多源已被数据支持**；陷阱**没有被打中**，而这本身给出了一条很硬的新约束。

---

## 1. 多源证据：记录至少有两个家族

本轮 12 次崩溃的 fault 地址（= 被破坏的 va_list 首字）分成两族：

| 家族 | 取值 | 出现次数 | 特征 |
|---|---|---|---|
| A | `0x28416e00000640` | **4 次**（跨不同 pid、不同时刻） | **完全相同的常量** |
| B | `0x11035 0xebcd 0x182ce 0x1d673 0x8c5b 0x4d9b 0xdb54 0x16c35` | 8 次 | 全部落在 [0x4d9b, 0x1d673]，**每次都不同** |

家族 A 反复出现**同一个 64 位常量**（`hi32=0x28416e00`，`lo32=0x640`）——这不可能是随机或
per-process 指针，只能来自**某个固定来源**（全局量 / 固定结构 / 固定偏移）。
家族 B 每次都变，来自**另一个来源**。

⇒ **至少两个不同的写入者。** 后续任何"抓一个就收工"的做法都是错的。

## 2. 只读金丝雀陷阱（不预设写入者）

`tmpfiles/an4/vro.c`：`main()` 进入**纯寄存器读循环**（内联汇编，无栈写、无调用），
辅助线程随后把**顶栈页**（含 `start_stack-0xc0`，即历次记录落点）`mprotect(PROT_READ)`。

于是：任何**内核**对该页的 uaccess 存储（无论 `copy_to_user` 还是内联 `sttr`、无论多大、无论谁）
都会触发 permission fault，被 `cth.ko` 的 `do_page_fault` 钩子记下 `far` + **出错指令 pc** + comm。

- 用户态写会 SIGSEGV，所以 main 从不写该页（实测 0 次 user fault）。
- `pf_kernel_only=1` 把用户态 fault 全部滤掉，只留内核态。

**运行条件**：ASLR 关、24 个 vro + 8 个 vsurv3（后者作"现象是否还在"的对照）、5 分钟以上。
同期 vsurv3 崩了 **12 次**（家族 A/B 都在），`cth: PF` = **0**。

按比例：24/(24+8)=75% 的进程是 vro；12 次崩溃 → 若写入与"目标进程在干什么"无关，
应有约 9 次落在 vro 的只读页上。实测 0。

**⇒ 写入不是在"任意进程停在那个地址"时发生的。它被绑定在"目标进程正在执行那次可变参调用"上。**

## 3. 受害者从来不在系统调用里

`/proc/<pid>/syscall` 采样 600 次，全部返回 `running`；`/proc/<pid>/stat` 状态 200/200 全 `R`。

⇒ 受害者**几乎永远在用户态**。结合第 2 条：写入发生在**该 CPU 上打断用户态的
中断上下文**里（此时 `current == 受害者`，`current->mm` 就是受害者的 mm）。

## 4. 与上一轮的否定合起来

上一轮已用四种过滤（全上下文 / 内核+中断 / 仅内核线程 / 受害者自身）× 200 次崩溃证明：
**这条写入不是 `copy_to_user`**（探针字节级校验在位）。

结合本轮：
- 不是 `copy_to_user`（任何上下文）；
- 不在"目标进程停着"时发生；
- 发生在打断用户态的中断里。

⇒ **写入者是"中断上下文里的一条内联 uaccess 存储（`sttr`）"。**

## 5. 下一轮仪器已经定型（关键前提已验证）

arm64 + SW TTBR0 PAN 下，任何内联 uaccess 存储都必须先打开 uaccess 窗口：
`uaccess_ttbr0_enable.isra.0` / `uaccess_ttbr0_disable.isra.0`。

本轮实测：
- 内核镜像里这两个符号各有 **150 个本地克隆**，合计 **1050 + 1005 个调用点**；
- **全部 300 个克隆的第一条指令都是 `paciasp`**（0 例外）。

⇒ 可以安全地做 **300 站点 uaccess-window 探针**：每个克隆 `+0` 改成 `b <该克隆专属 trampoline>`，
trampoline 先执行 `paciasp`（在入口 SP 上，与原来等价），再取参数、记录
`lr(=克隆+4)` / `comm` / `in_interrupt()` / `current_pt_regs()->sp`，最后 `b 克隆+4`。
因为内核无 KASLR、模块区与内核 text 相距约 107 MB（< ±128 MB），分支可达。
每个克隆的 trampoline 由脚本按站点表生成，无运行时查找、无自改代码。

判据：**只要 `in_interrupt()` 为真且 `current_pt_regs()->sp` 落在受害者栈页，
就直接点名写入者**（pc 所在的函数）。

## 6. 本轮的其它落点

## 7. 教训

- **教训 37**：多源是默认假设。记录必须按"家族"分类（本轮的 A/B 就是靠"同一个常量重复出现"
  才浮出来的），不能把所有崩溃当成一个写入者。
- **教训 38**：`mprotect(PROT_READ)` + `do_page_fault` 钩子是**唯一不预设写入者形状**的陷阱
  （不看大小、不看函数、不看上下文），代价是必须先让目标进程"不写那一页"。
- **教训 39**：`/proc/<pid>/syscall` 是判断"受害者是否进过内核"的最便宜手段，
  比 `stime`/`minflt` 可靠得多（后者被我们误用过一次）。
