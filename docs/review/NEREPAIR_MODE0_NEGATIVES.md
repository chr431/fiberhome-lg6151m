> **任务**：看板 task-7。nerepair 已实机布防（2026-11-03 19:55:21 dry→armed，无重启），mode 0 是**在役**的默认修复门，而它**不调用 shape_ok**。本报告在 host 侧补上这块从未测过的负样本回归。

> **判据来源**：`gw/src/nerepair.c`，md5 `d28b1d0ec0edf4716775e686432dac06`（构建脚本每次运行重新抽取并打印 md5）。
> **语料**：`_local/evidence/crash-root/h4_rec150.txt`（150 条真记录；本机统计 **114 A0B2 / 36 B0A2**，与 `docs/SIGSEGV/00_STATE.md` 的 114/36 一致）。

## 0. 判决（三句话）

1. **mode 0 的假阳性面是结构性的，可以 100% 构造命中**：只要 16 KB 扫描窗里存在一个 32 B 窗 `{X,0,Y,0}`，且 `low32(X)` 或 `low32(Y)` 落在 `addr±8` 且本身在 `[0x400,0x20000]`，mode 0 就接受——**不要求第二个非零字存在、不看高 32 位、不看长度语义**。实测：`{V,0,0,0}`（单小值 + 零填充）**509/509 与 200/200 全收**；`{V1,0,V2,0}` **300/300 与 200/200 全收**；而 `shape_ok` 对同一批样本 **0/100 与 0/509**（100% 拒绝）。Wilson 下界：mode 0 接受率 **≥98.1%**（n=200 档）。
2. **假阳性随栈的"零密度"放大，不由随机性驱动**：结构化稀疏栈（`p_zero` = 0.40/0.55/0.70/0.90）+ 故障地址取"窗内确实出现过的那个 in-band 值"（即"整数被当指针用"的自然场景）⇒ mode 0 接受率 **27.2% / 45.4% / 60.6% / 88.6%**（Wilson 95% CI 在 §3）；而**纯随机字节 0/500**（0.0% [0–0.8%]）⇒ 驱动因素是**零填充结构与"地址就是窗内那个值"**，不是碰巧。
3. **假阳性窗口被夹在 `addr ∈ [0x400, 0x20000]`**：带外地址（<0x400 或 >0x20000）**0/500 全拒**（F4a/F4b）。这条同时是 mode 0 的**漏修窗口**：150 条真记录里，A0B2 的 A 值超带的 2 条、以及全部 36 条 B0A2（故障地址是复合字 ⇒ 根本不进 mode 0）都修不到。
4. **建议（v2.3 变更项）**：把 mode 0 的"单字门"换成 **形状校验窗**（几何条件不变，改用 `shape_ok` 复核 ±16 相关的 8 对齐窗）。实测代价：构造负样本 **0/4,209 全拒**（95% 上界 0.09%），真记录 **0/150 丢失**（F6 的 150/150 与 P 的 112/112 全部保留）。

## 1. 判据（从现行源码逐字抽取，不做拷贝）

mode 0 = `find_record_near_stack(pid, sp, addr, …, mode=0)`（`gw/src/nerepair.c:627-689`）的内层测试，逐字等价于：

    for each page in [sp & ~0xFFF, +16 KiB), 4096 B read via process_vm_readv
      for off = 0; off + 32 <= 4096; off += 8:
        q0..q3 = 4 qwords
        if (q1 != 0 || q3 != 0) continue
        lo0 = low32(q0); lo2 = low32(q2)
        if (lo2 == addr || lo2 == addr+8 || lo2 == addr-8) { if (!len_band(lo2)) continue; ACCEPT(which=q2) }
        if (lo0 == addr || lo0 == addr+8 || lo0 == addr-8) { if (!len_band(lo0)) continue; ACCEPT(which=q0) }
    len_band(v) := 0x400 <= v <= 0x20000

**与 `shape_ok` 的三点结构差异（这就是假阳性面的来源）**

| # | `shape_ok`（硬门） | mode 0 | 后果 |
|---|---|---|---|
| 1 | 要求 `w1==0 ∧ w3==0` **且** 另一非零字必须构成合法形态（`small0∧big2` 或 `big0∧small2`） | 只要 `w1==w3==0`，**另一字可以完全不存在**（`{V,0,0,0}` 也收） | 单小值 + 零填充被当成记录 |
| 2 | `len_band` 作用在**记录里的长度字**（`lo2`/`lo0` 是"另一个字"） | `len_band` 作用在**匹配到的那个字**上 ⇒ 要求"故障地址本身像长度" | 语义错位：把 A 值当长度判；A>0x20000 的真记录被结构性拒 |
| 3 | 用 tag 掩码比 `w0` 与故障地址 | 比 `low32(q0)/low32(q2)`，且**高 32 位完全不看** | 复合形态/大值不再被区分 |

> 结论：mode 0 不是"shape_ok 的弱化版"，而是**另一套判据**；它的接受集 ⊋ 真家族集合。

## 2. 方法（host 侧，可复现）

- **抽取**：`build_mode0_test.sh` 每次运行从 `gw/src/nerepair.c` 用三段 `sed` 抽出 `#define NR_TAGMASK..NR_LEN_MAX`、`static int shape_ok`、以及 `#define DEREF_SCAN_BYTES .. /* returns 1 if this fault was handled`（含 `len_band` 与 `find_record_near_stack`），共 186 行；并**断言**抽出的定义是 mode-aware 版本（v2.0 的旧签名没有 `mode` 参数）——不是则拒绝运行。
- **一处有据的宽度归一化**：本 host 是 LLP64（实测 `sizeof(unsigned long)=4`），而设备是 aarch64/LP64。若不处理，`(f >> 32)` / `(w2 >> 32)` 会在 32 位值上移位 32 位 ⇒ **静默变成 0**，等于测了一条设备上不存在的判据。脚本只做两处机械替换：`unsigned long → uint64_t`、`UL → ULL`（只改类型宽度与整型后缀，不动任何运算符/常量值/分支顺序），并在运行结束时用两项对照证明归一化正确：
  - **对照 A**：`shape_ok(真记录, w0)` **150/150 接受**（这条走 `big2` 分支——正是 32 位截断会杀掉的分支）；
  - **对照 B**：`shape_ok({V,0,0,0}, V)` **0/100**。
  （若归一化有误，对照 A 会立刻塌成 0/150。首轮未归一化的运行确实塌了——见 §7 的"实测教训"。）
- **谓词**：每条样本同时评估三个谓词——`mode0`（现役门）、`proposed`（建议的形状校验窗）、`shape_on_hit`（对命中窗本身跑 `shape_ok`，用于判断"只加命中窗硬门"是否安全）。
- **统计**：率 + Wilson 95% 置信区间（`z=1.959964`，脚本内实现；n=0 时区间按 [0, 3/n] 规则给出）。

**P 的 FN 分解（114 A0B2 / 36 B0A2）**

- A0B2（w0 = A）**114 条**：其中 **112 条 A ∈ [0x400,0x20000]** ⇒ mode 0 经 which=q0 全部接住；**2 条越带**（实测 w0 = `0x20282`、`0x2007d`，仅比 0x20000 高一点）⇒ **被结构性拒**。**A0B2 的 q0 分支漏修率 = 2/114 = 1.8% [Wilson 95% 0.5–6.2%]**。
- B0A2（w0 = 复合字 {len,ip}）**36 条**：`addr = w0 ≥ 2³²` ⇒ 既不在带内，也不在 mode 0 的比较范围内（真实故障地址是 ≥16 MiB 的复合字，`deref_attempt` 会走 X2 分支，而 **X2 默认关**）⇒ **36/150 = 24.0% 结构性不覆盖**。
- **对账**：设计注释 `:716-719` 写"自然 NE 6/7 条落此缺口"，那是**另一份 7 条自然 NE 语料**；本报告的分母是 150 条 canary 语料（2/114）。两者**语料与分母都不同，不得互相换算**。

**命中位置（证据质量）**：P 族前 3 条的实测命中落在 `0xea8`(which=q2)、`0xea8`(no hit)、`0xe98`(which=q2)——即**命中窗常常是"记录前一个 32 B 窗"**（该窗的 q2 恰好是记录的 w0）。动作语义相同（都是 `regs[rn]=sp; pc+=4`），但日志里的 `rec=` 不是记录起点。这条同时说明：**"只对命中窗做 shape_ok"会误伤**——P 族 `shape_on_hit = 0/150`，而那 112 条正是 mode 0 现在唯一能接住的真记录。

## 5. 建议（v2.3 变更项）

**推荐：形状校验窗（shape-validated window）**——几何条件一字不改，只在接受前把"单字命中"升级为"整记录复核"：

    hit = 命中偏移（which==0 时匹配字是 q0，which==2 时匹配字是 q2）
    cand[0] = hit                                        /* 匹配字作 q0 */
    cand[1] = (which==0) ? hit-16 : hit+16               /* 匹配字作 q2（另一侧） */
    accept ⇔ ∃ c ∈ cand，c 在窗口内且 c+32 不跨映射边界，且 shape_ok(buf[c..c+32], buf[c].w0)

实测代价/收益（同一份语料、同一台 host）：

| 指标 | 现役 mode 0 | proposed |
|---|---|---|
| F1–F5 构造负样本接受 | 2,318/4,209（55.1%） | **0/4,209（0.0%，95% 上界 0.09%）** |
| F6 真记录（长度字路径） | 150/150 | **150/150（无损失）** |
| P 真记录（A 字路径，112 条可达） | 112/150 | **112/112（无损失）** |
| 额外 I/O | — | **0 次**（原扫描已把 4 页读进缓冲；跨页/边界处需按缓冲边界处理，或退回一次 32 B `process_vm_readv`） |
| 额外 CPU | — | 每次命中 1–2 次常数时间比较（`shape_ok` 只比 4 个 qword） |

**不要做的两种改法**
1. **"命中窗直接套 shape_ok"**：P 族 `shape_on_hit = 0/150` ⇒ 会丢掉那 112 条真记录（90% 的 A 字路径覆盖）。必须带 ±16 的另一侧候选。
2. **只收紧 `len_band` 的位置**（例如改成对"另一个字"判带）：会顺带废掉 which=q2 的长度字路径（F6 150/150）——除非同时引入 X3 的 shape_ok 门。

**proposed 不解决的问题（必须并列写明）**：A0B2 ∧ A∈带外（2/114）与全部 B0A2（36/150）仍然覆盖不到；前者要靠 **X3**（shape_ok 替代 `len_band(lo0)`），后者要靠 **X2**——而 **X2/X3 两把钥匙默认关**（`xrep=0`）。若目标是"少漏"，需要在 v2.3 里把 X2/X3 或至少 X3 转为默认开，并注意成本影响（`docs/review/NEREPAIR_PERF.md` §9：X3 的第二次 16 KB 行走在 `g_xrep=1` 时**绕过` `xform_budget()` 的 50 次/s 上限）。

## 6. armed 窗口的观察建议（哪些 REPAIR 应人工复核）

**现状（设备侧，只读）**：STAT 里与 deref 路径相关的计数是 `rep2=`（deref 修复累计）、`dfhit=`（进入 deref 判据并被接住）、`would2=`；布防后 `DREPAIR` 行格式为


```
DREPAIR  pc=0x…  addr=0x…  rn=<n>  rec=0x…  which=q0|q2  q0=0x…  q2=0x…
```


**人工复核规则（凭日志自身即可判，不需要设备）**

| which | 从日志可重建的窗 | 复核规则 |
|---|---|---|
| `q0` | `[q0, 0, q2, 0]`（门已保证 `q1=q3=0`） | 直接算 `shape_ok([q0,0,q2,0], addr)`：**不过 ⇒ 疑似假阳性**（应人工看该进程/站点） |
| `q2` | 同上（匹配字是 q2） | 记录可能在**后一窗**：判 `q0` 是否像 A 字（`0 < q0 < 2^24`）且 `q2` 是否像 `{len,ip}` 复合（高 32 ≠ 0 且低 32 ∈ [0x400,0x20000]）；两条都满足 ⇒ 良性；否则 **REVIEW** |

**现成脚本**：`tools/oneoff/sigsegv/mode0_repair_triage.py <nerepair.log>`（纯 host、只读日志、离线可跑）。自检（§7）实测输出：

    REVIEW pc=0x4e6f68 addr=0x1234 q0=0x1234 q2=0x0 which=q0
    ---
    deref repairs: 2 ; shape-consistent: 1 ; REVIEW: 1

（第一条是规范记录 `{0x1ee27,0,{len,ip},0}` ⇒ ok；第二条是 `{V,0,0,0}` 形态 ⇒ 被标 REVIEW，正是 mode 0 会误修的形态。）

**建议的处置阈值（需 Lead 裁定，此处只给可执行初值）**
- `REVIEW` ≥ 1 条 ⇒ 逐条人工复核（对照该 pid 的 core/.stack 与站点）；
- `REVIEW` 比例 ≥ 30%，或 24 h 内 ≥ 5 条 ⇒ 建议**回 dry-run**（删 `/data/gw/nerepair.dry` 的反操作 = 建回标记并 `killall` 重启，属写操作）**并先上 §5 的形状校验窗**再布防；
- `REVIEW` = 0 且 `rep2` 增长 ⇒ 记为该窗口"deref 修复形状一致"，可纳入 v2.3 门禁证据。

**实测教训（值得写进方法论）**：**首轮运行是错的，且错得无声**。host 是 LLP64（`sizeof(unsigned long)=4`），抽出的判据里 `(f >> 32)` 在 32 位值上移位 ⇒ 恒 0 ⇒ `shape_ok` 的 `big2` 分支被杀死：
- 首轮"对照 A"（`shape_ok(真记录,w0)`）会给出 **0/150**，而正确值是 **150/150**；
- 首轮 F6/P 的 `shape_on_hit` 全 0、`P mode0` 从 112 变 148（因为复合字被截成低 32 位后误判"在带内"）。
只有把宽度钉成 `uint64_t` 并保留那两项对照，数字才成立。**任何"从设备源码抽判据到 host 跑"的回归都必须自带一条"只有 64 位才成立"的对照**，否则会静默测出另一个判据。

**判据抽取范围与完整性**（脚本内三段 `sed`）
- `/^#define NR_TAGMASK/,/^#define NR_LEN_MAX/p` → 三个常量；
- `/^static int shape_ok/,/^}$/p` → 硬门本体；
- `/^#define DEREF_SCAN_BYTES/,/^\/\* returns 1 if this fault was handled/p` → `DEREF_SCAN_BYTES`/`DEREF_SMALL_MAX`/`NR_LEN_LO/HI`、`is_load_insn`、`xf_*` 分类、`len_band`、`find_record_near_stack`、`addr_family_plausible`。
- **未抽取**（也不需要）：`deref_attempt`（调用方）、`read_mem`（本 harness 用受控 16 KB 镜像替换）、`xform_budget`、slotdrop。因此本报告测的是**判据函数**，不是完整路径（调用方门控在 §8 说明）。

## 8. 边界与未测（[B]/[C]）

**[B] 未核实**
1. **设备侧的无条件假阳性率**：本报告给的是"判据在给定窗内容下的行为"（E3）；F3 的 27–89% **以"故障地址就是窗内那个带内值"为条件**。设备上 deref 型故障地址的分布（有多少落在 [0x400,0x20000]、其中多少同时出现在被扫窗里）**未测** ⇒ 不能把 55.1% 或 88.6% 直接读成"设备上每 N 次崩溃会误修 M 次"。
2. **稀疏栈模型**：F3 用 i.i.d. 槽模型（零/带内整数/其它），真实栈有连续零区、结构体、指针数组、ASCII 串等 run-length 结构 ⇒ 接受率会偏离；模型参数已写出，可换。
3. **语料代表性与口径**：150 条语料是 **canary 家族**（vsurv4 探测器），不是自然 NE；"114/36"是 A/B 形态构成，不是自然发生率。自然 NE 只有 4/4 的小样本（n=4，不可外推）。
4. **归一化的语义等价性**：只做了类型宽度与整型后缀替换 + 两项对照；**没有**逐语句语义比对（未见任何运算符/常量值/分支顺序变化，且对照 A 走 `big2` 分支通过）。
5. **proposed 门的实现细节**：跨页/跨映射边界的 ±16 候选读法（是否退回一次 32 B `process_vm_readv`）在源码层未实现、未计成本；本报告只测判据语义。

**[C] 必须上设备 / 需写操作才能确认**
1. **设备侧 deref 故障地址分布**（判据：`DREPAIR`/`WOULD_DREPAIR` 行的 `addr` 直方 + `which` 分布）——只读即可取，但需在 armed 窗口跑（当前窗口 `dfhit/rep2` 样本极少）。
2. **REVIEW 率的实测**：armed 窗口内用 §6 规则统计 `DREPAIR` 行的形状一致比例。
3. **v2.3 形状门上线后的 a/b 对比**（写：改二进制 + 部署）——预注册同 boot ABAB，判据 `REVIEW` 率与 `rep2` 增量。
4. **X2/X3 默认开**（写）。它们覆盖本报告量到的两处 FN（A0B2 越带 2/114、B0A2 36/150），但成本需按 `NEREPAIR_PERF.md` §9 预注册测量。

## 9. 结论分级

### [A] 已核实（host 可复算，含两项对照）
- 判据从**现文本**抽取（源 md5 `d28b1d0ec0edf4716775e686432dac06`，mode-aware 断言通过，186 行），未使用任何过期版本。
- mode 0 接受 `{V,0,0,0}` **509/509 + 200/200 = 100% [≥98.1]**、`{V1,0,V2,0}` **300/300 + 200/200 = 100% [≥98.1]**；`shape_ok` 对同族样本 **0/100**、对真记录 **150/150**（对照 A/B）。
- 稀疏栈条件接受率 **27.2 / 45.4 / 60.6 / 88.6%**（p_zero 0.40/0.55/0.70/0.90，CI 见 §3）；纯随机 **0/500**；带外地址 **0/500**。
- 真记录：`addr=`长度字 **150/150**；`addr=w0` **112/150**，其中 A0B2 112/114、B0A2 0/36；A0B2 越带漏修 **2/114 = 1.8% [0.5–6.2%]**。
- proposed 形状校验窗：构造负样本 **0/4,209**（95% 上界 **0.09%**）、真记录 **0/150 丢失**（F6 150/150 保留、P 112/112 保留）。
- "只对命中窗套 shape_ok"不安全：P 族 `shape_on_hit=0/150`，会丢那 112 条。
- 自检：`mode0_repair_triage.py` 在本会话的合成日志上给出 2 条 deref 修复 / 1 条一致 / 1 条 REVIEW。

### [B] 未核实（原因）
- 设备侧无条件假阳性率（缺故障地址分布，见 §8.1）；稀疏栈模型的代表性（§8.2）；语料是 canary 而非自然 NE（§8.3）；归一化的逐语句等价性（§8.4，现仅有行为对照）；proposed 的边界实现与成本（§8.5）。

### [C] 必须上设备才能确认（含写操作）
- armed 窗口 `DREPAIR` 的 addr/which/形状一致性统计（只读即可，但需样本量）；
- v2.3 形状门 ABAB（写）；X2/X3 默认开的收益与成本（写）。
