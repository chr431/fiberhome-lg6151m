# 08 · D25 预注册 · 从受害 VA 反查「持有截断地址的描述符」（2026-11-03 D4）

> **预注册文档：实验开窗之前写定并 commit。实验后只追加 §9–11，不改 §1–8。**
> 编号 08 顺延（01..07 已占用）。中性命名：不含目标网络名与个人凭证。

## 1. 问题

D2 的地址宽度假设：若驱动把**用户 VA** 当内核 VA 做 `virt_to_page` 算术，完整
PA = `va + 2^39`（mod 2^64）通常远超 DRAM；但若描述符/环控制块只保留**低 32 位**
（CCCI `str w1,[desc+idx*8+0]` 实证字段），实际总线地址 = `va & 0xffffffff`，
只要该值落在 `[DRAM_BASE, DRAM_BASE+SIZE)`（本机 `0x80000000-0xffffefff`）就会
写进真 DRAM——这能解释「受害者是随机栈页」与「不是每次都崩」。

D1（C-207）已排除背景态下 `dma_map_page_attrs`/`dma_map_sg_attrs` 两个 wrapper
上的伪页通道；D2 线指出真正的「截断」发生在**驱动自己写描述符**的内联路径。
本实验换方向：**不做写侧钩子，直接从受害 VA 反查——RAM 里有没有任何结构
（队列/描述符/环/控制块）持有该 VA 的截断 32 位值或原值。**

## 2. 假设（先写死）

- **H_trunc**：存在某个 DMA 队列/描述符/环结构持有 `(受害 VA & 0xffffffff)`
  （32 位 LE 字段）或受害 VA 原值（64 位）；即「用户 VA 被写入硬件可见结构」，
  该结构就是写侧链路的名点对象。
- **H_absent**：全 RAM（可读部分）无任何合法归属的命中；截断地址不由静态 RAM
  结构持有（可能在硬件内部寄存器/FIFO、或地址并非截断形态）。

## 3. 受害 VA 的定义与目标值

canary（`vsurv5`，D1 同款：altstack + 固定头 + 8 页栈 dump，路径
`/data/repro/h5_<pid>_<hit>.bin`）每次 SIGSEGV 记录 fault-time 寄存器。
每次崩溃取 **x2**（记录/va_list 所在栈地址，即「被写坏的目标槽」）与
**fault VA**（`si_addr` / `fault_address`，即记录 word0 被 va_arg 解引用后的
故障地址）两个 VA。

每次崩溃的扫描目标（**逐值独立**，共 4 个主值）：

| 值 | 形式 | 宽度 |
|---|---|---|
| T1 | `x2 & 0xffffffff` | 32 位 LE（4B 粒度） |
| T2 | `x2` 原值 | 64 位 LE（8B 粒度） |
| T3 | `faultVA & 0xffffffff` | 32 位 LE |
| T4 | `faultVA` 原值 | 64 位 LE |

辅助（exploratory，不参与主判据）：若能在 RAM 中定位到本次记录本体
（`word2 = {len, ip}` 的 8B 唯一值）→ 得到受害栈页 PA；再以该 PA 的
4B/8B 形式各扫一遍，检查是否有结构持有**正确的** DMA 地址（对照 D2 的
「正确 PA 编程」分支）。辅助结果单独报告，不与 H_trunc 混算。

## 4. 仪器

- **canary**：`vsurv5`（`tools/oneoff/sigsegv/vsurv5`，md5 设备侧核对），
  与 D1 完全同款；崩溃预算 ≤3 次或 ≤10 min，先到者为准。
- **pascan v2**（新写 oneoff，`tools/oneoff/sigsegv/pascan2.c`）：
  - `pascan2 <start> <end> <value_hex> <width:4|8>`
  - 按页 `pread(/dev/mem)`；4B 模式按 4 字节步进，8B 模式按 8 字节步进；
  - 每个命中打印 `HIT pa page off w4 w8 ctx16`（ctx16 = 命中点前 8B + 后 8B
    的 16 字节 hex，用于离线判读「真 32 位字段 vs 64 位指针低半」）；
  - 统计并打印 `pages_read / pages_unreadable`（**可读性门禁**：不可读页的
    「0 命中」无效，A3 教训）；
  - **自污染标记**：若命中页内容含本工具名 `pascan2` 的 ASCII 或目标值
    十六进制 ASCII 串，打印 `SELF` 标记（扫描器自身栈/堆页）；
  - 命中打印上限 512/值（计数不截断，`hits_total` 全量）。
- **正对照（三条，缺一该值判据降级）**：
  1. **自建标记**：设备侧启动 `marker`（4KB 页内写 4 个 8B 魔数：
     `0xD25A5A5A5A5A5A5A`、`0x00000000D25B5B5B`、`0x123456789ABCDEF0`、
     `0x00000000DEADBEEF`，然后 pause 常驻），pascan 必须分别命中；
  2. **噪声底**：同宽度随机值各 1 个（32 位随机值取同 DRAM 带内随机数，
     64 位随机值取随机 64 位数）同法扫描，命中数即噪声底；
  3. **记录本体**：若 RAM 中定位到本次记录（`{len,ip}` 8B 唯一值），该命中
     即「受害者栈页」正对照。
- **归属判读**：命中 PA → ①`/proc/iomem` 段名（含 reserved 子区名）；
  ②线性映射换算 `VA = 0xffffffc000000000 + PA` → `/proc/kallsyms` 最近符号
  （同 boot 快照，先拉回 PC 离线符号化）；③若 PA 落在模块 vmalloc 页则标记
  `MODULE-UNCERTAIN`（需页表遍历，本轮不做）。

## 5. 窗与有效性门禁（任一不满足 ⇒ 该次崩溃的判据 INVALID）

1. canary 进程存活、`h5_*` dump 计数增量 = 崩溃次数；
2. 每次崩溃 dump 头可解析：magic `H4v1`、`npages=8`、`x2`/`fault_address`
   非零（x2 必须落在用户栈区间 `[start_stack-8P, start_stack)`，否则记为
   「非规范记录」不进入目标值）；
3. pascan2 可读性：`pages_read / (pages_read+pages_unreadable) ≥ 0.9`；
4. 三条正对照：自建标记 4/4 命中、噪声底已测、记录本体（若可定位）；
5. `boot_id` 窗内不变、无 kernel oops/panic；
6. 收窗：canary kill、0 个我方模块、`TRY_A` 低字节 = 0。

## 6. 判据（预写死，不改）

- **H_trunc 成立**：对某次崩溃的 T1/T2（x2 系）出现**非自污染、非噪声底、
  且归属到具体结构**的命中——命中 PA 落在 `/proc/iomem` 的具名 reserved
  区（如 WiFi/WED/CCCI 保留带）**或**线性映射换算后的最近 kallsyms 符号
  距离 ≤ 64 KB 且该符号属于 DMA/网络/驱动数据结构。此时把**地址、归属
  符号/区段、与受害 VA 的关系**写死点名。
- **H_absent（有条件）**：T1–T4 全部 0 命中（或全部为自污染/噪声底/受害者
  自身栈页），**且** §5 门禁全过 ⇒ 在「静态 RAM 可读区」范围内，截断地址
  不由 RAM 结构持有（E2）；残余 = 硬件内部持有/寄存器/FIFO/不可读 reserved
  带（后者按 A3 教训记为 BLOCKED，不得写成阴性）。
- **判读分层**：T1/T3 的 4B 命中若其所在 8B 字的另一半是 `0xffffffc0`/
  `0x0000007f` 等指针高半，判「64 位指针低半」噪声；只有另一半为 0 或
  合理 32 位字段时才计入「真 32 位字段」候选。
- 4B 噪声底若本身 ≥ 命中数，则该值无区分度（记录为「无区分度」而非阴性）。

## 11. 判决

**H_trunc 不成立（E2，静态可读 RAM 范围）：** 对 2 个新受害槽与 3 个历史崩溃，
`x2 & 0xffffffff` 的全部非自身命中都是 **64 位指针的低半**（`v8=0x0000007f…`），
位于受害者自身栈页/栈副本；**没有任何独立 32 位字段**（另一半为 0 或描述符字段）
持有截断 VA。`x2` 原值同样只出现在栈帧中。⇒「某 DMA 队列/描述符持有
`(受害VA & 0xffffffff)`」在本轮可读静态 RAM 内**未被证实**；截断地址形态的
描述符未被点名。

**但出现了一个预注册未列出的强命中（E2）：受害页 PA 被页地址数组持有。**
`0xb08c6000` 作为 32 位字段稳定存在于 `0x84d40c64`（stride-0x10、status=0x10000021）
与 `0x84d708d0`（stride-0x20、size=0x1000 + vmemmap 指针）；第二受害页
`0xb0418000` 出现在保留带 `0x83e89578`。这与「正确 DMA 地址编程」分支一致：
写侧结构持有的是**受害页的物理地址**（而不是截断 VA），受害页本身是**用户栈页**。
最简机制：**页池/环中的页被回收为用户栈后，DMA 仍按池中 PA 写入**（stale pool
entry / page recycling），而不是地址截断。记录本体在 32 个页中出现（普遍写入），
与「同一 32B 记录被写入池中多个页」一致。

**必须同读的边界：**
1. 数组的 owner（驱动/引擎）**未点名**：无 kallsyms 符号、无持有者指针命中；
   `0x84d40000`/`0x84d70000` 为动态页，`0x83e89578` 为无名保留带。
2. `pages_unreadable=27130`（5.2%），其中含保留带；这些区的「0 命中」无效
   （A3 教训），不得写成阴性。
3. 第二受害槽（29491）fault=0、x2 记录全零，属非典型事件；只用于页 PA 观测，
   不计入记录族判据。
4. 4B 噪声底 3/3、8B 3/3 均为扫描器自身；非自身噪声底 0/0。
5. 页池数组的 490/137 个 entry 中未出现记录本体所在页（32 个记录页 PA 不在
   已 dump 的 8 KB 窗口内）——数组可能更大或记录页来自另一池，下一轮需扩大
   dump 窗口并做 entry 全量比对。

**下一轮（建议）：** ①扩大 `0x84d40000`/`0x84d70000` 数组 dump（>64 KB）并与
32 个记录页 PA 全量比对；②用页表遍历把数组 VA 归属到 vmalloc/module（或
`/proc/slabinfo` 类通道）以点名驱动；③对保留带 `0x83e8xxxx` 结构做同样的
entry 解析与 owner 反查；④在 page_pool 释放路径（`page_pool_return_page`/
`__page_pool_put_page`）设只读钩子，验证「用户栈页仍在池中」的 refcount 语义。
