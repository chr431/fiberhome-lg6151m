# 09 · D26 预注册 · 页池数组解剖与 owner 点名（2026-11-03 A1）

> **预注册文档：实验开窗之前写定并 commit。实验后只追加 §9 起的结果节，不改 §1–8。**
> 编号 09 顺延（01..08 已占用）。中性命名：不含目标网络名与个人凭证。
> 输入：D4（C-209）在 `0x84d40c64`（stride-0x10 `{status,pa}`）与
> `0x84d708d0`（stride-0x20 `{pa,0x1000,vmemmap,flags}`）发现受害页 PA
> `0xb08c6000`；第二受害页 `0xb0418000` 在保留带 `0x83e89578`。

## 1. 问题

D4 把写侧从「截断 VA 描述符」（H_trunc，已否证）转向「**正确的页 PA + 页池/环
登记**」。但 D4 只看了两个 8 KB 窗口、没有时间序列、没有 owner。本轮回答三个
问题：

1. 这两个数组**是什么**？（格式、条目数上限、status 语义、PA 分布、邻接结构、
   边界/头部字段）
2. 受害页 PA 在数组里的条目**是常驻还是新进**？崩溃**后**是否被消费/清除？
   （直接区分「陈旧登记」与「活跃使用」）
3. 数组的 **owner 是谁**？（内核里谁持有指向数组页的指针；能否符号化到驱动/引擎）

## 2. 假设（先写死）

- **H_stale**（陈旧登记）：数组是某 DMA 页池/环的登记表。受害页 PA 的条目在
  **该页被分配给 canary 栈之前**就已存在，并在崩溃后**继续常驻**（不被消费）。
  ⇒ 页被池回收复用为用户栈后，DMA 仍按池中 PA 写入。
- **H_live**（活跃使用）：受害页 PA 条目在**崩溃前 ≤1 个采样周期内新进**，或
  崩溃后**被消费/清除**（状态翻转/条目归零）。⇒ 页同时是活跃 DMA buffer 与
  用户栈（更严重的 double-use）。
- **H_coinc**（分配巧合）：数组只是**空闲页链表/分配器元数据**，受害页条目在
  页被交出（分配）时即被移除；即崩溃前最后一次采样里条目应已消失。
- **H_owner**：存在可点名的 owner（内核指针/符号/模块），能把数组归属到具体
  驱动或引擎。

## 3. 对象与测量

### 3.1 数组对象

| ID | 页 PA | D4 观测格式 |
|---|---|---|
| A1 | `0x84d40000` | stride 0x10，entry `{u32 status, u32 page_pa, u64 0}`，8 KB 内 490 个页地址 |
| A2 | `0x84d70000` | stride 0x20，entry `{u64 page_pa, u64 0x1000, u64 vmemmap, u64 flags}`，8 KB 内 137 个 |
| R1 | `0x83e80000` 带内 `0x83e89578` | 保留带 `0x82000000-0x8470ffff`，u32 页地址/长度交错流 |

### 3.2 全量解剖（静态，canary 前）

1. 每个数组 dump **64 KB**（16 页，覆盖数组真实边界与前后邻接），另加**前后
   各 2 KB**（与 64 KB 合并即前后各 2 KB 在窗口内）。
2. 解码：按 stride 切 entry；统计 status 值分布（全 32 位值）、PA 字段分布
   （落在 System RAM / reserved 带 / 非页对齐 / 0 / 重复）、非零 entry 计数、
   数组起止边界（首个/末个非零 entry 的偏移）。
3. 邻接结构：检查数组页前后是否出现 magic、计数、锁、指针字段（任何 8B 值
   落在 vmalloc/线性映射区且非页 PA 的候选）。
4. **与 D4 的 32 个记录页 PA 全量比对**（`scan_logs_raw.txt` 中
   `0x0109a8c000000641` 的非自身命中页），以及两个受害页 PA。

### 3.3 时间序列（canary 窗）

- canary：`vsurv5`（D4 同款，md5 设备侧核对），后台运行。
- 采样：**每 30 s** dump A1/A2 的 8 KB 窗口（与 D4 同格式，保证可比）+
  `/proc/uptime` + `h5_*` 文件清单。每份 dump 落到设备
  `/data/repro/d26/arr_<seq>_<ts>.txt`，窗后一次性拉回 PC。
- 崩溃：轮询 `h5_<pid>_<hit>.bin` 新增；每次崩溃立即（≤10 s）：
  ①解析 dump 头（x2/sp/fault）；②`patrace` 把 x2/sp 翻成 PA；③立即 dump
  A1/A2；④记录 canary pid 的启动时刻（栈页分配时刻）。
- 分析：
  - **进入时机**：受害页 PA 首次出现在数组采样序列的时刻 vs 崩溃时刻
    （用 canary 进程启动时刻作「页成为栈」的上界）。
  - **消费**：崩溃后 ≥2 个采样周期（60 s）内条目是否变化/归零/状态翻转。
  - 每个采样把 A1/A2 全部 entry 的 PA 集合与 canary 栈页 PA 集合求交。

### 3.4 Owner 点名（三重）

1. **指针扫描**（`rangescan`，新 oneoff）：全 DRAM 扫 8B 值落在
   `[A_page, A_page+0x2000)`（A1/A2 各一次）；另扫
   `vmemmap struct-page` 指针（`0xfffffffe00000000 + (pa>>12)*0x40`）与
   数组 PA 的 4B/8B 形式。self 标记同 pascan2 规则。
2. **邻域判读**：若找到持有者指针 → 取其所在页 dump 2 KB，按 8B 值分类
   （vmalloc/module 范围、函数指针候选、常见结构字段模式），再用同 boot
   kallsyms 快照符号化（离线）。
3. **静态签名交换**：把本轮 dump 的精确格式（status 值集合/字段宽度/条目数
   上限/stride/边界偏移）写入 §9 结果节，供 A2 的「stride-0x10 {status,pa}
   数组写入循环」指令签名离线比对。

## 5. 窗与有效性门禁（任一不满足 ⇒ 对应判据 INVALID）

1. `boot_id` 窗内不变；无 kernel oops/panic；
2. 每个采样都有 `/proc/uptime` 与完整 8 KB dump（缺一记 gap，不插值）；
3. 至少 **2 次可用 canary 崩溃**（x2 落在用户栈区间、dump 头可解析）才判
   时间序列判据；否则只出静态解剖 + 判决降级为「不可判」；
4. 正对照：数组稳定 entry 在序列中可复现 + marker 4/4；
5. 每次崩溃后立即读 `TRY_A`（misc p1 offset 2060，期望 `0f 00 01 00 …`）；
6. 收窗：canary kill、0 个我方模块、`patrace` rmmod、`TRY_A` 低字节 = 0。

## 6. 判据（预写死，不改）

- **H_stale 成立**：对 ≥2 次崩溃，受害页 PA 在**该 canary 启动后的第一个采样**
  即已在数组中，且崩溃后 ≥2 个采样保持（值/状态不变）⇒ 陈旧登记。
- **H_live 成立**：受害页 PA 在崩溃前 ≤1 个采样周期才出现，**或**崩溃后 ≤60 s
  内条目被清除/状态翻转 ⇒ 活跃使用。
- **H_coinc 成立**：受害页 PA 在崩溃前最后一次采样已不在数组中（或数组条目
  在分配时被移除的明确证据）⇒ 数组只是分配器空闲链表。
- **H_owner 成立**：找到 ≥1 个非自身、非受害者栈页的持有者指针，且能归属到
  具体符号/模块/结构；否则记「owner 未点名」并给出残余盲区（不可读区、
  硬件内部）。
- 判读分层：数组内 PA 若为**非页对齐**或落在 reserved 带，单独计数，不与
  System RAM 页 entry 混算。

## 10. 结果

### 10.1 全量解剖（E2）

**arr1 = 8 个 512 项硬件描述符环**，每环 0x2000 B，基址 `0x84d40000 + 0x2000*k`（k=0..7）：

| 字段 | 值 |
|---|---|
| entry | `{u32 status, u32 pa, u32 0, u32 0}`，stride 0x10 |
| status | `0x10000021` 3118、`0x10000023` 197、`0x20000021` 76、`0x40000021` 6、`0x30000021` 2、`0x40000023` 2、其它极少数（0x70000021/0x50000023/0x80000023 各 1） |
| 语义 | status = `(token<<28) \| 0x21/0x23`；token 1 占 97%，2/3/4/5/7/8 共 ~2.6%；bit1（0x23）占 ~6%，位置无固定周期（间隔 1..23），符合**硬件回写标志位**（DD/EOP 类），非软件固定模式 |
| pa | 全部页对齐、全部落在 System RAM（**0 条**在 reserved 带），0x80d5f000–0xbfccf000；8KB 窗口内 2261 唯一 PA / 3408 条（重复最多 34 次） |
| 空槽 | 环尾有 22/26/63/70/82/86/54/17/64/67 等连续空槽（环未满或已消费） |

**arr2 = 8 个 `struct scatterlist[256]`（kmalloc-8k 对象，8KB 对齐）**，基址
`0x84d70000 + 0x2000*k`：

| 字段 | 值 |
|---|---|
| entry | `{u64 page_link, u32 offset=0, u32 length=0x1000, u64 dma_address, u32 dma_length=0x1000, u32 pad=0}`，stride 0x20 |
| page_link | `page_link & ~3 = VMEMMAP_BASE + (dma_address>>12)*64`，**VMEMMAP_BASE 实测 = `0xfffffffdfe000000`**（1389/1389 条一致；**不是** 0xfffffffe00000000） |
| flags | bit1 = SG_END（8KB 窗口内 105 条）；D4 命中的对象 nents=137（idx 137 为 SG_END） |
| dma_address | 页对齐 System RAM PA，与 arr1 的 pa 同一页池 |

**两表配对（A2 的 a2[i]↔a1[i+128]）**：在**活跃窗口内成立**。以崩溃时刻 dump 为例，
`a1[i+128].pa == a2[i].dma_address` 只在 i=0,1 与 **i=48..93**（连续 46 项）成立 ——
这正好是 DMA 引擎当前在飞的窗口；窗口外两表不同步（sg 项为 0 或旧值）。因此
“固定全表映射”不成立，“**活跃窗口映射**”成立（E2）。

**邻接/边界**：两族结构均按 8KB 对象/环对齐分配；数组页之间无 magic/计数头
（`0x84d38000–0x84d8f000` 内所有 0x20/0x10 结构都直接以 entry 开头）；未见
`struct sg_table{sgl,nents}` 落在 dump 窗口内（sgl 指针只在窗口外被搜到，见 10.4）。

### 10.5 两处基址修正（对全项目有影响）

1. **VMEMMAP_BASE = `0xfffffffdfe000000`**（实测 1389/1389 条 scatterlist 一致）。
   D1 预注册/报告用的 `VMEMMAP_START = 0xfffffffe00000000` 偏高 0x2000000；D1 的
   “伪页 < VMEMMAP_START”判据不受影响（伪页恒 < 2^33），但引用该常量处应更正。
2. **线性映射基址 = `0xffffff8000000000`**（不是 `0xffffffc000000000`；后者是
   module/vmalloc 区，modules 实测在 `0xffffffc0009xxxxx`）。证据：FE 结构字段
   `0xffffff8001736880` = PA 0x1736880 的线性别名；内核 image VA 走
   `_stext 0xffffffc008110000 ↔ PA 0xfd910000`（iomem “Kernel code”）。
   ⇒ **D4 与 D26 早期按 `PA+0xffffffc000000000` 做的 owner 反查全部搜错区间**；
   这解释了 D4「无持有者指针」的阴性。

### 10.6 崩溃风暴与“自持崩溃环”（方法学发现）

13 个 canary 在 12:25–14:10 产生 **582 个 h5 dump**（单 canary 最高 57 次）。同一
canary 的 x2 固定、fault 恒 < 0x100000：**一次外部写坏 va_list 槽后，handler 的
siglongjmp 回到同一循环，槽仍是坏值 ⇒ 每次循环再崩一次**，形成自持崩溃环。
⇒ **h5 计数 ≠ 写入次数**；C-204 的 13.9–20.3/min “热态”若含同种环，需重新按
“每 canary 首次崩溃”口径复核（本轮 13 canary / 45 min 内首崩 13 次 ≈ 0.29 首崩/
canary/min，与 D4 的 0.2 同量级）。

## 11. 判决（按预注册 §6）

1. **H_stale：对当前 13 个受害页不成立（E2 阴性）**。受害页 PA **0/13** 出现在
   arr1/arr2（崩溃时刻 +2s、30 s 采样、1.7 ms 高频 watch、收窗 final，全部 0）。
   数组确实含**陈旧登记**（D4 受害页驻留 ≥68 min，其 canary 早死），但那些条目
   不是当前被写的页。
2. **H_live：不成立（E2 阴性）**。没有任何受害页在崩溃前后进入/离开数组。
3. **H_coinc：与数据一致（E2）**。数组是 8 队列的 DMA 描述符环 + scatterlist 表，
   条目反映“已投递的 DMA buffer”，按慢速环头旋转（~2 项/min）；受害页不在其中。
   ⇒ **这两族数组不是当前崩溃集的写入者**。
4. **H_owner：不成立（E2 阴性）**。无稳定持有者指针、无符号、无 sg_table 命中。
   唯一非自身线索（0xb47e3fc8 的 bio_vec 形态页数组）是瞬态，不能点名。
5. **残余上位方向**：写侧仍未被点名。与全部阴性兼容的候选是 A2 的
   **per-CPU page_frag / 缓存 struct page**（持有 page* 而非 PA，写入经线性别名
   普通 store，天然逃过 uaccess/dma_map/sttr 普查）；本轮 vmemmap 精确搜对该假设
   只给出 0 稳定命中（但 page_frag 是 per-CPU 且随分配快速更新，单点扫描灵敏度低）。

**必须同读的边界**：
1. 30 s 采样在 12:37 后被崩溃风暴挤占（12 个采样后出现 gap），时间序列判据以
   **崩溃时刻 dump（44 个）+ 1.7 ms watch** 为主。
2. `pages_unreadable=27130`（5.2%，含保留带）：这些区的 0 命中无效。
3. vmemmap 搜索只做了 3 个受害页（其余 10 页未扫）。
4. 数组的“静态条目”在 1.7 h 尺度会变（环头推进），所以“D4 受害页驻留 ≥68 min”
   是下限而非永久。
5. 环/sg 的 8 队列归属（哪个驱动/引擎）未点名；A2 已排除“FE RX 环”（字段序相反）。
