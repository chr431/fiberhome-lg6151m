## 2. W1 数据表（boot#1，全部 inj=0、START 后）

| 臂 | 形态（在 nat 基础上加） | v 事件/300s | c 事件/300s | RR | 判 |
|---|---|---|---|---|---|
| natfp | 4×`stp q`（32B，对齐保存区） | 309 | 248 | **1.245** | 复验成立 |
| nat2q | 仅 2×`stp q`（64B 突发） | 485 | 466 | **1.041** | 2 对即满 |
| nat8s | 8×`str q`（16B，同址同值） | 117 | 214 | **0.547** | 宽度减半仍可见 |
| qoff | 4×`stp q` 基址−16B | 487 | 485 | **1.004** | 对齐无关 |

功效门（对照 ≥20）超 12–24×；所有臂 iters≈29.5k/300s（同率）。

**合并判读**（含 U-H 的 nat/split/strb=0 与本轮 W2）：

1. 签名的必要成分 = **FP 源寄存器（q 系）store 突发**——nat 系（X 源 16B/8B）零命中；
   q 源必可见。
2. 结构 = **连续保存区写入**：≥2 邻接 32B 满可见（nat2q）；16B 同内容减半（nat8s 0.55）；
   对齐无关（qoff 1.00）。
3. **孤立/散布 FP store 不足以触发**（本轮最有价值的边界）：真实 musl 路径中 vsnprintf 的
   单次 32B va_list 物化 + vfprintf 入口两对散布 spill（相距 0x30）在 stealth2 上**零触发**
   ——尽管 nat2q 证明"2 邻接 32B"在合成流中已满可见。⇒ 写者识别的是**保存区模式**
   （邻接、密集、反复），不是"出现 32B/q 源事务"本身。
4. 该边界同时解释了 W1 合成臂与 W2 真实二进制行为的一致性。

## 3. W2 数据表（boot#2 崩溃后，600s 三方同窗）

| 臂 | 每调用热路径 FP-store 台账 | 事件/600s | RR | SELFCRASH |
|---|---|---|---|---|
| ctl（stock 重建） | 7（4×prologue stp q + 1×vsnprintf 物化 + ≤2 core spill） | **68** | 1.0 | 0 |
| stealth1（str-q shim） | 11（8×str q + 同上 ≤3） | **59** | **0.868** | 0 |
| **stealth2（no-FP-save shim）** | ≤3（仅 libc 内部残余） | **0** | **0** | 0 |

- 零结果功效：对照 68 事件 ⇒ P(0)=e^-68≈1e-30；截断首窗（w2p，3 分钟）方向一致
  （ctl 8 / st1 9 / st2 0）。
- stealth1 ≈ 原生可见度：其台账（11）≥ stock（7），实测 0.87——排序与台账一致，证明
  **可见度由 FP-store 台账定量决定**，也反证 stealth2 的零不是"shim 环境 artifake"。
- **此消彼长**：窗内 NE 台账零新增（写者注意力未见向系统其它进程转移的激增）；弱阴性
  （λ 已塌，功效有限）。
- stealth2 的 ABI 合规性：q0–q7 不保存 + vr_offs=0，仅当**调用方从不传 FP 变参**时自洽
  ——自研 C 二进制（无 %f/%g）满足；对外暴露的 variadic API 不可用此形态。

## 5. 崩溃台账 #24（自伤，E0）

- 现象：12:55 W3 首次读相命令中 socket 断、设备复位；pconsole-ramoops（262KB，md5
  9798d7ff…）全量在档。
- 栈：`dw_write+0x1a0 [dpwr] → el1h_64_sync → do_mem_abort → do_alignment_fault →
  die_kernel_fault → ipanic_die`。**根因**：shell 循环 `seq 0 4 0x7fc` 输出**十进制**
  步进值，被 dpwr 的 `sscanf("%lx")` 按十六进制解析 → readl 落在 0x12 等非对齐偏移 →
  Device 属性对齐故障（与 U-G9 #22 同族，再现于 kmod 路径）。
- 处置：自动恢复（panic→复位），启动门过（163 模块、pstore 完好、无 boot loop、单次）。
  W2 重跑 + W3 安全化（awk printf "%x" 生成偏移）。
- 教训（AGENTS 候选行）：**busybox `seq` 的十六进制端点不产生十六进制步进值**；任何
  MMIO 批量读循环的偏移生成必须显式十六进制化并对 4/8 对齐断言。
