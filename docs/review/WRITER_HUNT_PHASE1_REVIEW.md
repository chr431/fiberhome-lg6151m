## 2. 装置风险（Lead 第 2 问，源码级）

### 2.1「RO 期间受害者不写该页」—— **成立（结构上）**
- 窗内只有 `mprotect(RO)`(:315) → `nanosleep(&ts,0)`(:324-325) → `mprotect(RW)`(:328)；
- 比较缓冲是 **static**（:282），不在栈页；
- **snprintf 目标在堆**（:586-589 `bp = (cfg_ro>=0 && g_vbuf) ? g_vbuf : b`）；
- **`nanosleep(&ts,0)` 第二参为 0** ⇒ 内核不回写 timespec（若回写就是内核态写用户栈，会把 RO 页踩出假阳性）；
- **va_list 在窗内不被消费**（`vsnprintf` 在 `ro_window` 返回后，:350-354）⇒ 「活 va_list 存在但本进程不写」正是实验要的状态；
- **自我写检测**：窗内本进程 store 打到 RO 页 → `RO_FAULT`（:476-481）记录 addr/pc/sp。

**残余风险（非阻断）**：`helper_same_page` 只查 `&page` 一个地址（:285、:291）——若 `ro_window` 栈帧**跨页**，其余局部仍可能落在被 RO 的页上（漏检）。建议改区间检查 `[&page-256,&page+256]`，或把该函数局部下沉为 static。

### 2.2 CPU-uaccess 情形：**只能给「未判定（≤E1）」，不能给「倾向 CPU（E3 上限）」**
1. RO 页上 `copy_to_user`/`process_vm_writev` 走 **-EFAULT 静默失败**（无信号、无日志；本内核无 PERF_EVENTS、无 fxhook）⇒ 页上「无变化」与「写者没写这页」**观测同形**；
2. RW 对照臂是**另一个时间窗**（且串行）⇒ 给不出同窗暴露；
3. 唯一能点名 CPU 写的是**权限 fault 的 PC/LR**（需 fxhook/T-09），本设计没有。
⇒ 分支 C 应写成：`RO 臂无变化 + RW 臂有变化 = 不支持非 CPU，且 CPU 未被证实；E1 上限，CPU/非 CPU 未判定`。写成「倾向 CPU（E3）」会在下一次引用里变成「CPU 写（E2）」——C-182/C-187 的老坑。

## 4. U-C（ptrace=117 覆盖）设计结论：**不值得单独立项**

1. **通道被结构性关闭**：nerepair 是全进程独占 tracer（实测覆盖 59/59 用户进程、TracerPid 唯一值 = nerepair pid）⇒ 第三方 `PTRACE_ATTACH/POKEDATA/SETREGSET` 一律 EBUSY。⇒ 在役期「用户态 ptrace 型跨进程写」不是未检验，而是不可能发生；audit 排除 117 号的代价当前 = 0。
2. **真正未覆盖的是 `/proc/<pid>/mem` 写**：不经 ptrace、不经 `__arch_copy_to_user`（走 `mem_write`→`access_remote_vm`）⇒ C-206/C-214 的漏斗看不到，audit 也无法用路径 watch 稳定命中 procfs。
3. **正对照做不出来**：补 117 号的正对照必须是我们自己的 ptrace 写者，而它在 nerepair 在役时 attach 不上；不装 nerepair 时的阴性又无法外推 ⇒ 两头都不通。

**替代**：① 零成本——把 `WRITER_HUNT_GAP_AUDIT.md` 的 U-C 行改为「结构性关闭（nerepair 独占 tracer），非未检验」并从 Top-3 必覆盖降级（符合 C-169）；② ≤0.2 人日——`/proc/<pid>/mem` 能力自检：自建 helper 向受害进程写 magic，看现有观测是否有一条能看见（看不见 ⇒ 缺口从猜测变实测 E3，且不需模块、不需停 nerepair）；③ 1–2 人日（仅当 ② 确认不可见）——`mem_rw/access_remote_vm` 入口钩子，与 T-09 fxhook 合并一次上机。

## 5. 结尾三栏

### [A] 已核实（本地源码/文档，零设备）
1. scanary_ro 七项实现到位：RO 目标=page(&ap)（:283-284/:315）、**先 RW 再 dump**（:327-338）、比较缓冲 static（:282）、snprintf 目标在堆（:586-589）、`nanosleep(&ts,0)` 不回写（:324-325）、`RO_FAULT`（:476-481）、`vap_drift`（:297-303）、`CTRL_INVALID reason=no_change`（:367-368）。
2. `vcall()` 是 printf 类消费点（:350-354）⇒ 受害者形态与历史家族命中一致（uaprobe_victim 缺这一点）。
3. runbook 命令行与二进制不匹配（:1101-1103 vs 预注册 §3）⇒ MF-1 阻断。
4. CPU-uaccess 分支只能到「未判定（≤E1）」。
5. uaprobe_victim（交叉件）：CLI 静默忽略未知参数、无 printf 消费点、RO 正对照从未真写 ⇒ 作主件不合格，作交叉件需先修三处。
6. U-C：117 号通道结构性关闭；真正缺口是 `/proc/<pid>/mem`（不经 uaccess 漏斗）。

### [B] 未核实
1. 未知 CLI 参数在 scanary_ro 是「报错退出」还是「静默忽略」——需现场一条 `--ro-arm` 试探（MF-1 前置）；
2. RO 窗内是否有库内写该页（静态审查只覆盖自身代码；libc syscall wrapper 理论无栈写）；
3. 页迁移风险（仍无 patrace gate）。

### [C] 必须上设备才能确认
1. **RW 臂能否观测到 ≥1 次该页变化（暴露前提）—— 开窗第一个判据，不是实验结果**；
2. RO 臂 `RO_ON/RO_OFF` 成对、`RO_FAULT=0`、`vap_drift=0`（仪器自证）；
3. **分支 N（RO 下 32 B 仍变化）⇒ 非 CPU 写（E4）—— 唯一值得开窗的结果**。

> 一句话：**装置合格、可开窗；先把 runbook 命令行改成 `--ro=1 --ro-sec 540`（MF-1），并把「倾向 CPU（E3）」改成「未判定（≤E1）」（MF-2）。**

### 6.1 MF-1 状态：**执行侧已规避，文档待改**
Lead 实跑用的是真实 CLI（`--victim main --ro 0 --ro-sec 600 …`）⇒ 「整晚白跑」不会发生；runbook 文本由 v5-analyst 改。⇒ **MF-1 降级为文档一致性问题**（不再是阻断）。

### 6.2 `helper_same_page` 实测触发 —— 守卫按设计工作（**这条要写进报告**）
实测日志：`RO_INVALID reason=helper_same_page vap=0x7fe1650be8 page=0x7fe1650000 helper=0x7fe1650c08`
⇒ `helper` 与 `vap` **同页**（0x7fe1650xxx）⇒ 守卫拒绝 RO，**这是正确行为**（否则 helper 自己的栈就把 RO 页踩了，测到的是仪器）。判级：**E3（仪器自保护生效）**，不属缺陷。

### 6.3 「RO 段搬到独立 mmap 栈的 pthread + 守卫改 sp∩page」—— **不足以保证 RO 臂成立**，还缺 3 件

**缺 1（关键）：受害者线程必须在整个 RO 窗内被「停放」**
- 现在 `ro_window(&ap)` 是在**受害者自己线程**上被 `vcall()` 调用的；一旦 RO 段搬到 pthread，`ro_window` 会**返回**到 `vcall` → 受害者继续 `vsnprintf`/继续压栈 ⇒ **在 RO 页上继续写** ⇒ 触发 `RO_FAULT` 或直接崩。
- ⇒ 必须让受害者线程在发布 `&ap` 后**切到独立栈阻塞**（uaprobe_victim 的 `swapcontext` 到 alt stack + `nanosleep` 循环正是这个形态），并把「停放」写进判据；否则「受害者不写该页」不成立。

**缺 2：守卫要检「活栈区间」，只检 SP 不够；且 `sigaltstack` 是逐线程的**
- `sp` 落在 `[page,page+4096)` **之外**并不安全：栈向下长，`[sp, sp+frame_extent)` 可能跨进被守护页（帧上沿在页内）。⇒ 应检 **两个线程的活栈区间与 page 是否相交**（RO 线程的 mmap 栈 + 停放后受害者线程的 SP），而不是单点 SP。
- `sigaltstack()` 是**每线程**属性：搬到 pthread 后，RO 线程与受害者线程**都要各自 `sigaltstack`**，否则 `SA_ONSTACK` 在没设置的那个线程上回落到**当前栈**（若正好是停放栈就没事，若是目标页就炸）。

**缺 3（判据级）：实测 poff 有两个值 ⇒ 预注册的「差异落在 &ap±64B」会漏**
- 实测：单帧深后 15/15 全落 `page=0x7fe1650000`，但 **poff 有两种：0xdb0 与 0xb10**（相差 **0x2a0**）。
- 预注册分支 N① 写「整页 digest 变化且差异落在 **&ap±64B**」——若写者这次落在另一个 poff（0x2a0 外），**该判据会把真实记录判成噪声/漏掉**。
- ⇒ 判据必须改为 **页级 changed-byte map**（报出页内所有变更偏移），再用**家族形状过滤**（`{len∈[0x400,0x20000], ip 四段 1..254, 两侧零字}`）确认是记录；**「&ap±64B」只能作辅助**，不能作唯一窗口。

### 6.4 `--depth-list 0` 必须写死进预注册（多档 = 多页）
- 实测：默认 5 档每 60 s 换档 ⇒ 第一轮 **17 次命中跨 3 页**；固定单帧深后 **15/15 同页**。
- ⇒ ① 预注册必须把 `--depth-list 0`（或等价单深度）写成**硬前提**（Lead 已确认为**两臂**硬前提）；② 多档窗一律判 INVALID（这就是 `vap_drift` 的现场版）；③ 这条实测只证**层 1**（定位层），**不证层 2**（机制层）——见 §6.7。

### 6.5 MF-2 / MF-3
Lead 已转 v5-analyst 改文档；我按新口径（分支 C = **未判定（≤E1）**；RW 臂 = RW→RO→RW + 计数/期望 + 0 变化判 INVALID 且写补救路径）复核落盘后的版本。**在这两条落盘前，RO 臂仍可跑**（不影响仪器），但**结论只能写「非 CPU 写（E4）」或「未判定」**，不得写「倾向 CPU」。

### 6.7 两层判决：定位层 vs 机制层（Lead 口径确认，必须分开写）

> 我此前把「15/15 同页」写成「正面支持 RO 目标 = page(&ap)」——**这句话只对层 1 成立**。Lead 指出必须分层，这里写死：

| 层 | 命题 | 由什么证据判 | 现有证据（截至本文） |
|---|---|---|---|
| **层 1 · 定位层** | 「RO 臂保护的页 == 写者实际命中所在的页」（即 RO 目标选择正确） | 同帧深下的命中页一致性 | **E3 已成立**：`--depth-list 0` 后 **15/15 全落 `page=0x7fe1650000`**（poff 0xdb0/0xb10）；反面对照：多档时 **17 次跨 3 页** ⇒ 多档窗不可用 |
| **层 2 · 机制层** | 「写者**绕过 MMU**（非 CPU 写）」 | 受保护页在 RO 窗内**仍被写入**（且 `RO_FAULT=0`、`vap_drift=0`、`RO_ON/RO_OFF` 成对） | **尚无证据**：必须由 RO 臂产出。层 1 成立**不推出**层 2——两者是不同命题（层 1 只说明"打对了页"，不说明"这一写不是 CPU 做的"） |

**推论（写报告的纪律）**：
- 层 1 可作为 **U-A 设计依据**（E3）引用；**不得**当作「非 CPU 写」的任何证据；
- 层 2 只有两种结论：**① RO 臂出现页级变更且形状过滤通过 ⇒ 非 CPU 写（E4）**；**② RO 臂无变更 ⇒ 「未判定（≤E1）」，不写「倾向 CPU」**（MF-2）；
- 两层必须**分节写、各自给等级**，禁止合并成一句「RO 验证了 DMA 写」。

### 6.8 已确认的口径与门禁（Lead 2026-11-03 深夜确认）
1. **缺 3 判据**：页级 diff + 家族形状过滤为**主**，`&ap±64B` **仅辅助** ✓（与我 §6.3 缺 3 一致）；

> **改判依据（perf-reviewer 决定性对照，post-hoc）**：RW **停放臂**（同 victim/同 D=0x1000、页可写、只停放 600 s）停放期间**自然命中 0 条**；`RO_END`(600.03 s) 后 3.9 s 起、29 s 内 **5 条**（同页 ≈10.2/min，与 clean RO 臂窗后 ≈18/min 同量级）。若写者与受害状态无关，600 s 停放期望 ≈100 ⇒ 实测 0 ⇒ **P≈e⁻¹⁰⁰** ⇒ **写者只在受害者运行时写**。
> ⇒ **clean RO 臂窗内 0 命中由「受害者停放」解释，与 PTE 无关**；该窗对层 2 **无判别力**（期望值本身就是 0，不是"没看见 3 条"）。
> **连带**：**所有停放态 RO 窗**（540 s / 1200 s D=0 / 1800 s clean）**都对层 2 无判决力**——前两个另因别的理由排除，第三个因本条混杂排除。

**为什么是「未判定」而不是「阴性/PTE-aware」**：预注册表要求 RW 臂 ≥10 次页内命中才有功效；本轮 RW = **1/600 s（0.1/min）** ⇒ 1800 s 期望 3.0，观测 0 ⇒ **P(0)=e^-3≈5%**，且 rule-of-three 上界 3/1800 s = **0.1/min 与 RW 的 0.1/min 相同** ⇒ **无判别力**。

**窗后 11 命中：不得升级，原因是「状态混淆」而非纪律**
- 窗内受害者**停放**（futex），写者率由 RW 臂给出 = **0.1/min**；
- `RO_OFF` 后 helper 发布 `g_ro_done` 唤醒受害者 ⇒ **已恢复运行**；48 s 内 11 条 = **13.7/min**，恰落在 **C-204 客户端热态 13.87–20.33/min** 区间 ⇒ **跳变主要来自「受害者在跑」，不能归因于「RO 解除」**。两者相差 ~100×，与 PTE 无关。
- 报告必须写：「窗后 11 命中发生在受害者恢复运行之后，与窗内停放态不是同一状态；不得作为 RO/PTE 证据。」

**下一轮设计建议（本轮最重要产出）**
1. **当前设计结构性低功效**：va_list 在栈上 ⇒ RO 必须先停放受害者 ⇒ parked 写者率 0.1/min ⇒ 要达 ≥10 命中需 **≈10,000 s**。
2. **唯一能出强结论的路线**：**「页 RO 且受害者活跃」**——va_list 放**独立 mmap 专用页**（非栈），受害者保持 printf 循环运行，只 RO 那一页；用**同状态 active-RW 臂**定 λ（预期 **≈13.7/min**）⇒ 1800 s 期望 **≈410** ⇒ 零命中 P≈e^-410 ⇒ **可升级 PTE-aware**（命中 ⇒ 非 CPU E4）。
3. 下一轮预注册必含：λ 臂与 RO 臂**同状态**、同 D、页归属过滤、`first_seen` guard band、单实例 ≥3 次枚举、`d ≥ 0x10d8`、以及 pause/unpark 的显式日志行（本轮缺 `UNPARKED`）。

### 7.1 下一版设计（三选一排序，附结构性理由）

**结构性结论（先于选型）**：**「受害者运行 + 目标页 RO 长窗」物理上不可能**（受害者每一步都在写该槽）；而「RO 长窗 + 停放」已被证伪。⇒ 唯一可行形态是 **短 RO 脉冲**：**`~0.5–1 ms` 的 RO 脉冲（受害者保持运行）＋ 每次缺页记录 fault PC/comm/时间戳＋同脉冲内 scanner 命中相关**。判读：脉冲内**外部 PC/comm** 的缺页 ⇒ CPU 写并**当场点名**；脉冲内**有记录、无外部缺页** ⇒ 绕 MMU（DMA，E4）；受害者自身缺页按 PC/comm 排除。

| 排序 | 方案 | 判定 | 理由 |
|---|---|---|---|
| **1** | **自建模块（修正版）**：`do_page_fault`/`fixup_exception` 钩子（fxhook 系）＋RO 脉冲 | **必做部件** | 只有它能**在受害者运行态**记录"谁缺页"（PC/comm）；⚠️**不要用调试寄存器**——那是**按线程 VA**，抓不到别的进程/内核上下文的 CPU 写（§6.3 已更正） |
| 2 | 时间相关性判决 | 廉价前置 | 低风险、可把「写者依赖运行态」从 E1 抬到 E2（"只在 printf 消费相位命中"），并为脉冲定相位窗口；本身不判 CPU/DMA |
| 3 | 双别名页 | **建议取消或改用途** | DMA 不认别名（两 VA 同 PA，写一样可见），CPU 走 RW 别名照样成功 ⇒ **不解决 CPU/DMA**；只能做 VA/PTE 归因，且仍受"受害者必须不停写该页"约束 |

**开窗前新前置（写进下一版预注册）**：① 先测**同状态** RW λ；**λ<10/600 s ⇒ 直接判设计无功效，不开 RO 臂**；② 混杂变量清单第一项＝「停放 vs 运行」；③ 同状态、同 D、页归属过滤、`first_seen` guard band、单实例 ≥3 次枚举、`d≥0x10d8`、显式 unpark 日志行。
