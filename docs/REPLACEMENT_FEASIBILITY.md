# 组件"自研替换"方案：可行性与涉及面分析

> 2026-10-21 · **只分析，不动手**。本文回答一个问题：把崩溃涉及的组件逐步换成
> 我们自己的实现，是否可行、要换哪些、换到什么程度、代价和风险是什么。
> 数据来源：`/data/gw/logs/ne_events.tsv`（core_meta 逐次崩溃台账）、
> `gw/` 全量脚本调用面扫描、`docs/VENDOR_MAP.md`、本机已有自研件清单。

---

## 0. 结论摘要

1. **前提要先纠正**：在"干净窗口"（2026-10-20 08:16 → 10-21 19:34，剔除我们自己
   的取证实验时段）里，35.3 小时共 69 次崩溃，归属是：
   - **自建静态 busybox：44 次（64%）**
   - **自建静态 iproute2：17 次（25%）**
   - 官方组件：4 次（6%，hostapd 2、iptables 1、logread 1）
   - 未知（`?`）：4 次（6%）

   **89% 的崩溃已经发生在"我们自己的替代件"里，而不是官方组件里。** 这是 2026-10-19
   P2 静态化之后的直接结果：崩溃面从厂商 musl 动态件迁移到了 busybox/iproute2。

2. 因此"彻底更换涉及的官方组件"如果按字面执行，**最多只能消掉约 4 次/天**；而且
   hostapd/wpad、procd、内核/驱动、modem 栈都不可替换（见 §3）。

3. 真正值得替换的是 **busybox 与 iproute2 这两个"我们已静态化但仍不可控"的第三方件**。
   但"全量从零自研"（含 sh/awk 解释器、300 个 applet）**不可行也不划算**：
   - 我们自己的 shell 脚本共 **49 个、8456 行**，替换 `sh` 等于重写整个编排层；
   - `grep/sed/cut/tr/tail/...` 合计只贡献 ~3 次/天，从零实现是负收益。

4. **推荐路线：分层替换 + 自建替代实现（不是全部从零写）**
   - P0（已完成）：logc v1.4（去 printf）、logcut v1.0（去 awk 数组）、log_keeper v2.7；
   - P1：**netq**（`ip` 只读子集的 drop-in）+ pidof/ping/ls/sleep 小工具；
     预计把崩溃从 ~28.5/天（awk 修复后基线）降到 **~12/天**；
   - P1.5（可选）：**自建 busybox**（最小 applet 集 + 补丁）替代 Alpine 二进制，
     保留 CLI 兼容、拿回可控性；
   - P2/P3：`ip` 写子集、自研 logd（顺带稳定 aee/logread 路径）——**按实测再决定**；
   - **不做**：sh/awk 解释器、hostapd/wpad、procd、xtables、内核/驱动、gdb。
5. **替换不等于免疫**：`sleep 1` 与 `?` 证明还有一类未定位机制；任何替换方案都必须
   配"受限运行时"编码规范 + 每个自研件的崩溃取证，否则只是把 bug 换个地方。

## 0.5 第四轮修订（2026-10-21 深夜）：优先级反转

> 本节写在原方案之后、基于同一天的后续取证。它**推翻原方案的主线排序**，
> 但保留 §3 的组件矩阵作为兜底资料。

### 0.5.1 新事实

"机制未知"的那一类崩溃已经定性：**就是 musl 的 printf/stdio va_list 缺陷**
（详见 `docs/SIGSEGV_ANALYSIS.md` §12）。要点：

- 20 行最小复现器（反复 `snprintf(buf,24,"%ld",i)`）在设备上 **2 秒内必崩**，
  `-O0/-O1/-O2` 全崩 —— 与程序、优化、日志数据无关；
- 崩溃时 `vfprintf` 帧内的 va_list 被写成小整数（`__gr_top=0`、`__stack` 垃圾），
  与 logc v1.3、busybox 的 `sh` 两份 core **逐字段同签名**；
- 金丝雀（只 `return 0` 的静态程序）30 万次 0 崩 —— 不存在"与程序无关的背景率"。

### 0.5.2 因此排序要改

| 方案 | 覆盖（次/天） | 成本 | 结论 |
|---|---|---|---|
| **修 musl printf + 用同一 musl 重编静态工具链** | **~40 / 47（logc 类 + sh + grep + pidof + ls；sleep 待确认）** | 定位 1–2 轮 + 重编/回归 1–2 轮 | **新的 P0** |
| 逐个替换组件（netq/小程序/logd） | ~17 / 47（ip + 小程序 + logd/logread） | 6–10 轮 | 降为 P1/兜底 |
| 替换 `sh` | 4.8 / 47 | 6–10 轮 | **不做**（musl 修好后无必要） |

关键判断：**一个 musl 补丁的覆盖面是"换组件"的 2.5 倍，成本却低一个数量级**，
而且修好后 busybox/ip/我们自己的工具一次性受益。反过来，即使把 ip/小程序全换成
自研件，`sh`/grep/pidof 仍会继续崩（它们跑在同一个 musl 上）。

### 0.5.3 修订后的路线

- **P0（立即）**：用最小复现器定位 musl 的写入者（观察点已收敛到
  `vfprintf` 的 `va_copy`/`nl_type` 邻接区），做候选补丁；每轮用
  复现器 + `sh` fork 循环 + 全量 selftest 验证。
- **P0.5**：用打好补丁的 musl 重编 `gw/bin/busybox`、`gw/bin/ip` 与全部自研工具；
  跑 24h 崩溃台账对比（目标：`sh/grep/pidof` 的 NE 归零）。
- **P1（仅在 P0 失败时启动）**：按原方案做 netq + pidof/ping/ls/sleep 自研，
  先把 ip 与小程序从崩溃面里拿掉。
- **P2（不变）**：厂商动态件（hostapd/logd/thermal_core）不可替换，
  维持"检测+恢复+取证"；logd 自研仅在需要日志链路可控时再做。
- **明确不做**：`sh`/awk 解释器、hostapd/wpad、procd、xtables、内核/驱动。

### 0.5.4 对原方案其余部分的处置

- §3 的组件矩阵、§4 的技术约束、§9 的风险与止损 **继续有效**，
  但阅读顺序改为：先看本节，再把矩阵当作"如果 musl 补丁失败"的备选清单。
- §6 的 P1/P2/P3 里程碑**整体后移**，不再是下一轮的主线。
- §0 的"结论摘要"保留为历史判断；以本节为准。

## 2. "自研"的四种粒度（避免把"自研"等同于"从零写"）

| 粒度 | 含义 | 适用 | 本项目先例 |
|---|---|---|---|
| **A. 从零实现** | 新写一个小工具，只做一件事 | 功能边界清晰、调用面小 | `logc`、`logcut`、`healthdog` |
| **B. 自建替代实现** | 拿上游源码自己编译/裁剪/打补丁，保留 CLI | 调用面大、兼容性要求高 | `gw/bin/ip`（iproute2 自建）、`v3httpd`（替代 nginx+webs） |
| **C. 移除需求** | 改写调用点，让这个工具不再需要 | 用法很窄 | awk 锚点抽取 → `logcut` |
| **D. 保留 + 隔离** | 不换二进制，靠监督/重试/超时/取证降影响 | 不可替换或收益极低 | hostapd 活套接字判据 + 即时修复、netlock 串行化 |

**关键判断**：busybox 的 300 个 applet 属于"调用面大、兼容性要求高"，正确粒度是 **B**
（自建 busybox + 已知缺陷补丁），而不是 A（从零写 300 个 applet）。

## 4. 关键技术约束

### 4.1 运行库：静态 musl 不免疫
三个已实锤的反例：
- `logc` v1.3：崩溃在 **musl `strftime → snprintf("%0*lld") → vfprintf`** 的 va_list 污染；
- 静态 busybox `awk`：**busybox 自身**的数组释放路径在退出时 NULL 解引用（约 1%/次，
  空数组/满数组都中）；
- 静态 iproute2 `ip`：`filter.label` 这个 .bss 全局被写成小整数 `0x157c0`，在
  `fnmatch` 里当指针解引用。

因此自研件必须遵守**受限运行时规范**（已在 logc v1.4 / logcut v1.0 落地）：
- 热路径禁用 `printf/snprintf/strftime` 家族与 locale；用有界手写格式化；
- 解析器不用动态数组/哈希，不信任任何长度字段；先校验后使用；
- 固定上限 + 显式边界；每个工具自带 `--selftest`，解析类再加 fuzz；
- 每个工具装 SIGSEGV/SIGBUS handler 写面包屑（`logc` 先例），可选 core 窗口；
- 静态链接、`-fstack-protector-all`、无多线程、无 dlopen。

**但要诚实**：`sleep 1`（不做格式化、不做解析）也崩过一次，说明还存在我们尚未命名的
机制。替换方案降低的是"已知三类"的暴露，不是全部。

### 4.2 迁移机制：现成的 drop-in 农场
`gw/toolchain_init.sh` 已经建立 `/data/gw/sbin` 符号链接农场（busybox --install -s），
`rc.extend.sh` 把 `/data/gw/sbin:/data/gw/bin` 前置到 PATH。替换单个工具只需要：
1. 新二进制放 `/data/gw/bin/`；2. 农场里对应名字指向它（或直接同名覆盖）；
3. 脚本零改动。**这是本方案成本最低的部分。**
限制：只在 `rc.extend` 之后的守护树生效；早期 `/etc/rc.d` 仍用厂商 `/bin/sh`。

### 4.3 兼容面（按组件）
- **CLI 输出**：脚本大量用 `grep` 解析 `ip` 输出（`-o` 格式、空格、字段顺序）。
  netq 必须逐字节兼容被使用的子命令，否则脚本会静默判错（比崩溃更危险）。
- **ubus**：logd 的 `log` 对象（read/stream/oneshot/lines）是 logread/aee/GUI 的契约；
  logc 已经实现了客户端侧，服务端可照 `tmpfiles/logd.c`（OpenWrt 上游）实现。
- **/dev/log**：所有 `logger` 调用的入口；替换 logd 必须接管该 socket 且保持 dgram 语义。
- **netlink**：`ip` 的读写子集；v6、多路由表、fwmark、rule 优先级都要覆盖。
- **WiFi 私有面**：hostapd/wpad 与 MTK 驱动（mwctl/apcfg/MLO）深度耦合，**不可替换**。
- **启动顺序**：logd 必须在 logger 之前；替换要接进 rc19/rc.extend 的正确时序。

### 4.4 取证与可维护性
每增加一个自研件 = 源码 + 构建脚本 + VERSIONS 登记 + selftest 断言 + 崩溃取证 +
冷启动验证。按现有节奏，这是"每件 0.5–1 轮"的固定成本，必须在路线图里计入。

## 6. 建议路线（每阶段独立可回退）

### P0（已完成，2026-10-21）
logc v1.4（printf-free）、logcut v1.0（awk 数组移除）、log_keeper v2.7。
**验收**：logc 零崩溃 ≥1h；awk delta 输出逐字节等价；logcut 600 次 0 崩；selftest 97/0。

### P1：netq（只读）+ 小工具（建议下一轮）
- `netq addr|route|rule|link`：rtnetlink 只读子集，**drop-in 兼容 `ip` 的输出格式**；
- `pidof`/`pgrep`、`ping`、`ls`、`sleep` 自研小工具（合计 ~500 行）；
- **影子模式先行**：同一时刻跑 vendor `ip` 与 netq，diff 输出，连续 24h 零差异再切 PATH；
- **验收**：影子期 0 diff；切换后冷启动 + 全量 selftest；崩溃计数（ne_events 增量）下降。
- **预计**：28.5 → ~12 次/天。

### P1.5（可选）：自建 busybox（最小 applet 集 + 补丁）
- 用 zig 自建 busybox 1.36.1，只编我们用的 applet，打上已知缺陷补丁（数组释放路径等）；
- 与 Alpine 版逐命令行为对比（我们已有 selftest 与脚本语料）；
- 收益：把 grep/sed/... 的不可控第三方件换成"可打补丁的第三方件"，成本远低于从零写。

### P2：`ip` 写子集
- `addr add/del/flush`、`route add/replace/del`、`rule add/del`、`link set/add/del`；
- 先双写校验（netq 写 + vendor `ip` 读回对比），再切换；
- **验收**：断网/换网/重启演练后路由表与规则逐条一致；冷启动 3 次。

### P3：自研 logd（含 aee/logread 兼容）
- /dev/log + 10MB 环 + ubus `log` 对象；帧格式以 logc 的解析器为准（已被 fuzz 过）；
- 先旁路影子（复制 /dev/log 到我们的环，不影响厂商），再接管；
- **验收**：aee 转储、GUI 日志页、logread 兼容；ring 轮转/清环；冷启动。
- 附带收益：aee 的厂商 logread 读到的是**干净帧**，其已知崩溃触发条件消失。

### P4（可选）：thermal_core 接管
- 读 `/sys/class/thermal`、驱动风扇；接管前 24h 双跑对照温度/转速；超温自动回退厂商。

### 明确不做
- **sh/awk 解释器**（8456 行脚本；早期 boot 仍依赖厂商 sh）；
- **hostapd/wpad**（MTK 私有面）；
- **procd / 内核 / 驱动 / modem 栈**；
- **xtables/iptables**（0.7/d，netfilter netlink 成本过高）；
- **gdb**（取证工具）。

## 7. 成本/收益账（估算）

| 阶段 | 工程量 | 预计崩溃率 | 主要收益 |
|---|---|---|---|
| 现状（awk 已修） | — | ~28.5/d | 基线 |
| + P1 | 2–3 轮 | ~12/d | ip 11.6 + 小工具 4.8 |
| + P2 | 2–3 轮 | ~10/d | 写路径覆盖（未观测到的风险） |
| + P3 | 2–3 轮 | ~9/d | logd/logread 路径 + 日志链路可控 |
| + P4 | 1–2 轮 | ~8.5/d | 温控件可控 |
| 残余 | — | sh 4.8 + grep 2.7 + hostapd 1.4 + ? 2.0 + iptables 0.7 | 不可替换/未定位 |

> 结论：**P1 是唯一"高性价比"阶段**（去掉约 58% 的当前基线）；P2 之后收益迅速递减，
> 主要价值转为"可控性/可维护性"，而不是崩溃次数。

---

## 8. 决策建议

1. **下一步只做 P1**：netq 只读 drop-in + pidof/ping/ls/sleep。理由：ip 占 25%、
   调用面明确、只读安全、可逐字节对比、可 PATH 回退。
2. **并行做一次"sh/grep/sleep/? 四类各抓一份 core"** 的取证窗口（不改代码）：
   如果它们与已知三类同源，P1.5 的自建 busybox 补丁可以顺带解决；如果是新机制，
   替换方案不能替代根因调查，需要单独立项。
3. **P2/P3 暂缓**，以 P1 的实测（ne_events 增量、影子 diff、冷启动）为决策依据。
4. **不做 sh 替换**：在 8456 行脚本 + 早期 boot 依赖的前提下，这是投入最大、风险最高、
   收益最不确定的一项。
5. 任何阶段都保持：vendor 二进制不删、PATH 可回退、每阶段冷启动验证、崩溃台账对比。

---

## 9. 风险与止损

| 风险 | 止损 |
|---|---|
| netq 输出与 `ip` 有细微差异 → 脚本静默判错 | 24h 影子 diff + 逐字节断言 + 切换前一键回退 |
| 自研件引入新崩溃 | 受限运行时规范 + crash breadcrumb + core 窗口 + selftest |
| logd 接管破坏 aee/GUI/logger | 先旁路影子、再接管；保留厂商 logd 随时回退 |
| thermal 接管导致过热 | 24h 对照 + 超温自动回退 + 硬件看门狗 |
| 维护成本累积 | 每件都要源码/构建/注册表/selftest；路线图按"轮"计费 |

---

## 10. 一句话结论

**把"更换官方组件"改成"把崩溃面从不可控的第三方件迁移到可控的自研件"，并且只迁移
性价比高的那一半（ip + 小工具 + 可选的 logd）；sh/awk/hostapd/内核明确保留，
用监督、取证和受限运行时规范兜住。**
