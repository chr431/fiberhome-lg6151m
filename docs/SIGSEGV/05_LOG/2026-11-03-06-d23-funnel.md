# 06 · D23 预注册 · 终局一枪：`__arch_copy_to_user` 漏斗捕获（2026-11-03 夜间 N3c）

> **预注册文档：实验开窗之前写定并 commit。实验后只追加 §9–11，不改 §1–8。**
> 编号说明：NN=06 顺延（01..05 已占用）。本文档中性命名：不含目标网络名与个人凭证。

## 1. 问题

32B 记录族 `{u32 X, 0, u32 len, __be32 ip, 0...}` 的写入者身份。N2d 静态普查给出
唯一漏斗：全部调用式 uaccess（160 个 `bl` + 416 个 per-TU 克隆调用 + `copyout`/iov_iter
数据面）都汇入 `__arch_copy_to_user` @ `0xffffffc00843b680`（首指令 `05 00 02 8b` =
`add x5,x0,x2`）。D21 已排除 mt_wifi 的 12 个调用式站点；D20/D21 的热窗证明
50 KB/s 级客户端数据面不行使任何 mt_wifi 调用式站点。

## 2. 假设（先写死）

- **H_u**：记录族的写入者是 uaccess 路径（任何上下文，含 borrow-mm 的 kthread）——
  即某个进程/内核执行体通过 `__arch_copy_to_user` 把该 32B 形状写进用户态地址。
- **H_d**：写入者不在 CPU uaccess 路径（DMA/总线主写、或其它非 `copy_to_user` 的
  CPU 写原语）。

## 3. 仪器

- **模块**：`funnelcatcher.ko`（源码 `tools/oneoff/sigsegv/bmods/funnelcatcher.c`）。
- **站点**：vmlinux `.text` `0xffffffc00843b680`，期望 4 字节 `05 00 02 8b`
  （小端存储序）。模块参数 `site=` 缺省即此值；`dryrun=1` 只定位 + 字校验 + 分支
  可达性计算，**不写一字节**。
- **补丁原语（与 N2d 方案的差异，预先声明）**：本内核 `CONFIG_RODATA_FULL_DEFAULT_ENABLED=y`
  且 `mark_linear_text_alias_ro()` 把 `[_stext,_etext)` 的**线性别名也设为 RO**；
  直接写 `__va(pa)` 会权限 fault。故采用**等价可写别名**：页表遍历取该页 PA
  （`pmd_page_paddr`，处理 PMD leaf）→ `pfn_to_page` → `vmap(1 页, PAGE_KERNEL)` →
  在 vmap 别名写 4 字节 `b <模块内 trampoline>` → `dc civac + ic ivau`（对 image VA）
  → `vunmap`。写入与 I-cache 维护在 `stop_machine` 内完成。还原 = 同一原语写回
  原 4 字节 + 逐点读回断言。
- **跳转**：AArch64 `b` 仅 ±128 MB。模块区实测位于 `0xffffffc000d??000` 附近
  （N3-exec：base=0xffffffc000dc2000、stub=0xffffffc0019f7000），站点
  −stub ≈ 106 MB，可达。**init 时计算并打印实际距离；越界即失败、不 patch。**
- **trampoline 过滤器**（零开销路径）：入口先原子计数（总调用），然后
  `len==32` 或 `len==16` 才进入 C 形状检查（`copy_from_kernel_nofault` 读
  src 前 32B，避免无 extable 的裸读 fault）；形状 = `len==32 && src[8..16)==0 &&
  src[24..32)==0`，或 `len==16 && src[8..16)==0`。命中写入 per-cpu 无锁环
  `(ts, lr, dst, len, src, data[32], pid, comm)`；非 32/16 长度直接执行被替换指令
  `add x5,x0,x2` 并跳回站点+4。
- **正对照**：`funnel_selftest`（静态 aarch64 工具）向 pipe 写入 32B
  `{u32 标记, 0, u32 32, 0, ...}` 后 `read(fd,buf,32)`；pipe 读必走
  `copy_page_to_iter → copyout → __arch_copy_to_user`，len=32 且 src 前 32B 即
  该形状。**预期恰 1 条命中（lr 落在 copyout/copy_page_to_iter 族）**。

## 4. 窗与有效性门禁（任一不满足 ⇒ 该窗 INVALID）

1. `insmod dryrun=1`：`VALIDATION OK`；站点字 == `0x8b020005`；PA/别名/vmap 定位成功；
   打印 branch 距离 ∈ (−128MB, +128MB)。
2. live：`INSTALLED`、`/proc/funnelcatcher` 头行 `PATCHED`、站点读回 = 我们写入的 `b`。
3. **热窗 ≥1200 s**：PC（192.168.9.145，MyHome/rai0）持续拉 `app.js`（目标 ≥50 KB/s，
   `curl -o NUL`），窗内设备 `boot_id` 不变、无 oops/panic/重启。
4. 正对照在窗内执行且 `shape_hits ≥ 1`（证明过滤+记录链真的在跑）。
5. 总调用计数 `calls_total` 窗内增长 > 0（漏斗确实被行使）。
6. 收窗：`rmmod` 后站点读回等于原始 4 字节（还原断言）、0 个我方模块、`TRY_A` 低字节=0。

## 5. 判据（预写死，不改）

- **主判据（H_u）**：有效窗内**记录形状命中数 > 0**（不计正对照那一条）⇒ H_u 成立，
  且命中样本的 `lr`（结合 `/proc/kallsyms` 符号化）即写入者调用链。
- **排除判据（H_d 上位）**：形状命中 = 0 **且** §4 门禁 1–5 全满足 ⇒ uaccess 物理性
  排除（E2/E3）；DMA/总线主写假设上位。
- 若命中 > 0 但全部可归因于正对照 ⇒ 视同 0（正对照单独标记 pid/comm）。
- 若仪器缺陷导致崩溃：崩溃预算 ≤2；同一缺陷重复出现即停（不改判据救场）。

## 9. 开窗后追加 · 仪器实现与两次修正（§1–8 未改）

### 9.1 补丁原语（与 N2d 方案的偏差，实测原因）

`CONFIG_RODATA_FULL_DEFAULT_ENABLED=y` + `CONFIG_STRICT_KERNEL_RWX=y`：本内核
`mark_linear_text_alias_ro()` 把 `[_stext,_etext)` 的**线性别名也设为 RO**，
故 N2d 的 `__va(pa)` 直接写会权限 fault。改用**自建可写别名**：TTBR1 页表遍历 →
`pmd_page_paddr`（实测 site 页为 PMD leaf）→ `pfn_to_page` → `vmap(1, PAGE_KERNEL)` →
在别名写 4 字节 `b` → 对 image VA 执行 `dc civac + ic ivau`（每 CPU）→ 留到还原后
`vunmap`。dryrun 实测（04:47）：`site=ffffffc00843b680 word=8b020005 next=aa0103ef`
（下一字 = `mov x15,x1`，与 copy_to_user.S 源码一致）、`tramp=ffffffc0019d0000`、
`delta=-111,588,992`（106.4 MiB，±128 MiB 内）、`pa=0xfdc3b680`、
`alias=ffffffc008097000 readback ok`。live/还原均读回断言通过。

### 9.2 形状非特异性（v1 抖振，主窗前完成修正）

v1（仅按 §3 的 len/零字过滤）开窗 2 s 内 permissive 形状命中即达 ~1e3/s：
构成是 `sh/ash` 的 0x01 开头全零拷贝、comm 名拷贝、临时 `sockaddr_in`
（含 PC 的 192.168.9.145）与栈残留；64 槽环会在 0.1 s 内被冲掉。若把它当作
"记录形状命中"会得到完全错误的 H_u。故 v2 起：
- **全形状只计数**（`shape32` / `shape16`，仍满足 §5 的"命中数"可观测性）；
- **记录判据 = 家族 B 内容**（`04_FAMILIES.md §3.1`）：
  A0B2 `{A,0,len,ip,0}`：`len∈[0x40,0x4000]` 且 `+0x14` 为 unicast IPv4；
  B0A2 `{B,0,A',0}`：`A'∈[0x1000,0x100000]` 且 `B≠0`。
  v3（确认窗）把 A0B2 的 A 放宽为任意值（含 0），因 C-205 自然样本为
  `{0,0,len,ip}`。
- 记录附带 4 级 fp 回溯（`CONFIG_FRAME_POINTER=y`，`_copy_to_user` 有
  `stp x29,x30; mov x29,sp`），以解析 generic `_copy_to_user` 之上的真实调用者。

**声明**：§5 原文"记录形状命中数>0 ⇒ H_u"隐含"该形状特异"。实测特异度不成立
（见上），故本文件把"记录族的形状"操作化为家族内容；全形状计数与家族内容计数
**两者都报告**，判决只采用后者（否则会被 benign 拷贝假阳性击穿）。

### 9.3 正对照（E4）

`funnel_selftest`：向 pipe 写 32B `{0x12345,0,len=0x680,ip=192.168.9.145,0}` 后
`read(fd,buf,32)`。两窗均恰得 1 条 `fl=04 A0B2`，`comm=funnel_selftest`，
`lr=copyout+0x3c`，fp 链 `copy_page_to_iter+0xac → pipe_read+0x16c →
new_sync_read+0x64 → vfs_read+0xcc`，`data` 与注入载荷逐字节一致（E4）。
说明：过滤、记录、lr/fp 符号化、环读取全链路有效。

## 11. 判决

**H_u 不成立；uaccess（`__arch_copy_to_user` 漏斗）对家族 B 内容做物理性排除
（E2/E3）。** 依据：两窗合计 1890 s、2913 次 app.js 拉取（~293 MB WiFi 客户端
流量）、漏斗入口 28,957,748 次调用、permissive 形状 407,635 次（~215/s），
而**家族 B 内容命中 = 0**（正对照 2 条，可完全归因）。

范围与局限（必须与结论同读）：
1. 只覆盖**独立** `len==32`（及 `len==16`）的 `copy_to_user`；若记录被嵌在更大
   缓冲区的拷贝里，本仪器不覆盖（未观测 ≠ 未发生）。
2. 家族内容判据来自 `04_FAMILIES.md §3.1` + C-205 自然样本；A/B 取值域外的
   变体不会被记录（v3 已放宽 A 含 0）。
3. permissive 形状本身非特异（shakedown 实测 ~1e3/s），任何仅凭"形状命中"的
   H_u 结论都不可信；本判决只用内容命中。
4. 与 N2d §5-D 一致：DMA/总线主写（陈旧 PA/描述符）成为上位假设；窗口内 4 起
   自然用户态 NE 且无内核 oops，不构成因果证据，但与其相容。
