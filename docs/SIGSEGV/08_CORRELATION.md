### 意外收获：命中与 RX 包数**近乎严格线性**

- 逐 10s 分箱：**corr(命中, RX 包数) = 0.965**；corr(命中, eth1 包) = 0.965；corr(命中, eth0 包) = −0.05。

> **以包为单位，命中率是线性的** → 写入者是「**每个有线 RX 包一次机会**」的路径，而不是"每 N 个事件"或"环回绕"。

### 与既有结论的合并

- WiFi TX：**排除**（臂1 D 臂反向 + 臂2 全程 rai0 TX=0 仍命中 127.6/min）。
- eth0 专属路径：**排除**（臂2 中 eth0 RX 下降而命中 ×71）。
- **写入者的必要条件 = 有线端口（eth0/eth1）共用的 EDMA RX 环上、每 RX 包一次的写机会。**
- 定量锚点：**~1.3×10⁻³ 命中/RX 包**，可用于反推「每个 RX 缓冲回收事件命中率 ~0.1%」还是「某个固定槽位/条件组合」。

## 风险量化（1.3/千包意味着什么）

- 每千个有线 RX 包 ≈ **1.3 次**「32B 记录落进 canary 栈页」的写事件。家用 500 pps ⇒ **~5.6 万次/天**写机会（单个目标页）。
- 而自然 NE 只有 ~4/h（≈96/天）→ **约 580 次写机会才产生 1 次进程死亡**：绝大多数写入落在无害位置（未映射/已释放/非指针字段）。
- **这解释了「为什么系统还能跑」，但同时说明"NE 数低 ≠ 问题小"**：NE 计数只统计了"写到了 va_list 且解引用"的那一小撮；
  真正的内存破坏面比 NE 数大 2–3 个数量级。
- 也解释了 canary 与自然进程的差异：canary 的栈页是**刚分配的**（大概率来自回收的 RX 缓冲页池），
  而自然进程的栈页通常是长寿命页，落在"曾经是 RX 缓冲"的页上的概率低得多 → 自然 NE 率远低于 canary 率，
  **不能用 canary 率外推自然 NE 率**（与 00_STATE §6 停止规则一致）。

## 静态：EDMA RX 路径（vmlinux.elf，符号齐全，capstone 反汇编）

对象：`analysis/kern/vmlinux.elf`（18 MB，47,910 符号）。工具：`_local/work/crash-root/vml_dis.py <sym>`。

| 函数 | 事实 |
|---|---|
| `mtk_poll_rx_edma0/1` | NAPI RX 轮询：描述符基址 `[ring+0x28]`，**步长 0x20（32B）**，索引按 `ring+0x20`(cidx) 与 `ring+0x1c`(环深) 取模；取描述符后 `tbz w28,#0x1f` 检查 **w1 的 bit31（DD/完成位）**，未置位即退出循环 → **消费侧的顺序是对的**（先确认 DMA 完成再消费） |
| `recycle_fe_dma_buf` | 薄壳：`container_of(x0-0x40)` → 调 `ops->[0x48]` |
| `fe_edma_recycle_buf` | 把缓冲挂进**延迟回收链表**（自旋锁内 `str x5,[x3,#8] / str x3,[x20,#0x7d8]`），**不做 dma_unmap** |
| `fe_dma_set_rx_recycle` | 只置 `+0x540` 的回收模式字节 |
| `mtk_rx_clean_edma` | 环 teardown：逐缓冲 `dma_unmap_page_attrs(desc->w0)` → `page_frag_free()` |
| 分配器 | **无 page_pool**；缓冲来自 `__netdev_alloc_frag_align` / `build_skb`（page_frag） |

**静态判决（如实）**：**路径已锁定，具体窗口未定位。**
- 消费侧（DD 位检查）顺序正确，未发现"未等 DMA 完成就消费"。
- 回收是**延迟链表**（不是立即回填），也未发现"先 free 后 unmap"。
- 因此**未能在静态层面指出明确的 bug 点**。可能的位置收敛为：延迟回收链表与回填/环复用的交错时序，
  或 `page_frag` 在跨 CPU 回收时的可见性——两者都需要运行时证据（kprobe 被 `CONFIG_KPROBES=n` 堵死，
  `pagemap` 也不存在），故本轮**不作断言**。

**形状线索（待验证假设，不是结论）**：RX 描述符 = 32B、`w0=缓冲 PA`、`w1=状态/长度（bit31=DD）`、
`w2..w7` 在空闲态为 0（`dump_dma` 实测）。记录 = `{小整数, 0, len, src_ip}`，**尺寸吻合但内容与"空闲态描述符"不符**；
若硬件在 DMA 完成时把 L3/L4 信息写回 `w2..w7`（MT7988 EDMA 支持 RSS/L3L4 信息），则记录可能是**写回后的描述符片段**。
验证方法：在收到包后立刻 dump 该槽位的 8 个字，与记录逐字段比对（下一轮可做，需 1 次 `dbg_dma` + 1 次记录抓取）。

## 描述符/头写回假设：分两半，**一半被静态代码否定，一半被解释为采样时机**

### A. "DMA 在缓冲区前置 32B 头" —— **不成立（静态代码否定）**
- 装填（`mtk_rx_alloc_edma` 0x59625c）：`add x1,x1,#0x40` → **`dma_map_single(buf+0x40)`**，缓冲头部留 64B。
- 收包（`mtk_poll_rx_edma0` 0x5956e8）：`build_skb(buf)` 后 **`skb->data += 0x40`、`skb->tail += 0x40`** → skb 数据正好从 `buf+0x40` 开始，与 DMA 目标重合；随后 `skb_put(len)`。
- → 若硬件在 DMA 起点写头，驱动会把它当以太头。**所以 DMA 不往缓冲区前置任何头**；那 64B 头room 既不被 DMA 写、也不被驱动读。

### B. `w1 = 0x00060000` 的含义 —— **是长度字段，不是 header 标志**
- 装填：`sturh w1,[desc,#5]` → 缓冲大小写进 **byte5..6 = 位8..23**；0x600=1536 → `w1 = 0x600<<8 = 0x00060000`（"bit17/18" 只是 1536 的二进制位）。
- 消费：`ubfx x1,x28,#8,#0x10` → 从 **位8..23 取包长**；`tbz w28,#0x1f` → **位31 = DD**。两侧自洽。
- → Lead 最初对 bit17/18 的解读可撤回。

### C. Lead 的"200 条抽样 w2..w7 全 0" —— **是采样时机，不是假设被否**
`mtk_rx_get_desc_ext`（0x592dbc）：**只有 w1 的 bit31(DD) 置位时**才把描述符 w0/w1/w2/w3 拷出使用。
dump 到的 1024 条全是 **DD=0 的待收状态**，w2..w7 当然为 0 —— **DD 置位后的写回形态根本没被采到**。

### D. 修正后的假设（当前最可信，能解释全部观测）
**记录 = EDMA 在 RX 完成时对描述符的写回（32B = 整条描述符）**，携带包长与 L3/L4 解析出的 IP。
若该描述符所在页被回收复用为用户栈页 → 写回落到用户栈。这同时解释：每 RX 包一次机会、32B、含 IP、
以包为单位线性、只在有线 RX 出现。

**验证方法（不需要新仪器）**：制造 **RX 积压**（灌流把环压满、驱动来不及回收），使部分描述符保持 DD=1，
再 `cat /proc/mtkfe/dump_dma` 抓 w2..w7；出现非零即当场验证。约需 10 min + 一次 2 min 窗口。

## 本轮最终结论（定稿）

1. **写入者 = 有线端口（eth0/eth1 共用 EDMA RX 环）的「每 RX 包一次机会」路径**，速率 **1.3 ± 0.2 命中/千个有线 RX 包**。
   支撑：LAN-only 臂 ×71 且 eth0 RX 反向下降；WiFi TX 全程 0 仍命中；逐包线性（corr 0.965）。
2. **WiFi TX 排除、eth0 专属路径排除、WED tuple 路径排除**（后者见 00_STATE §10 P1 诊断）。
3. **具体窗口未定位**（静态未发现明确 bug：消费侧 DD 顺序正确、回收走延迟链表、无"先 free 后 unmap"）。
   定位需要运行时证据，而 kprobe（`CONFIG_KPROBES=n`）与 pagemap（`CONFIG_PROC_PAGE_MONITOR=n`）双双不可用。

4. 若仍要拿 PA，唯一可行的内核侧手段是重编内核开 `CONFIG_PROC_PAGE_MONITOR`（成本高，需刷机）。

## DD=1 突发采样实验（2026-11-01 11:10）—— **用户态采不到，如实记录**

方法：制造 RX 突发，在突发期间连续 dump `/proc/mtkfe/dump_dma`，统计 `rx_total / dd_set / w2..w7 非零`。
脚本 `/data/repro/dd_burst4.sh`（每次 12 份快照）。

| 突发 | 负载是否真发 | 快照数 | rx_total | dd_set | w2..w7 非零 |
|---|---|---|---|---|---|
| B1 (1793501060) | **失败**（SSH 通道 `Socket is closed`，仅 8 s） | 12 | 1536 | 0 | 0 |
| B2 (1793501098) | **有效** 408.5 MB / 23.9 s（≈17 MB/s） | 12 | 1536 | 0 | 0 |
| B3 (1793501136) | **有效** 400.4 MB / 22.5 s（≈18 MB/s） | 12 | 1536 | 0 | 0 |
| 基线（无流量） | — | 3 | 1536 | 0 | 0 |

**口径（不得含糊）**：**3 段中 2 段为有效负载（各约 400 MB、17–18 MB/s），1 段因 SSH 通道断开失败；
有效段内 24 份快照全部 `dd_set=0`。** B1 是空跑，不能计入数据。

**结论**：**用户态无法捕获 DD=1 状态**。一次 `cat dump_dma` 要读 5656 行（数百毫秒），
而 NAPI 在微秒级消费掉 DD=1 描述符 —— 采样窗口比目标状态宽 4–5 个数量级，撞不上。
**这不是假设被否，而是验证路径在用户态不可行。**

## 三条用户态验证路径均已堵死（本轮固定资产）

| 路径 | 阻塞原因 | 影响 |
|---|---|---|
| kprobe / ftrace 探针 | `CONFIG_KPROBES=n`（无 tracefs/kprobe_events） | 无法在 `dma_unmap`/`page_frag_free` 上做页级判决 |
| VA→PA 翻译（PA 匹配） | `/proc/*/pagemap`、`/proc/kpageflags` 均不存在（`CONFIG_PROC_PAGE_MONITOR=n`） | 无法把 canary 栈页映射到 PA，无法与 `dump_dma` 的缓冲 PA 比对 |
| DD=1 写回形态采样 | dump 耗时数百毫秒 vs NAPI 微秒级消费 | 无法观测 RX 完成时的描述符写回 |

→ 任何进一步的**机制级**判决都需要内核侧手段（重编内核开 KPROBES 或 PROC_PAGE_MONITOR），成本 = 一次刷机。

## 方法论笔记：**速率假象 —— 为什么三段混算会凭空造出「成簇」**

我在 09_CONDITIONAL.md 初版宣称「命中在时间上显著成簇（21.7% 的秒有 ≥2 个不同 canary）」。
**该结论已撤回**，原因是一类可复现的统计陷阱：

1. **把不同速率的三段混算**：静默段 1.8 命中/min、LAN 段 127.6 命中/min、回落段 0.5 命中/min。
   合并后按 1 秒粒度统计"同秒 ≥2 个 canary"，自然会出现大量"多命中秒"。
2. **在 1 秒粒度、2 次/秒的速率下，泊松过程本来就长得像"成簇"**：
   λ=2.1/s 时，1 秒窗口里出现 2 个命中是最常见结果之一；相邻间隔的 p10≈0 也是必然（期望间隔 0.48 s）。
3. **正确做法 = 速率匹配零模型**（对干净的 LAN 段单独做）：

| 量 | 观测 | 独立 4-canary 泊松零模型 | 判定 |
|---|---|---|---|
| 同秒 ≥2 个**不同 pid** 的秒数 | 131 | **127.0** | 比值 1.03，无超额 |
| 同秒 ≥2 次命中的秒数 | 131 | 186.4（同速率泊松） | 观测**低于**泊松 |
| 同 canary 间隔 p50 / p90 | 1 s / 2 s | 1.32 s / 4.38 s（指数） | 尾部更短（比泊松更规则） |

**结论**：**速率匹配后与独立泊松无显著差异** → 没有"共享页/突发批次"的证据。
写入者是**每包独立、无记忆**的（这一点反过来成了后续判别实验的基础）。

**教训**：这又是一次「判据集合 ≠ 被判定对象的集合」——
用"1 秒窗口 + 混合速率"去检验"是否成簇"，判据本身就把速率效应当成了簇聚效应。

## 测量能力边界声明（本轮定稿，见 [10_MEASUREMENT_PROTOCOL.md](10_MEASUREMENT_PROTOCOL.md)）

> **canary 命中率不是可复现的量化指标**：它在 **~1/min 与 ~127/min** 之间随未知的慢变设备状态漂移
> （同一批"新起 canary"在不同时间相差 **19 倍**）。
> 因此 **「1.3 命中/千包」只能在同一会话内做相对比较，跨会话一律不可比**。
> 这是**测量能力的边界声明**，不是研究失败——它防止后来人拿两个不同会话的数字做因果推断。

三个候选杠杆已全部排除（流量 1366× 无响应 / canary 重启无响应 / eth0 环重置无响应），
但**「写入者在有线端口共用 EDMA RX 路径」这条硬结论未被动摇**（LAN-only 臂 ×71 支撑）。
