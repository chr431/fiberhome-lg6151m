## 1. 机制（已验证）

**蜂窝 MD 固件经 DPMAIF 的 RX DMA，按 MD 侧私有持有的陈旧（stale）缓冲页
列表，持续向 AP DRAM 写 16/32 字节环记录。被写页一旦被复用——用户进程的
anon 页、或已释放回 buddy 的内核页——就成为全家族 SIGSEGV 的注入源。**
printf 家族只是最高频的污染内存解引用路径（选集效应，§5.1），不是缺陷方。

机制链（每一环都有实测锚点，见 §3/§4）：

```
[AP] dpmaif/ccci RX 缓冲池页（4KB/条，环记录 PLEN0=4096 管理）
  → 生命周期事件（队列重建/端口关闭 churn）后页被释放回 buddy，
    但 MD 侧私有持有的缓冲页列表【不失效】（§3-E4：AP 全量不可见）
[MD] MD 经 DPMAIF RX DMA 继续向列表内 PA 写环记录
  → 输出与当前活环内容字节一致（§3-E2：活 PIT 值两次注入用户页）
[受害] 被写页已被复用：用户 anon 页（绊网活捉）/已释放内核页（死后写入）
  → 污染块落在任意数据结构上，按形状表现为 va_list 崩溃/NULL 解引用/
    .bss 指针损坏等不同签名（全家桶"看起来"是多个缺陷，实为一个机制）
[排除] AP 驱动映射路径干净（§3-E5：1465 次映射零坏页）；
  活 BAT/PIT 表与全部 dpmaif 寄存器零陈旧（§3-E4）
```

## 2. 已验证判据（照抄使用，不要自己发明）

### 2.1 注入块签名（识别新 core/现场用）

- 16B 块 `{small, 0}`：small ∈ [0x2710, 0x40000] ∪ {0}，非单调；
- 32B 块 `{small, 0, 0x????????_0000_06xx, 0}`：低 32 位落在 0x6xx/0x1180 族；
- 同页可多块（16B 节距）；页尾 0xfc0 起（word 504+）高发；
- **禁止用 magic 值当指纹**：`0x1c28416e00000680` 等高 32 位在现场间会变，
  只能作个案旁证（曾在 6 处/4 个独立构建重复出现）。

### 2.2 va_list 健康判据

- 三个指针字段（`__stack/__gr_top/__vr_top`）落在用户态可访问范围；
- **`*_offs == 0` 不是坏值**：第 9+ 个变参正常走 `__stack`（musl pop_arg
  0x51e8c：`gr_offs>=0` → 走栈）；旧判据"两个 offs 都为负才健康"会误判合法
  长参数列表；
- 健康基线（实测）：`{栈地址, 栈地址, 栈地址, -48, -128}`。

### 2.4 内核 fault 行读法

arm64 是 `unhandled exception: DABT`，`[base+size]` 是**故障指令所在 VMA**
不是故障地址；dmesg 会被 printk 限流吞行（fault 计数须以 aee 增量为准）。

## 3. 写入者身份（坐实，2026-10-22）

**写入者 = 蜂窝 MD 固件经 DPMAIF 的 RX DMA（活体）**——它参与当前环维护
（输出与活环同源），只是写目标（缓冲页列表）是陈旧的。

| # | 证据 | 结论 |
|---|---|---|
| E1 | injwatch4 全程 38min 报 **21 次命中**，全部页尾 0xfc0/word504-505；受害页实测 `st=1`（PageAnon）、rcnt=1、mapping 带 ANON 位 | 注入持续可复现；受害页是用户页 |
| E2 | 活 PIT 环页尾（0x90800000+0xfc0）内容 `{0x92d7a600,0}{0x92d79e80,0}…` 实测在案；**0x92d7a600 两次被原值注入两个不同用户页** | 写入内容=当前活环记录 ⇒ 写入者是活体环维护者（MD/DPMAIF RX） |
| E3 | 16B 记录 `{0xe7e0f000,0x80000000,0x30000000,0xa}` 持久存在于已释放的 findpa staging 页（其余内容是 ELF 残影）；记录本身引用另一受害页 0xe7e0f000 | **释放页死后写入**；环记录引用已释放缓冲（与 §4-A5 的 `{PLEN0=4096,DONE=0,ptr→受害页}` 环条目同族） |
| E4 | 受害 PA（0xe5e86000/0xe7e0f000/0xec12c000）全 RAM 段扫描（0x80000000–0xf0000000，含全部 MD 保留窗）**零引用**（除自匹配与注入记录本身）；7 个 dpmaif 寄存器窗清点**无受害 PA、无陈旧环基址**（只有当前基址及其镜像）；**`AT+CFUN=1,1`（MD 完整复位）后注入 1–2 分钟内恢复** | 陈旧列表/其重建机制在 **MD 侧或 DPMAIF HW 内部**，AP 读不到、MD 复位也只暂停 1–2 分钟——运行期持续重建 |
| E5 | 三个 dma_map 调用点挂 shim 45min：**1465 次 TX 映射零坏页**（全是合法 kmalloc slab skb 数据）；RX/frag 0 次；剧集全程环基址稳定 | **AP 驱动重映射陈旧页被反证**；"驱动交页"假设作废 |
| E6 | findpa 全 RAM 扫描会命中扫描器自身内核栈（vprintk+112 返回址 + `{pa, pa\|0x7ff}` 相邻重复 + 0xffffffc0… 栈指针） | 仪器自匹配特征（曾导致"驱动在栈上构造描述符"误判，已撤回） |
| E7 | ~~ABAB：阻断 `ttyCMIPC6` 端口 churn 15min，注入率 1.36→0.41/min~~ **⟦v1.1 轮复测撤回**：同法复测（2026-10-22 20:26–20:33）注入率不降反升（1.4→2.3/min）——首轮 3–4 倍下降是剧集相位方差，非因果。**端口 churn 与注入无因果关系** | （结论：端口开合不是泄漏源；活跃源见 §8.6） |

**排除清单**（内容形状/行为学，均实测）：eth0/mt7530（无 MAC 头、非偏移 0）、

## 5. 受害者生态与缓解定性

### 5.1 选集效应

污染块落在进程内存任意位置，多数落点无人解引用；printf 的 pop_arg 是全系统
最高频的解引用点，所以全家桶"看起来"是 libc 缺陷。`-l 200` 降幅、纯字面量
不崩、自有可变参数"不崩"（解引用点少一个量级）由此统一解释。

### 5.2 已落地缓解（保留+冻结，§22 口径）

| 项 | 实测效果 | 定性 |
|---|---|---|
| logc v1.4 去 printf | 7 崩/h → 0（A/B 10:0） | 保留：摘掉最高频解引用点 |
| logcut 替换 awk | 18.4/d → 0 | 保留：少 spawn+无大数组堆页 |
| procmatch 替换 pidof/pgrep | 2.7/d → 0 | 保留（另修 busybox pgrep -x 真 bug） |
| P2 静态工具链农场 | **崩溃零改善**（静态件同崩） | 保留但**冻结**（F1：不再为治崩溃扩面）；退役须根修验收后两臂 A/B |
| core_trap/core_meta、watchdog aee 增量判据 | 证据管线有效 | 保留 |
| `ap_auto_logging=0` 护栏 | 防 logread -f 常驻复活 | 保留（红线） |
| hardened vfprintf（guard 拦截） | 技术有效但 guard 误伤 gr_offs=0 合法态 | 归档不部署 |

**冻结规则**：F1 不再为治崩溃新增用户态替换；F3 文档/注册表不得再把 musl/
awk/pidof 写成缺陷根因；gw 侧无崩溃修复主线，主线=§8。

### 5.3 运营注意

- dropbear 高频 spawn 会卡死（accept 后 EOF/无 banner，不可恢复，只能
  `sys_reboot`）——取证脚本限并发、结果落 /data；
- 取证探针自身崩溃会进 ne_events/aee 台账，普查按 §2.3 规则扣除。

## 8. 修复主线：dpquarantine（页隔离内核模块）

### 8.1 设计（为什么是它）

- MD 侧列表 AP 不可达（E4）⇒ **修不了写入者，只能切断"被写页进入复用流"**；
- memmap 预留（LK cmdline）：依赖"失效 PA 跨重启稳定"，与观测（受害页随
  剧集滚动、分布跨 175MB）不符——**降级为兜底**；
- stop-path leak-on-timeout（A6 顺序缺陷）：只覆盖 stop 窗口，实测注入发生
  在无 stop 的稳态（基址 1h 不动）——**单用不足，降为辅助**。

### 8.2 方案

`dpquar.ko`（源码 `gw/src/dpquar.c`，调用点补丁机械与 dphook 同款、已验证）：

1. 钩 dpmaif 的 `dma_unmap_page_attrs` 释放点（6 处，站点表见源码），shim 在
   原调用前对 `dma_addr`（=PA，无 IOMMU）解析页，`get_page_unless_zero` 加
   引用 → 页不回 buddy，入隔离表；
2. 策略：在押 TTL（默认 24h，`hold_s`）+ 总量上限（默认 4096 页/16MB，`cap`），
   FIFO 逐出——**有界**，无 OOM 风险（队列稳态长寿命，隔离事件罕见）；
3. 观测面：每站点计数（调用/隔离/逐出）+ 在押页页尾监视（**writer-hit =
   在押页被写次数——修复有效性与机制命中的直接验收读数**）+ /proc/dpquar；
4. 站点启用按位掩码（`qmask`）：teardown/错误路径（冷站点）默认隔离，每包
   路径（热站点）默认只计数——防隔离洪水；
5. rmmod：先还原补丁、msleep 让在飞 shim 退出、逐出全部在押页。

### 8.3 验收口径（§22.7 原则）

模块在位 + 补丁点命中计数 + **writer-hit>0 证明机制命中**；injwatch4 剧集期
用户页命中 → 0。**装后残余属预期**：已被 MD 列表持有的存量页会继续被写，直到
MD 列表自然失效/MD 重启——残余期"只降不零"，文档化。崩溃率只作旁证（26/d
基线下 7 天期望 182 次，统计判据不敏感）。两臂 A/B（开/关各 7 天）后才谈
农场退役（§5.2）。**（2026-10-23 更新：两臂观察经操作者决定取消，依据与
收尾见 §8.4；农场退役待定。）**

### 8.6 活跃源定性（已解决，2026-10-22 深夜轮）

v1.3 实测排除 + 三轮新仪器后，**活跃源已定性并压制**：

**排除**（全部实测锚点）：
- dpmaif 全 10 站点在押零命中时注入仍 ~2/min → 交接不经 dpmaif dma 路径；
- **环本体**：ktext 全文 cci/dpmaif **零 `dma_free_attrs` 调用点**——环只分配
  （bat_init+0x60/late_init+0x348）不释放（每次队列重建泄漏性保留），永远不回
  buddy，当不了受害页；
- **cci_ipc/ILM**：`ccci_ipc_send_ilm` 为拷贝进 skb 路径，不交 PA；
- **端口 churn**：E7 复测撤回（无因果）。

**buddyscan 定性**（自底向上：扫 buddy 页注入签名，buddy 页保留前属主内容）：
- 陈旧列表人口直接可见：**~400 个固定 PA 的 4K 页集合**（6 min 内 distinct=402、
  192 个 ≥5 次重现、单页最高 113 次；45s 窗口 44 进 44 出 ≈1 页/s 被写）；
- 记录形态：**同值记录喷多页**（`{0,0x5e,0}` 族与 `{6,0,…,0x70014,0}` 族），
  非逐槽异值的环游标——状态/广播类写入；
- 成员页除尾部记录外**内容全零**（ex-anon/零填页）；前属主考古因此不可用；
- 4 个稳定成员 findpa 交叉：全部为扫描器自匹配（§3-E6 特征）——**AP 侧零引用，
  列表在 MD 侧私有持有**，与 E4 一致；跨 MD 温复位存活（CFUN=1,1 后 1–2 min 恢复）。

**关键盲区发现（migrate 类型）**：列表成员是 ex-anon 页，位于 **MOVABLE 迁移
链表**；`GFP_KERNEL` 分配只从 UNMOVABLE 链表取页——dpclamp v1.0 用 GFP_KERNEL
**147K 次采样零命中**（同期 buddyscan 每轮 ~47 张签名页）。这是此前一切"抓不到
交接"的分配侧原因。换 `GFP_HIGHUSER_MOVABLE` 后立即命中。

### 8.8 原厂对照：为什么纯原厂"不发病"（2026-10-23 逆向轮）

证据源：2026-09-29 纯原厂全盘备份（RP0102，slot b 出厂态）+ rp103 官方镜像
解包（rootfs/kernel/lk/md1img）+ 运行实况对照。结论：**原厂没有任何绕开该
机制的刻意设计，同一 bug 在原厂处于"低暴露 × 零观察"的静默态。**

- **机制原厂同样存在**：双槽共享内核——运行内核与 rp103 官方内核版本串逐字符
  一致（5.15.134，2026-09-09 厂商 CI 构建；刷机管线只写 p26 rootfs）；
  md1img 分区从未改动（MOLY.NR16.R2.MD800.MP.V86.P40，2025-12-04）。
  写入者三件套（MD 固件 + DPMAIF + 驱动）在纯原厂一模一样。
- **原厂 MD 自身偶发致命异常**：出厂 3.3 个月（2025-06-14 → 09-29）aee 仅
  2 条记录且均为 MDEE（09-16 MSONIC0/DSPNR1s 0x12；09-17 MCU_core1 task
  fatal 0x0C0B）——每起 MDEE→MD 复位→正是同一条 teardown 泄漏路径。原厂
  把 MD 复位当日常静默自愈（mtk_netagent `watch modem_reset`+respawn、
  ccci_mdinit procd respawn、zmtk_boot_done A/B 簿记）。
- **零刻意防御（全树实扫）**：rootfs 全树 `emi|mpu` 零命中；ko_install.sh
  仅装 USB 串口/ebtables 模块；crontab 空；无任何内存护卫守护。所谓"防御
  设计"只有 mtk_mem 的 zram（=50% free, lz4, swappiness=100）——但本固件
  同配（/proc/swaps 实测在跑）且无压力时 Used=0，"swap 换入覆盖自愈"假说
  排除。
- **不显症的乘法拆解**：① 暴露面——原厂 ~40 个长寿守护，spawn 率低于本
  固件守护动物园约两个数量级（NE 需毒页恰好被新进程分到并触碰污染偏移，
  census 受害者全集为本固件静态工具链即选集效应）；② 观察面——原厂守护
  RLIMIT_CORE=0（镜像默认值，rc.extend v2.2 注释实证），进程 SEGV 不进
  core_pattern → aee 零记录，"零 NE"是盲区不是事实；③ 事件面——开发期
  人为 MD 复位（CFUN=1,1 压测 49373 次 teardown）远超原厂自然率
  （3.3 个月 2 起）。

### 8.9.3 遗漏/缺陷清单

结构性遗漏（残余率的成因，非回归）：

- **S1 阶层盲区**：order-0 采样只见本 CPU pcp+order-0 热池；签名页与空闲伙伴合并入
  高阶块后不可见（且 order-0 非空+NORETRY 下采样不触发分裂），直到分配压力拆块才
  重新暴露。
- **S2 SMP 可见性**：system_wq 单 CPU 执行，1024 次 alloc/free 在同一 pcp FIFO 里
  循环同一小池（alloced=122880 而独立可见池 ~10³ 页量级）；其他 CPU pcp 不可见。
- **S3 UNMOVABLE 成员嫌疑**：本轮 buddyscan 考古字段（a8）见内核指针残影成员——
  若属 UNMOVABLE 迁移链，GFP_HIGHUSER_MOVABLE 采样永不可见（§8.6 migrate 盲区的
  反方向）。
- **S4 原位投毒不可防**：写入者对 PA 直写不问分配状态；页在持有时被写=原位损坏
  （E1 本质）。dpclamp 只能压缩"自由态可见存量"，压不掉分配态命中。
- **S5 无剧集反应**：idle 退火到 60s 巡检，剧集窗口内新签名页要等下一轮 sweep；
  首 NE 后无任何加速——滴漏与簇的共同窗口来源。

实现缺陷（dpclamp v1.2 源码级）：

- **D1** `test_and_hold` 存 digest 时 `t[3]` 被 XOR 两次（t[3]^t[3]=0）≠ watch 用的
  `tail_digest()`——首轮 watch 对 t[3]≠0 页产生伪 writer-hit（whits 污染一次后自愈）。
- **D2** watch 每轮只扫 ctab[0..255]——held>256 后尾部页永不监视（cap=8192 下必发）。
- **D3** 签名窗只认末 64B 的 t[0]/t[1] 两个 16B 槽位——记录单独落在 0xFD0/0xFD8 的
  页漏判（本轮 65 页宇宙未见该形态，风险降级但存在）。
- **D4** 无 /proc 写接口、无 episode 台账——触发与运维反推都无处落。

测量面缺口：**M1** ne_events 有 104 行 epoch 无效行（pre-NTP 落账）+ 多行 args 破坏
TSV 结构（boot 窗口 NE 不可统计）；**M2** 开机自载在 syslog/dmesg 零留痕（本 boot
grep=0，只能靠 lsmod 事后确认）；**M3** logread 单发崩溃 6 起/天，spawn 方未定位；
**M4** 两臂对照取消后无压制效果基线，只能对 10-20/21 的 25.8–44.2/d 口头对比。

**结论**：dpclamp 的机制与方向成立（持续收敛、无 KE 复发、内存稳态），残余率是
"覆盖=单 CPU 热池 + 反应=固定周期"的必然结果。下一轮方向=事件反应+深度遍历（§8.10）。

## 8.10 下一轮方案设计：dpclamp v1.3（剧集反应式 + 深度排空）【已实施，见 §8.10.3】

> 设计原则：F1 冻结不变（不新增用户态替换）；内核改动限定 dpclamp 本体 + 一个
> /proc 写接口 + core_meta 一行触发；dpquar 不动；v1.2 可随时 rmmod 回退。

1. **深度排空（deep drain，主武器）**：两阶段遍历全部 buddy 空闲链表（全
   order × 全 migratetype，不问 S1/S2/S3 的阶层与类型）——
   阶段一（持 zone->lock）：仅摘链表头页指针入本地有界数组，不读内容（锁窗目标
   <5ms/zone）；阶段二（无锁）：读页尾签名；命中页重取锁复核（PageBuddy 仍在 +
   签名仍在，容忍竞态）后按 rmqueue 语义整块取下、释放无签名兄弟页、仅扣住签名页
   （order-N 块按 2^N 记 cap）。依据：buddyscan 已在生产反复实证该遍历安全（本轮
   5×23624 页零异常）。pcp 仍由 burst 覆盖（pcp 无稳定遍历面）。
2. **触发器三路**：
   - T-a 内核：whits delta≥1 → deep+burst（前置修复 D1；剧集期写入者每秒级重写
     集合，检测延迟≈1 个 watch tick）；
   - T-b 用户态：core_meta v1.1 在 exec aee 前追加 `echo deep > /proc/dpclamp`
     （/proc 已 0666）——**NE 即探测器**，零内核风险，覆盖"whits 未鸣而 NE 先至"
     的窗口（受害者生态保证每个剧集至少一次 NE 可供触发）。模块侧冷却 300s 合并
     同源触发；deep 命中 ≥8 签名页才升级 burst（NE 探测默认只买 deep 的 ~1s，
     不买 burst 的 90s）；
   - T-c 开机：insmod 后立即 deep×1 + burst 90s（= §8.4 备案未实施的预热排水，
     覆盖 04:00 定时重启后毒页跨重启流转窗）。
3. **burst 模式（次武器，覆盖 pcp 热池）**：batch=1024 背靠背（sweep 完成即续；
   实测 1024 批 wall 2.5–8s → 90s 场 ≈11–30 轮、11–30K 页采样；4096 为参数上限
   不作缺省），时长 ≤90s、有 clamp 续期、硬帽 10min；NORETRY/NOWARN/minfree/
   cond_resched 全继承；连续 3 轮空 burst 提前终止。与 KE#3 的本质区别：事件驱动
   有界 vs 固定周期无退火。
4. **SMP 轮转**：sweep/deep 间轮换 kthread CPU 亲和性（4 核轮转），覆盖各 CPU pcp
   （关 S2 的采样侧）。
5. **缺陷修复**：D1 双 XOR；D2 watch 改滚动游标；D3 签名窗扩到 t[0..3]（单块命中，
   other-count 判据不变）；D4 /proc 增 episodes/bursts/deeps/last_trig 与触发来源。
6. **配套测量面**（非 dpclamp 本体）：core_meta v1.1（args 去换行、epoch 无效标
   `unsync`，关 M1）；自载与触发留痕写 /data/gw/logs/fixstack.log（关 M2）；
   logread spawn 方定位一轮（M3）。
7. **边界（不做并明示）**：不 hook 分配路径；S4（分配态原位投毒）不可防——残余
   下限存在；deep 只在事件触发/手动时执行，不进任何热路径。

### 8.10.1 性能预算（实现前分析）

——pcp/zone 锁接触均为微秒级窗口，且已被强制扫描 A/B 的负载类覆盖。

### 8.11 T1 定时排空 + T3 跨启动集持久化（2026-10-25 下午部署, dpclamp v1.4）

> 背景：10-25 白天实测残差 0.66/h（04:00–11:37, 5 起自然 NE = 4 个反应剧集,
> 反应链每次闭环但总慢一拍）。机理定位（§8.10 模型细化）：NE = MD 写**已分配**
> 页；空闲 buddy 里的签名页是"上膛的枪"——sweep 只见 pcp（1024 页/次）, 只有
> deep 全量走能拆除, 而 v1.3 的 deep 只在剧集后跑 = 每把枪都要等下一个受害者
> 触发。决策（操作者批准三件套）：守护面加固 + T1 + T3 探查。守护面加固见
> AVAILABILITY_DESIGN §8.1.1（NE 假红修正）与 healthdog v1.6。

**T1 定时 deep（deep_every_s=60, 0=off）**：kthread 定时全量 buddy 遍历,
把签名页在"空闲可见期"内拆除, 暴露窗压缩到 ~1 分钟。成本实测 95–101ms/次
≈ 0.3% CPU, zone 锁窗 ≤288µs（10 次定时 deep 实测, sched 计数按 60s 前进）。
预期: 剧集簇（同窗 2–3 连发）→ 单发; 残差率进入"只有首写即分配类"的地板。

**T3 PFN 种子（确定性清零路径的探针+工程本体）**：
- `/proc/dpclamp_seed`：流式 hex PFN 喂入（跨 write() 分块安全）, 每页 O(1)
  buddy 夺取（PageBuddy 头判定 + list_del + rmqueue 同款会计 + split + 持有
  目标页/释放兄弟页）, **无签名要求**——成员资格由既往 boot 的签名背书。
- `/proc/dpclamp_pfns` 导出持有集; log_keeper v2.10 每 5min 收割：union 文件
  `/data/gw/dpclamp_pfns.txt`（喂下次开机）+ 每 boot 快照
  `logs/dpclamp_pfn/<boot_id>.txt`（跨启动集合 diff 证据, held 数变化才重写）。
- rc.extend v2.9：dpclamp insmod 后立即喂 union（守护动物园拉起前）。
- **假设**：MD 陈旧集跨启动稳定（旁证：两次 Boot warm-up deep 同为 95ms/百余
  页量级）。若成立 → 开机预抢 = 集合成员永远到不了受害者手里 = 确定性近零,
  无"每 boot 首发税"; 若不成立 → 围堵维持（定时 deep 兜底）。
- **判读法（每个 04:00 boot, fixstack.log `seed:` 行）**：`fed=N ok=K dup=D
  miss_nb=M`——ok/(fed-dup) 比例高 = 集稳定; miss_nb（分配中/块尾; 新 ctab
  上 dup≈0）高 = 集漂移。结合当日 NE 率终判。
- 首次实弹（13:2x 手动喂本 boot union 307 PFN）：fed=307 **dup=307** 零副作用
  ——解析器/查重链验证 ✓。注：miss_nb 计数把 dup 也算入（返回值同路）; 开机
  时 ctab 为空故 dup≈0, 判读语义不受影响。
- 已知偏差：seed 会计用 MIGRATE_MOVABLE（分配侧同款语义; 页块级
  get_pfnblock_flags_mask 未导出）。唯一漂移是顾问计数 NR_FREE_CMA_PAGES
  （若种子页恰在 CMA 页块）; free_pcppages_bulk 会按真实页块 mt 归位释放页。

（get_pageblock_migratetype → get_pfnblock_flags_mask）, insmod 失败; 且热换

### 8.12 Phase 2 两臂判决协议（预登记，2026-10-26）

> **本节是预登记**：判据在看任何 A/B 数据之前写定。事后不得修改本节判据；
> 若必须改，另开一节说明理由并保留本节原文 —— 这是 2026-10-25 复核得出的
> 唯一纪律结论：§8.9.1 的「无台阶下降」正是先有数、后找说法的产物。

**为什么必须两臂，而不是「放一周看看」**

P0 改变了观测口径：logc 自崩在 v1.5 之前根本不进台账（`_exit` 绕过
`do_coredump`），现在会进。因此 **P0 之后测到的率天然高于历史数字** ——
不是因为变糟，而是因为能看见了。任何「新窗口 vs 历史 27–50/d」的对比都是
无效对比。唯一有效设计：在同一套仪器下先测 A 臂，再测 B 臂。

**主指标**

全部 NE / 24h（按排除规则扣除后）。分母 = 窗口实际小时数折算 24h；报率时
分子、分母、口径必须同时给出。`origin` 列（our-tree / vendor-tree /
unknown）**只作诊断分组，不参与主判** —— 「ip 命令崩了」对用户就是服务受损，
不因调用者是谁而免责。

**排除规则（缺一不可；1–5 与 §2.3 一致，6 为本节新增）**

1. 每 boot 后前 10 分钟不计（boot 窗口，core_meta 链尚未就绪）；
2. `args` 含 `kill -SEGV`（自测注入）；
3. `comm=?` 且 `exe=?`（进程已回收，不可归因）；
4. `exe` 前缀 `/tmp/pf_*`、`/tmp/v_*`、`/data/p0*`、`/data/repro/*`（自建探针）；
5. `args` 含 `busybox awk`（复现循环）；
6. **新增**：`args` 含 `avail_hourly.tsv` 的 awk 行（`api_avail.sh` 的 GUI 聚合
   自崩；v1.2 起已改纯 shell，此规则只用于剔除历史行）。

**两臂协议**

| 臂 | 配置 | 最短 | 建议 |
|---|---|---|---|
| A（当前） | `FIXSTACK_ENABLE=0`，内核修复栈不加载 | 3 天 | 4 天 |
| B | `FIXSTACK_ENABLE=1`，dpquar + dpclamp 加载 | 3 天 | 4 天 |

- 臂间切换用 reboot 完成，以每日 04:00 定时重启为自然边界（`reboots.log` 有据）；
- 每臂须覆盖 ≥3 个 04:00 周期，且每日数据无 >2h 缺口；
- 窗口期间禁止手工 SSH 干预与高频 GUI 轮询 —— 二者都会注入额外崩溃
  （§8.9.1 的 41 条自噪声即此教训）；确需访问时在 `ne_window.tsv` 记一行。

**判决规则**

1. **默认判「无收益」**：修复栈必须自己证明有用，而不是我们去找它有用的证据。
2. 判「有收益」须同时满足：B 臂相对 A 臂的 24h 率下降 **≥30%**；两臂各 ≥3 天；
   每日数据完整（无 >2h 缺口）。
3. **安全条款（优先于统计）**：任一 boot 的 pstore 回溯点名修复栈符号
   （`dc_main` / `run_deep` / `grab_cand` / `process_block` / `dpclampd` /
   `quarantine_page`）→ 立即判**退役**，不必等窗口跑完。
4. 数据不足（时长或完整性不达标）→ 判「未定」，**不得**判「有收益」。

**窗口锚点**

设备侧 `/data/gw/logs/ne_window.tsv`，制表符分隔一行：

    <epoch>\t<boot_id>\t<当时 ne_events 行数>\t<臂 A|B>\t<备注>

该文件不进任何消费方解析；`ne_events.tsv` 格式不动 —— 往里加哨兵行会被
按行数/sig= 解析的消费方当成一次真实崩溃，反而污染刚要干净的基线。

**已知混淆变量（解读时必须声明）**

- GUI 可用性页轮询频率（v1.2 前每次轮询跑一段会崩的 awk）；
- 每日 04:00 定时重启（`reboot_sched.sh`），非异常；
- 剧集簇：单次剧集可 6 分钟内连发 12 起，单日率方差大，故需 ≥3 天；
- 环境因素：蜂窝/WAN 无上游时 `boot_gate` 判 degraded，与 NE 无关。

**复核方式**

按上述 6 条排除规则对 `/data/gw/logs/ne_events.tsv` 逐行复算；本机存有复算
脚本 `tmpfiles/sigsegv_audit/verify_rate4.py`（仓外，按 oneoff 纪律不入仓），
任何人都可据本节规则重写一遍并对照。
### 8.13 旧修复栈退役（2026-10-26）

**结论**：`dpquar` + `dpclamp` 这一栈整体退役，源码、产物与构建脚本同批从仓内删除，
可经 git 历史取回（`gw/src/dpquar.c`、`gw/src/dpclamp.c`、`gw/bin/dpquar.ko`、

### 8.14 新方案尝试一：牺牲页池（设计 + 负结果，2026-10-26）

**设计依据（来自 §8.6 的 buddyscan 定性）**

MD 的陈旧列表是 **~400 个固定 PA、不增长**的页集合，成员是 ex-anon 零填页、
位于 **MOVABLE** 迁移链表，45s 窗口 44 进 44 出 ≈ **1 页/s 被写**。既然列表固定，
理论上的根治就是**把这 400 页永久扣住**——写入落在无人读取的内存里。

**实现**：`tools/oneoff/printf_repro/sacpool.c`（纯用户态，无内核模块）
—— mmap 一块 anon 内存并逐页 touch，强制内核分配 MOVABLE 页（与陈旧页同迁移类型），
然后长期持有、每 30s 重 touch 一次，**永不读取内容**。撤池即整块 munmap。
选择纯用户态而非内核模块，是因为它不可能把设备搞死——而旧栈的三次故障都是内核级。

**实验**：A-B-A-A 四块各 20 轮，指标为 pfcanary 的 TTC（秒）：

| 块 | n | 均值 | 中位 | 标准差 | 60s 截断 |
|---|---|---|---|---|---|
| P0 基线 | 20 | 21.84 | 20.09 | 18.05 | 2 |
| P128（池 128MB） | 20 | 20.51 | 7.45 | 22.43 | 2 |
| P256（池 256MB） | 20 | 23.94 | 13.59 | 24.72 | 5 |
| P0b 基线 | 20 | 8.06 | 1.49 | 14.11 | 0 |
| P0c 基线（撤池后补测） | 20 | 16.67 | 11.15 | 18.41 | 2 |

**结果：未证明有效。**

- 无单调剂量-反应：P128(20.51) < P256(23.94)，但 P256 相对基线 +60% 的 t 仅 1.45；
- 相邻两块基线的差异 **−13.78 s（t=−2.69）**，比任何"效果"都大；
- 补测 P0c 回到 16.67 s，与 P0 无显著差异（t=−0.90）→ **P0b 的下探是瞬时漂移，
  不是池子留下的持续效应**。

**方法学结论（比结果本身更重要）**

pfcanary 的 TTC 在 **5–10 分钟尺度上自身摆动 2.7 个标准差**（均值 8–22 s）。
这意味着：

1. **块级 A-B 设计在本指标上无效**——块内漂移与块间差异同量级，n=20 无法分辨
   小于约 2 倍的效应；
2. 任何短于漂移周期的对照都必须**逐轮交替**（每次运行换臂），而不是分块；
3. 这也解释了 §8.12 为何坚持 ≥3 天/臂：长窗口平均掉的正是这个漂移。

**对 §8.12 的影响**：快层目前只能可靠地**否决巨大效应**（例如"修复后完全不再崩"），
不能分辨 30% 量级的改善。要分辨小效应，必须改成逐轮交替设计。

**当前状态**：旧栈已退役（§8.13）；牺牲页池**既未被证实也未被否决**，不纳入生产，
保留在 oneoff 供后续用逐轮交替设计重测。


### 8.15 新方案尝试二：直接测量（buddyscan）+ 牺牲页池被证伪（2026-10-26）

**换仪器：从赛跑指标换成确定性计数**

§8.14 的 TTC 指标噪声太大（基线块间摆动 2.7σ）。本轮改用项目已有的
`/data/repro/buddyscan.ko`（§8.6 的定性数据即出自它）：

    /proc/buddyscan → scans=N buddy_pages=.. signed=.. hits_now=..

`hits_now` = **当前 buddy 空闲链表中带注入签名的页数**。实测噪声：

- 连续 12 次扫描：`hits_now=48` **全部一致**；
- 6 分钟观察窗（18 次采样）：恒 48，仅两次瞬时 42/44。

**噪声≈0**，与 TTC 的 8–22 s 摆动不可同日而语。这回答了"静默/换仪器能否
降噪"——能，而且靠的是换仪器，不是靠静默设备。

**牺牲页池实验（§8.14 的方案）**

池子 256MB 实测确实分配并持有（MemFree 1295424→1033512 kB，65536 页），
释放后干净归还。持有一整 6 分钟，逐 20 s 采样：

| 时刻 | T0 | T4 | T5 | T6–T18 | AFTER |
|---|---|---|---|---|---|
| hits_now | 48 | 42 | 44 | **48** | 48 |

**结论：牺牲页池被证伪。** 持有 256MB 空闲页 6 分钟，签名页人口毫无变化。

**根本原因（比结论本身重要）**

buddy 里那 ~48 张签名页是**无害子集**——它们空闲、无人使用，写入落在没人读的
内存里。真正危险的是 MD 列表中**已被活进程持有的那 ~350 张**（§8.6：列表总人口
~400，任一时刻约 48 张处于空闲态）。池子只能拿空闲页，**结构上碰不到危险的那部分**。

由此得出两条推论：

1. **"扣住空闲页"这一整类方案都不可能奏效** —— dpquar（teardown 隔离）、
   dpclamp（采样扣留）、sacpool（大池持有）同属此类，全部被同一条理由否定。
   这解释了 dpclamp "排空存量"路线的必然失败：**污染是稳态过程，不是可耗尽的存量**
   （§8.6：44 进 44 出，自维持）。
2. 修复空间因此收窄为三条，且都不轻松：
   - (a) 停掉 MD 的写入 —— 写入者在 MD 固件侧，**AP 侧不可达**（§8.7）；
   - (b) 让受害者容错 —— 重试/加固解引用点，属缓解不属根治；
   - (c) 检测并修复**活页** —— 需周期扫描在用的用户页，代价与误伤风险都高。

**当前状态**：旧栈已退役（§8.13）；sacpool 与 injcount/injdiag 保留在 oneoff
供后续参考，**不纳入生产**。buddyscan 是本轮唯一被确认有价值的资产——
它是可用的低噪声仪器，只是它测的量（空闲签名页人口）已被证明与"危险面"不重合。


### 8.16 新方案尝试三：用户态自检可行性评估 + 重新设计（2026-10-26）

§8.15 排除了"扣住空闲页"整类方案后，剩下的候选是 (c) 检测并修复活页。
本节回答一个更基本的问题：**坏页在用户态到底能不能被看见？**

**测试一：长期持有的页会被写吗？（injcount）**

分配 64MB、逐字写入已知图案、等 20 秒、统计被改动的页：

    pages=16384  modified=0   （8MB/5s 同样为 0）

**结论：不会。** 污染不落在长期持有的内存上——这与 §8.15 一致：
陈旧页是**新分配**的页，不是老页。

**测试二：崩溃那一刻，注入值在不在现场？（faultprobe）**

与 pfcanary 同样的 snprintf 循环，但装 SIGSEGV 处理器，记录故障地址、
SP、以及栈映射区内命中注入签名的位置。6/6 全部捕获（剧集期）：

| 故障地址 | 对应 §2.1 形态 |
|---|---|
| `0x28416e00000640` ×3 | 32B 块 `0x????????_0000_06xx`（低 32 位 0x640 在 0x6xx 族） |
| `0x1698c` | 16B 块 `{small,0}`，small ∈ [0x2710,0x40000] |
| `0x13917` | 同上 |
| `0x10a65` | 同上 |

**故障地址就是被注入值覆盖后的 va_list 指针**——两种形态与 §2.1 的签名定义逐字吻合。

**可行性判决**

1. **周期自扫（持有页）不可行** —— 测试一证明污染不落在老页上；
2. **故障点可观测，因此"解引用前校验"可行** —— 测试二证明被污染指针的取值极其离谱：
   aarch64 上合法栈指针是 `0x7fxxxxxxxxxx` 量级，而注入值是 `0x1698c` 这种
   或 `0x????????_0000_06xx` 形态。**一个地址范围检查就能拦住**。

**重新设计：解引用前的指针合理性闸门**

不做周期扫描（太慢、覆盖不到短命进程），改为在**解引用点**加一道极廉价的检查：
若 va_list 指针不在进程已映射区间内 → 判定为污染，返回错误而不是解引用。
进程存活，调用方拿到一次格式化失败。

实现路径：项目已有 `layerchk`（可单独编译 musl `vfprintf.c` 并显式链接在
libc.a 之前覆盖同名符号，README 记载"未打补丁仍崩 → 覆盖链有效"）。静态农场
的工具（busybox/iproute2）正是需要覆盖的对象。

**必须说清的三条限制**

1. 这是**缓解不是根治**——污染仍在，只是不再把进程打死；
2. 只覆盖 printf 解引用路径。§1 说 printf 是**最高频**路径（选集效应），
   但不是唯一路径；非 printf 形态的污染（NULL 解引用/.bss 指针损坏）拦不住；
3. 污染是**剧集式**的：本轮实测同一设备在剧集期 10/10 崩、平静期 0/5 崩。
   任何验证都必须落在剧集窗口内，否则测到的是"零"而不是"有效"。

**待办**：部署 hardened vfprintf 并用 §8.15 的 buddyscan + 剧集期 pfcanary 双指标验证。


### 8.17 剧集触发条件调查：两个假设均被否定（2026-10-26）

§8.16 的重新设计依赖一个未验证的前提——剧集何时发生。本节做触发条件调查。

**先挖已有台账（零设备交互）**

`/data/gw/logs/ne_events.tsv` 全量 548 行，按 §2.3 排除后 **285 次**崩溃，
跨 6.6 天。结构：

- 到达间隔：中位 **478 s**、均值 1998 s、p90 **5557 s**、最大 **40107 s（11 小时）**；
- 间隔 <10 s 的 **49 次**、>600 s 的 **137 次** → **双峰**：要么成串，要么孤立；
- 按 gap>300 s 切分得 **154 个剧集**，其中 ≥5 次崩溃的 **10 个**；
- 大剧集：持续 **中位 420 s**（35–891 s），间隔 **中位 3900 s**（402 s–60 小时）。

剧集是真实且成形的对象，但触发条件未知。

**假设一：AP 侧页分配突发（mmap churn）**

依据：A7（受害者＝新页获取率高的短命进程；长命探针 0 命中）+ §8.14 中误启
injwatch（128 MB 翻腾）曾伴生 106 秒 13 次崩溃 + injcount（长持页 20 s 0 命中）。

实验：A / B / A 各 8 样本（每样本 pfcanary 25 s 封顶），B 相做 8×128 MB 分配并各持 20 s。

| 相位 | CRASH | TIMEOUT |
|---|---|---|
| A1 平静 | 1/8 | 7 |
| B churn | 2/8 | 6 |
| A2 平静 | **3/8** | 5 |

**否定**：崩溃数 1→2→3 是随时间单调上升，A2 平静相反而是最高 —— 漂移盖过效应。

**假设二：进程 spawn 突发**

依据：一次大 mmap 与 500 次 exec 是不同形状——陈旧 PA 只有当它被发成某个进程的
新栈页时才致命。故改用 spawn 突发（500 次短命进程）。

| 相位 | CRASH | TIMEOUT |
|---|---|---|
| **A1 平静** | **5/6** | 1 |
| B spawn 突发 | 2/6 | 4 |
| A2 平静 | 2/6 | 4 |

**否定**，且方向相反：第一个平静相位崩溃最多。

**结论**

1. **两个 AP 侧触发假设均不成立**；剧集触发条件仍未识别；
2. 两次实验合计约 25 分钟里，设备恰好经历了一次剧集结束（5→2）与一次剧集开始
   （1→3）——**相位间差异远大于任何人为操纵效应**；
3. 因此：**在不知触发条件的前提下，无法用短时对照实验控制变量**。这不是实验
   设计的问题，是对象本身的属性——剧集是自主的，而我们的操纵在它面前是噪声。

**推论（对后续方法的影响）**

要识别一个不能主动操纵的触发条件，唯一可行的方法是**连续观察**：常驻哨兵按分钟
记录"剧集开/关"，同时记录候变量（MD 侧 /sys/kernel/ccci/*、内存、spawn 率、
uptime 等），跑足数小时后找出**转变前**的共性，而不是在转变中做对照。

这也意味着：§8.16 的 hardened vfprintf 若要验证，必须在**剧集窗口内**做，且
窗口由系统决定而非由我们决定——除非先把触发条件搞清。
