## 1. 问题

32B 记录族 `{u32 X, 0, u32 len, __be32 ip, 0}` 的写入者身份。D23 v1 在
`__arch_copy_to_user` 漏斗上只检查 **len==32/16 且记录在 src offset 0**，两窗
1890 s、28.9M 次漏斗调用、家族内容命中 0（正对照 2 条），据此排除了“独立
32B/16B uaccess 拷贝”。

但 D21 现场几何给出 **记录 VA = sp_call − 0xb0**（三窗同族 `topva=0x4e0
spva=0xb0`）。若某次 `copy_to_user(dst, src, n)` 的 src 在 16B 倍数 `o` 处
含该记录，则落点 = `dst + o`；要让落点 = `sp_call−0xb0`，只需
`dst = sp_call−0xb0−o`。**v1 对 n>32 或 o>0 的嵌入形态完全未测**——这是
S1 §5 软件残余清单的 #1（唯一“完全未覆盖”的 uaccess 形态）。

## 2. 假设（先写死）

- **H_emb**：记录由某次 `__arch_copy_to_user` 写入 victim 栈带，且
  `n ∈ [16,0x1000]`、记录位于 src 的 16B 倍数偏移 `o`（`o+32 ≤ n`），
  `dst ∈ [mm->start_stack−8MB, start_stack+0x1000)`。命中样本的
  `lr`/fp 链即写者调用链。
- **H_soft0**：不存在任何 uaccess 拷贝（含嵌入形态）把该记录写入栈带。
  结合 S1 的窗口普查与 PAN 实核，uaccess 家族（含嵌入）被物理性排除；
  软件侧只剩 ①内联 `sttr` 多笔组合（S1 §5 #2）与 ②GUP+直映射/页表重映射
  （S1 §5 #3），并让位于 DMA/总线主写（NIGHT-SUMMARY D 类）。

## 3. 仪器

- **模块**：`funnelv2.ko`（源码 `tools/oneoff/sigsegv/bmods/funnelv2.c`，
  REVIEW 见同目录 `REVIEW-funnelv2.md`）。产物 md5 见 §9。
- **站点**：不变，`__arch_copy_to_user` 入口 `0xffffffc00843b680`，期望首字
  `05 00 02 8b`（`add x5,x0,x2`）。补丁原语与 v1 逐字相同：TTBR1 页表遍历 →
  `pfn_to_page` → `vmap(1 页, PAGE_KERNEL)` 私有可写别名 → `stop_machine` 内写
  4 字节 `b <trampoline>` → 每 CPU `dc civac + ic ivau`；还原写回 + 读回断言。
  `dryrun=1` 只定位/校验/映射/读回，**不写一字节**。
- **trampoline 过滤**（asm 快路径）：`len ∈ [16,0x1000]` 才进入 C 扫描；
  范围外直接执行被替换指令 `add x5,x0,x2` 并跳回站点+4（不读 src）。
- **C 扫描**：
  - dst 硬条件 = 用户 VA（`dst < 1<<44` 且 `dst+len` 不回绕）；
  - `stack_hint` = `current->mm` 存在且 dst ∈ `[start_stack−8MB, start_stack+0x1000)`；
    `stack_near` = 同带内且 dst ∈ `[start_stack−256KB, ...)`；
  - 非 stack 且 `len>0x100` 按 1:16 采样（有界成本）；
  - 起点 `o0 = (−dst)&0xf`（记录 VA 16B 对齐），之后每 16B 步；
  - 块读 `copy_from_kernel_nofault`（0x100B/块，16B 重叠，坏 src 不 oops）；
  - 快筛 `q1==0 && q3==0`（2 次 64-bit load）；
  - 内容判据（家族 B，与 D23 v3 同口径）：
    A0B2 `{A,0,u32 len,__be32 ip,0}`：`len∈[0x40,0x4000]` 且首字节为
    unicast IPv4（∉{0,127,224..255}）；B0A2 `{B,0,u64 A',0}`：
    `A'∈[0x1000,0x100000]` 且 `B≠0`；
  - 16B-core 探索变体（`{u32 len,__be32 ip}`）**只计数、不记录**；
  - 命中写 per-CPU 环：stack 命中 → hot（1024 条/CPU），其余 → cold
    （256 条/CPU）；每条 128B，含 `ts/lr/dst/src/len/off/q0..q3/trace[3]/pid/
    comm/flags`；每 CPU **首条 stack 命中**另存 ≤0x1000B 全量 src dump。
- **读端**：`/proc/funnelv2`，头部 + 每 CPU 计数 + hot/cold 最近记录 +
  首条 stack 命中的全量 dump。默认 `maxread=32`/环，上限 256。
- **正对照**：`funnelv2_selftest`（静态 aarch64）用新 pipe 写入并在栈上
  `read()` 回读，覆盖 7 组（详见 §4 门禁 4 与 §9 离线验证）。

## 4. 窗与有效性门禁（任一不满足 ⇒ 该窗 INVALID）

1. `insmod dryrun=1`：`site word == 8b020005`；`delta in-range`；
   PA/别名/vmap 定位成功；别名读回 == 站点字；`/proc` 顶部 `dryrun`。
2. live：`INSTALLED`；`/proc` 顶部 `PATCHED`；站点读回 == 我们写入的 `b`；
   别名读回一致。
3. `calls_total` 在窗内增长 > 0（漏斗确实被行使）。
4. **正对照在窗内执行且 7 组全部符合预期**（`comm=funnelv2_selftest`）：
   - G1 `len=32, o=0`、G2 `64, 0x10`、G3 `128, 0x60`、G4 `0xc0, 0xa0`、
     G5 `0xd0, 0xb0`、G7 `64, o=8`（8B 错位 dst）→ hot 环各 ≥1 条 A0B2；
   - G6 `len=0xc0, off=0xb0`（仅 16B core）→ **不得**产生 32B 记录，
     `core16` 计数增加。
   若任一组缺失 ⇒ 仪器无效，窗作废（不得用“0 命中”下结论）。
5. 热窗 ≥1200 s；窗内设备 `boot_id` 不变；无 oops/panic/BUG；无其它我方模块。
6. 收窗：`rmmod` 后站点读回 == 原始 4 字节；`/proc/funnelv2` 消失；
   `TRY_A` 低字节 = 0；`lsmod` 无我方模块。

## 5. 判据（预写死，不改）

- **主判据（H_emb）**：有效窗内 **hot 环**出现 `FV2_F_STACK=1` 的 A0B2/B0A2
  命中，且 **排除正对照 pid/comm**，条数 > 0 ⇒ H_emb 成立；命中的
  `lr`/`tr0..tr2`（经 `/proc/kallsyms` 符号化）即写者调用链，`off`/`doff`
  与 D21 的 `spva=0xb0` 对齐。
- **排除判据（H_soft0 上位）**：上述 hot 命中 = 0，**且** §4 门禁 1–6 全满足
  （含正对照 7 组全过）⇒ uaccess 家族（含嵌入形态）物理性排除（E2/E3）；
  软件侧整体让位于 S1 §5 #2/#3 与 DMA/GUP 取证。
- **core16 单列**：core16 命中不作为 H_emb 判据（它是 A0B2 后半段 `{len,ip}`
  的超集，且对 0xc0/0xb0 的 q7 单 16B 形态敏感）。core16 > 0 只作
  “16B 核心形态存在”的探索性证据，必须与 hot A0B2 命中分开报告。
- **cold 命中单列**：非 stack 带的嵌入拷贝（`FV2_F_STACK=0`）不构成 H_emb，
  单独报告；它只说明“记录被更大拷贝携带”在非栈目的地上发生过。
- 若命中 > 0 但全部可归因于正对照（pid/comm）⇒ 视同 0。
- **几何限制（必须与判决同读）**：32B 记录放在 0xc0 拷贝的 0xb0 处物理上
  不成立（0xb0+32=0xd0 > 0xc0）；该形态只能是 16B core（q7 单槽），或
  32B 记录在 0xa0（q6+q7），或拷贝长度 ≥0xd0。因此“0xc0/0xb0”的现场同构
  由 G5（0xd0/0xb0）与 G6（core16）分别覆盖；**不得**把 core16=0 当作
  “0xc0 路径已排除”。

## 6. 停止规则

- 崩溃预算 ≤2；同一缺陷重复出现即停（不改判据救场）。
- 单条命令 8 分钟红线；设备线内部硬停按当班约定（本线 15:45）。
- 任何 `RESTORE FAILED` ⇒ 立即停止实验、重启设备、不得继续运行
  （模块文本即将释放，残留 `b` 会跳空）。
- 正对照任一组缺失 ⇒ 该窗作废，先修仪器；不得用阴性结果下结论。
- hot 环 `drop_hot` 持续增长（嵌套/重入）或 `srcfault` 异常高 ⇒ 降流量/缩短
  轮询间隔，必要时提前收窗。

  预算冲突），改为记录 32B 命中内容 + src VA + off，另给每 CPU 首条 stack
  命中保存 ≤0x1000B 全量 dump。
