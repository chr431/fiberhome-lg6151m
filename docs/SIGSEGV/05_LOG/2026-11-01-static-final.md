# 静态证据 · 2026-11-01 收口（analyst lane）

**背景三句**（给不熟悉本项目的人）：设备上有一族用户态 SIGSEGV，根因是**每 32 字节的外部写入**落进了崩溃进程的**用户栈**，
恰好盖住 C 语言变参函数用来遍历参数的 32 字节控制块（`va_list`），于是进程把垃圾当指针解引用而死。
我们用一个"金丝雀"程序（vsurv4：循环调用 `snprintf`，捕获 SIGSEGV 后把栈页转储成 h4 文件）**稳定地**捕捉这种写入。
本文只写**静态分析**（反汇编 + 内核源码 + 主机侧转储）得到的、可复核的结论；设备实验另见 lab/kdev 的文档。

> 记号：**E3** 直接观测（字节/指令级可复现）｜**E2** 强推断｜**E1** 弱/单点｜**X** 已证伪。
> 全文所有"记录"都指那 32 字节；所有偏移都是相对 `top`（= 进程初始栈指针 `mm->start_stack`）。

---

## ① 一句话结论

**记录不是任何网络/硬件描述符，而是一个"16B 值 + 8B 零"的表项族（两槽共 32B），携带「一个 17~18 位小值」+「逐包的 host-order 长度 + 网络序对端地址」；
它的写目标跟着**活着的** `va_list` 走（金丝雀深度实验证明），而"谁写的"仍未点名——已在静态侧排除所有可穷举的候选，剩下三条待验判据。**

## ② 已证伪清单（每条都能独立复核）

| F-1 | **记录不是有线网卡（EDMA）的 RX 描述符** | **E3** | 反汇编 `mtk_rx_alloc_edma`/`mtk_poll_rx_edma0`（vmlinux，脚本 `static/kd.py`）：描述符 `w0` 必须是"缓冲 DMA 地址"（页内偏移只能是 `0x40/0x7c0`），`w1` 的 bit31 是完成位、bit[23:8] 是包长；而记录 `q0` = 4.9 万~16.5 万、非 4K 对齐，`q1=0` 意味着"未完成"，且实测长度有 4416/4480 > 驱动编程的 1536 上限 | 找到第二套 RX 描述符格式且 w0 语义不是缓冲地址 |

| F-7a | **在"685 个直接 `bl` 站点 + 18 条指令回扫窗口"这一口径内，"目的地址来自结构"（`ldr x0,[xS,#off]`）的站点只有 6 个** | **E3**（对分类器的事实陈述） | 脚本 `static/usercopy_sites.py`；逐个反汇编核过：2 个是我分类器的假阳性（回扫跨函数边界），真 4 个里 2 个厂商站点长度固定 24/16B、2 个是运行时长度（见 F-8） | 用更长的回扫窗口或数据流分析找到更多 FIELD 站点 |

## ④ 结构身份的最佳描述（当前口径）

**形状（E3）**：32 字节 = **两个 16 字节"槽"**，每槽 = `{u64 值; u64 0}`（第二字恒零）：

| 槽 | 内容 | 说明 |
|---|---|---|
| 槽 0 | `u64 A`，17~18 位小值，`A ∈ [48957, 165456]`（归一化后） | 与历史"长度型 16B 块"同值域 |
| 槽 1 | 低 32 位 = **host-order 长度**（实测 {321, 1600, 1601, 4416, 4480}）<br>高 32 位 = **网络序地址**（本机 `192.168.9.1` / 公网对端 / `0.0.0.0`） | 内存里就是相邻的 `{u32 len; __be32 addr}` |

**读记录必须先归一化（E3）**：`va_arg` 会对它读到的 8 字节指针做 +8 自增 ⇒
A 型（写目标 = `va_list` 本身）要把 `q0` 减 8，B 型（写目标 = `va_list−16`）要把 `q2` 减 8；否则长度和 A 值都会系统性偏 8。

**与历史调查的收敛（E2）**：本项目历史文档 `SIGSEGV_ANALYSIS.md`
§2.1「**长度型 16B 块 `{small,0}`：small ∈ [0x2710,0x40000]，非单调**；同页可多块；16B 节距」
与 §14「**live PIT 表项 16B：`{u64 PA, u64 0}`；4KB 页 256 项，最后一项在 0xfc0**」
⇒ 今天这条 32B 记录与历史注入**属于同一类对象**（"值 + 零"的 16B 表项，1~2 槽/次），
而历史判定那条通道的载体是**调制解调器侧的 PIT 环**——这与"AP 侧已无候选"同向。

> 注：历史 §2.1/§14 那两条结论本身只有 **E1/E2**（当年样本与判据都更弱），这里**仅用于"同族"形态对比**，不作为独立证据。

**不要**把它建模成一个打包的 64 位整数（`(addr<<32)|len` 这种"高位地址低位长度"的打包在内核里没有先例；
有先例的 `jhash_2words`/`flow_dissector` 都是"地址|端口"，不是长度）。

## ⑤ 若要点名：最省钱的 3 个实验（按成本排序）

1. **读两个 proc 节点比对字段（≈0 成本，10 分钟）**
   `cat /proc/warp_ctrl/*/procinfo`、`cat /proc/hnat/{hnat_entry,hnat_usage}`，看是否出现同形 `{len, addr}`。
   ⇒ 命中即点名厂商 RX info（U-5）；全空只能写"无法证实"（不是"未启用"）。
2. **在 MD 共享区搜受害者的栈 VA（≈15 分钟，只读，脚本已给）**
   这是唯一能**当场点名"用户 VA 导出通道"**的手段；必须有正对照与噪声底，否则结论无效（见下 5 行用法）。
3. **romap + pte_redirect（kdev 已有能力，1 个窗口）**
   一次分开"跟 VA 走"与"留在旧物理页"：诱饵页出现 32B 记录 ⇒ VA 解析（E3）；留在旧页且 `refcount` 无额外引用
   ⇒ 只能是"PA + 由某 VA 派生的偏移"，此时实验 2 就是它的前提检验。

## 附：`md_va_scan.sh` 用法（5 行，lab 照抄）

```
1) 主机算目标：python md_va_scan.py --gen <startstack_hex> <sp_hex>  → 得到 TARGETS='A:.. B:.. PG:.. SPPG:.. NOISE1:.. NOISE2:..'
   （不要在设备 shell 里做 64 位运算：ash 会把 startstack-0x390 截成 32 位）
2) 设备(root)：TARGETS='...' PASCAN=/data/repro/pascan sh md_va_scan.sh run      # gen 只打印不执行
3) SRAM/MMIO 区必须另配 MODE1=<ioremap 读命令>；未配时脚本会主动 SKIP（mode=0 读 SRAM 会 SEA 重启）
4) 正对照：POS_ADDR=<kallsyms 里必然被引用的地址>；POS 命中 0 ⇒ 整轮作废（先修扫描器/区域/mode）
5) 判读：每区只看 A/B/PG 命中数 vs NOISE1/NOISE2 —— ≤噪声底写"0/N（检出下限=噪声底）"；>2× 且落在已知结构内=候选
```
