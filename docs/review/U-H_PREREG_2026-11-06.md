## W0 · T3 放逐窗（引擎对保留 DRAM 窗的可达性）

### 假设（写死）
- H-E：引擎注入无 DRAM 地址范围限制（含保留窗）⇒ λ_E ≈ λ_A。
- H-D：引擎只画"AP-normal"可分配带（或任何对 0xbf… 窗的不可达限制）⇒ λ_E = 0 而 λ_A 正常。

### 仪器
- `scanary_exile`（scanary v1.4 派生）：**同进程两 victim 线程**——A=匿名 mmap 栈（对照）、
  E=/dev/mem MAP_SHARED 映射 ISU 保留窗内 2MB（0xbf000000..0xbf200000，栈顶=win+2MB）；两线程
  hot_call 行为逐字相同（同 D、同 hold 10ms）；另有冷窗区 win+2MB..8MB（毒化、零写）与 8MB 匿名
  decoy。matcher/rules 逐字同 scanary v1.4（R2|R1|R1L|R3，主计数=inj=0）。
- `wmd5`（mmap /dev/mem → 落盘/属性探针）；`emiuctl.ko`（既有，调厂商 mtk_emiisu_control）；
  `udpflood_ug1.py` 3×800pps（既有）。

### 前提门（任一不过 ⇒ W0 不开窗，记 GATE_FAIL+原因）
1. **窗在 System RAM**：全量 /proc/iomem 中 0xbf000000..0xbf800000 落 System RAM 段（§27.2 全量纪律）。
2. **ISU 关断+冻结**：`emiuctl call <kallsyms-addr> 0` 后，窗快照 ×2（间隔 ≥30 s）md5 相同且字节差 0；
   重开 `call … 1` 后窗翻转（可逆性复验，U-G7 同法）——本轮 W0 全程保持关断。
3. **映射属性**：对窗内页做未对齐 u64 读+写探针无 SIGBUS；1MB 字节写时延 < 50 ms（cacheable 侧）；
   记录实测值。若未对齐致死或时延异常 ⇒ /dev/mem 路线 INVALID，当日不启用 exile.ko 备胎（另立轮）。
4. `scanary_exile --selftest` 全过（含 PFNMAP 栈区注入回收 T5e）。

### 臂与窗口（flood 全程 2400pps）
- **单窗 600 s × 2 窗**（两窗间不重启进程；flood 持续）。A/E 并发同窗 ⇒ 配对率比，天然消除会话方差。
- 计数：region=stackA / stackE 各自的 HIT_APPEAR+HIT_CHANGE+HIT_REWRITE（inj=1 剔除）/ 窗时长。
- **功效门**：λ_A ≥ 20 次/600 s/臂（两窗任一未达 ⇒ 该窗"无功效"，不作阴性）。

### 判据（冻结）
| 结果 | 判 |
|---|---|
| λ_E = 0 且 λ_A ≥ 20（两窗同向） | **H-D：放逐可用**（工程价值：关键守护栈可迁窗避写；后续另立部署轮） |
| λ_E/λ_A ∈ [0.7, 1.4]（两窗同向） | H-E：引擎范围不限 RAM 窗；T3 关闭收口 |
| 0 < λ_E/λ_A < 0.7 | 部分压制：记并分析落点几何（页/偏移分布 vs A 臂），不作二元结论 |
| 冷窗区 >0 真命中 | 单独记录（引擎无 store 流也画窗=对 C-265 decoy 结论在该窗的边界信息） |

### 中止/安全
- victim E 若 SIGBUS 风暴（映射属性问题）⇒ 立即停 W0，记 INVALID-attr。
- 本 W0 我方零 MMIO 写；ISU 经厂商函数操作（U-G7 验证过的挂起安全路径）；窗内只有用户数据。
- 收尾状态卫生：ISU 重开（call 1）+ 窗翻转断言 + 模块卸净。

## W1 · T5 谓词探针（目标捕获对 store 形态的依赖）

### 假设
- H-M：捕获谓词依赖 store 形态（宽度/顺序）⇒ 变形臂 λ 相对基线显著塌。
- H-N：谓词=地址流+内容校验，与形态无关 ⇒ 变形臂 λ 不变。

### 仪器
- `scanary_vamorph`（scanary v1.4 派生）：victim 换为**手写变参仿真**（深帧 + 自控 va_list 32B 槽
  更新流），`--mode`：
  - `base`：编译器自然形态（V0 校准门——仿真流必须先被证明有吸引力）；
  - `strb`：全部 8B 存储改为 8×strb 逐字节；
  - `split`：stp 类存储拆两条 str；
  - `junk1`：每轮先写 junk 再写真值。
- 每臂**并发**跑一个原版 scanary（同 D/hold/时长）作同窗对照 ⇒ 配对率比
  RR_mode = λ_mode / λ_scanary(同窗)。

### 门槛与判据
- **V0 门**：RR_base ≥ 0.3（λ_scanary ≥ 20/300 s 前提下）。不过 ⇒ 仿真流不足（"合成流不吸引"记
  录为发现），W1 止于此，V1..V3 不跑。
- 每形态 300 s × 1 臂（顺序 base→strb→split→junk1；λ 热态 300 s 期望百级，功效足够）。
- RR_mode ≤ 0.2（相对 RR_base）⇒ H-M 成立（形态敏感；记录敏感维度）；RR_mode ∈ [0.7,1.4] ⇒ 该
  维度不敏感；中间值 ⇒ 记录不下二元结论。
- 全臂同 boot、flood 同参数；probe 注入 inj=1 全部剔除。

### 安全
纯用户态，无新增面。victim 自带 SIGSEGV/SIGBUS handler（SELFCRASH 计数不隐藏）。

## 修订 A（2026-11-06 10:4x，**首个实验窗之前**；门禁阶段测量触发的仪器修正）

**触发**：W0 前提门实测结果——
1. 门 2 通过：ISU `call 0` 后窗 md5 冻结（473cfe79×2，30 s）；重开 `call 1` 后窗恢复翻转（c4d61923≠冻结值）——关断/重开双向验证 ✓（ISU 已复位至 boot 默认 ON）。
2. 门 3 **失败于 ISU 窗**：`wmd5 probe bf000000` 触发 fatal（未对齐访问 SIGBUS）——根因：`bf000000-bf7fffff` 在 iomem 全量里是**顶层 reserved 段**（非 System RAM 子节点）⇒ `pfn_valid()=0` ⇒ `phys_mem_access_prot` 给 `pgprot_noncached` ⇒ Device 属性不可承载线程栈。**非仪器 bug，是窗口选错了。**
3. 替代窗发现（同一次 iomem 全量 + DT reserved-memory 对账）：**`9c200000-9c3fffff`（2MB）= mblock-11-pl-drambuf + mblock-12-pl-boottag**，是 `9c1f1000 System RAM` 的 **reserved 子节点** ⇒ pfn_valid=true。

**修订内容（判据全部不变，只换 E 臂背衬窗口与映射来源）**：
- E 臂窗口 = **0x9c200000/2MB**（pl-drambuf+pl-boottag），映射 = `/dev/mem` MAP_SHARED（该窗实测 **cacheable**：未对齐读写 OK、1MiB 存储 700µs≈1.4GB/s）；
- 闲置断言（新门 2'）：两快照 30s md5 相同（实测 ad302ca7×2 ✓）；
- ISU 与本轮 W0 不再相关（已复位 ON）；
- 假设对更新：该窗是 pfn_valid 保留页（有 struct page、从不过 buddy 分配器）——H-D 的机制子型 (ii)「引擎只画经 buddy 管理的热页」（与 C-265 "buddy-pool recycle window" 措辞相容）预测 λ_E=0；子型 (i)「地址过滤只排除特定 carveout（如 0xbf 段）」预测 λ_E≈λ_A。两结果都是收口。
- 安全评估：运行期覆盖 pl-drambuf/pl-boottag（boot 暂存区；preloader 每次启动重写自用）；实验窗口有界（1200s），远离 04:00 定时重启。

**scanary_exile 参数冻结**：`--win-pa 0x9c200000 --win-size 0x200000 --stack 1m --duration 1200 --period-us 5000 --hold-us 10000 --depth 0 --stride 16 --log /data/repro/w0_exile.log`（单进程连跑 1200s = 预注册的"两窗 600s×2 不重启"，分析侧按 START 后 [0,600)/[600,1200) 切两窗）。flood 参数不变。

## 修订 B（2026-11-06 11:2x，junk1 臂在跑、natfp 臂未跑之前；**探索性补充臂**，不动冻结矩阵）

**触发**（冻结矩阵进行中数据）：arm1 base RR=429/449=**0.955**（V0 门大过：合成路线成立）；
arm2 nat **0/0/0**（对照 331）、arm3 strb 0（对照 118）、arm4 split 0（对照 130）——esink/iters
全部在推进（arm2 esink=2.6e16/iters=23654）⇒ 真阴性。**手写仿真流整体不可见，宽度变形臂失去
判别对象**（对不可见流做宽度变形只能再得 0）。

**base 与 nat 的结构性差分**（唯一待判变量集合）：
1. **FP 寄存器保存**：编译器变参 prologue 必存 q0-q7（4×`stp q,q` = **4 次 32B store 事务**）；
   我们的全部仿真模式（nat/strb/split/junk1）都只有 ≤16B store；
2. 保存区内容/指令顺序/取参指令形态的次要差异。

**假设 H-Q（探索性）**：目标捕获签名含 **32B store 事务**（与记录本身 32B 同宽，机制上诱人）。
**补充臂 natfp** = nat 形态 + 4×`stp q6,q7/q4,q5/q2,q3/q0,q1` 到 128B FP 保存区（q 值=当时寄存器
现值，与编译器行为一致）；判据同 RR 公式（并发 scanary 对照，300 s，λ_scanary≥20 前提）：
- natfp RR ≥ 0.3 ⇒ 32B（FP 保存）事务是签名的必要成分（H-Q 支持，E1）；
- natfp RR ≈ 0 ⇒ 排除 FP 保存单一因素，差分收至"编译器精确序列"（后续轮）。
纯探索臂，不写回冻结矩阵的 H-M/H-N 判定（那两条按原判据收口）。
