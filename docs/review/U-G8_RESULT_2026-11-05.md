# U-G8 · DFX 正面读出:死亡 dump 武器化 + 四窗矩阵 ⇒ 可见 DFX 面对写入者零签名

> 时段:2026-11-05 22:45–23:50(+0800)｜授权:"设法读DFX寄存器,至少在死之前把数据传出或者在设备上落盘。正面钉死非常重要。"
> 本轮 4 次受控 sysrq-b 复位(全部按需触发,零仪器性死亡/零挂起);仪器=COM6 raw 串口捕获 + sramrd.ko 只读 + scanary_mig v1.4 + 2400pps 洪水。
> **一句话**:BL31 复位路径本身把完整 DRAMC/DDRPHY 调试寄存器集(含 EL1 读即致死的
> `DDRPHY_AO_CHA/CHB+0x1520`)打印到串口——**死亡即读出、串口即传出**,sysrq-b 可按需
> 触发(4/4 成功,dump 从触发到打完 ≈20ms,数据在复位完成前已离机)。四窗矩阵
> (空闲/活跃 × 年轻/长稳内核)判读:**匹配生命周期相位时,写入者活跃与空闲在全部 12 个
> 可读 DFX/DRAMC-debug 寄存器上逐位相同** ⇒ 正面钉死在可见调试面**落空**;写者位于
> 一切可读调试面之下(U-G7 终局身份获得正面强化)。

## 1. 实验链(时间序)

1. **22:45–23:00 离线铺底**:tee_b full.txt 复核 0x1164c/0x11708=打印格式器,真正读在复位链
   (0xf600→0xf6a8→0x139bc→0x10d14);GDL{bus_id,addr,w_val} 字串=gps_dl 驱动日志(排除);
   旧 bw10 串口捕获里发现历史 [DRAMC-ATF] dump ×3(含 +0x1520 值)——机制免费实证。
2. **23:00–23:03 串口接管**:项目 serial_server 僵尸(占 COM6 不读,环形日志停在 Oct6)经 TCP
   QUIT 优雅退出(CH340 保护),serial_rawlog.py 接管。
3. **23:03–23:09 只读基线**:sramrd 活读 DRM_DEBUG_CTL=0x8303(×2 稳)、DBG0=0x09、
   NAO_CHA=0x400622be→0x400622b6、NAO_CHB=0x010622b6→0x400622b6(空闲分钟级翻动);
   ATF 缓冲扫描 128KB 全零。
4. **23:09 dump#1(空闲@2.58h)**:sysrq-b→27 行完整捕获(+0x1520=0x8008/0x8008,DBG0=0x8)。
5. **23:14–23:16 活跃窗**:受害者(900s)+洪水(2400pps),λ=46/min(99 真命中,poff=0xc10
   形态,len=1664,ip=110.65.xx.28 本机 WAN 端点);EL1 轮询:DBG0=0xd 持续、NAO 双通道 0x000622bf。
6. **23:16 dump#2(活跃@6.2min)**:0x8408/0xc、NAO_CHB=0xc00602b6;SGT 差异初步似流量相关。
7. **23:19 dump#3(空闲@4.2min)**:0x8408/0xc 与 #2 同态 ⇒ **bit22/bit2 与写者无关**;
   "疑似流量相关"被同 uptime 空闲对照否定。
8. **23:20–23:45 长稳等待**:settle 轮询(6.2/9.5/12.6/20.7/27min:DBG0 恒 0xd——bit2 活读
   在 27min 仍置位,死亡读才见清零;活读 vs 死亡读存在处理瞬变:bit0 运行置 1/死亡清 0)。
9. **23:44–23:46 dump#4(活跃@32.5min)**:受害者(300s)+洪水,λ≈40/min(21 命中)后
   sysrq-b:**0x8008/0x8,12 寄存器与 #1 逐位全同**(含 RGU 非复位寄存器)。
10. **23:47–23:50 收官**:sg8/sg8b 受害日志入库、串口原始流(1.45MB)入库、sramrd 卸净、
    受害者清、设备健康(第 5 次启动,无残留)。

## 4. 对终局身份的影响(给 VERDICT §17)

1. **U-G7 终局身份获得正面强化**:写者不仅无控制面(U-G7),在**全部可读调试面**上亦无
   状态签名(U-G8 四窗矩阵)。§16.1 的第 4 层(盲区标注)升级为:**盲区已读、有界、零痕迹**
   ——"残余子位置 DDRPHY DFX 族"的可读子集(0x1520 家族被 dump 的那一面)不含写者状态。
2. 死亡 dump 机制(复位路径 EL3 读 + UART 出)是本机唯一正面观测面,已武器化并归档;
   任何后续死亡(WDT/panic)都会自动产出该 12 寄存器快照——串口常开即可持续收割。
3. 正面钉死在本机的可达上限即此:**可见面无签名 + 一切控制面无手柄 ⇒ 写者在两者之下**。
   跨过该上限只剩厂商文档/EL3 调试固件/边界事务截获(本机无能力),与 §16.1 结论一致。

## 6. 追补修正（2026-11-06 清理轮 · 环形日志语料回收）

清理时从仓内 `tmpfiles/serial_ring.log`（8.2MB，旧 serial_server 多年环形日志）中回收了

该文件含串口登录明文口令，已移出仓库树）。按"每 dump 向前找最近启动横幅"归组后：

| K(秒) | +0x1520 ×2 | DBG0 |
|---|---|---|
| 150 / 299 / 531 / 605 / 646 / 910 / 1078 / 1581 / 2373 / 2403 / 2650 / 14768 | **0x84080007**(12/15) | 0x9 为主（SW_WDT 类 0xd） |

**判决更新（C-272，修正 C-269 的机制表述）**：
1. **"bit22/bit2=DRAM 生命周期态（年轻恒置、长稳清除）"的规则被语料证伪**：
   4.1h 仍置位（K:14768）、21min 已清零（K:1285）、12/15 置位——与 uptime、崩溃类型、
   复位路径均无干净映射。**它们的驱动未知（需厂商文档），单快照值不可作为任何分类器。**
2. **核心零签名结论不变且更强**：写入者活跃死亡的 dump（K:1582/K:2650/K:1078 上下文 +
   今晚 #2/#4）与非写入者死亡在可见 DFX 集上取值分布**完全重叠**（两类都出现
   0x8408 与 0x8008）⇒ 可见面没有任何写入者专属取值。
3. 方法论保留：**单对快照同一（#1 vs #4）本身不能证明写入者不变性**——本轮修正后，
   该论证改为"全语料分布重叠"；"匹配生命周期相位"这一框架作废。
4. DBG0 bit0 疑似反映复位来源（sysrq/PSCI 类清 0：K:3243/K:14768/今晚 #1#4；崩溃/WDT
   类多为置位），但存在例外，同样不作分类器使用。
5. 该语料同时回收：`cat/ash: synchronous external abort` 型崩溃签名多条，与 U-G5
   归因（#17/#18 读地址致死类）一致；串口 ring 从此类"沉默富矿"先挖后删（已入
   AGENTS.md round-close 清单）。

## 7. 追补（2026-11-06 凌晨 · 离线扫描：厂商侧有没有可抄的"关闭"路径）

**目的**：回答"厂商若通过 OTA 关引擎，我们能否照抄"。扫描面 = vmlinux（18MB）、ktext/kdata、BL31（tee_b 全反汇编）、
全部 7 件协处理器固件、**新拉取的 preloader**（eMMC boot0，4MB，Thumb-2，md5 a9785c43…，base64+md5 双验证）。

| 镜像 | DFX 簇（0x10239520/0x10249520/0x10005030/0x10005500/0x102xxxxx 调试寄存器）证据 |
|---|---|
| vmlinux/ktext | 无任何代码构造这些页地址（movz/movk 扫描全零；页基址全部来自 DT）；无 DRM_DEBUG/dfd 字符串；无 dfd 驱动 |
| BL31(tee_b) | **只读**：0x1077c 起的崩溃路径逐条 `ldr` 0x10005030/0x10005500/0x10230d00/0x10239520/…；全镜像对 DFX 簇**零 store**。存在的写只有 RGU(0x10001xxx)、EMICHN 调试库(0x10235a8x，RGU dump 内部握手)、EMI-CEN(0x10213018，MPU 处理器内) |
| 协处理器固件 | 无 DFX 常量；SSPM 仅有 EMI 页表(0x10217000/0x10234000/0x10244000)，用于 DVFS 监视 |
| **preloader** | **发现厂商 DRM 调试访问器**：3 处掩码写(0x10005030 清 bit14/13/12，经原语 0x55c0)+3 个状态 getter(读 bit20/21/22)+原始读；**写协议含魔术位**：写 `0x10005030` 需 OR `0x55000000`，写 `0x10005034` 需 OR `0x59000000`；emicen/emimpu 页由 preloader 配置(读 bit8-9 状态、写 offset 0x38/0xe8-0x110) |

**内核侧可调用的厂商 API（emiuctl.ko 直接调，先例 mtk_emiisu_control）**：
`mtk_emicen_emi_monitor_stop/init`（drvdata+0xf8 使能位=0/1，init 另配 5 路通道 base+0xf00..0xf10=0x807..0x8007）、
`mtk_emiisu_control`（已测，无效应）、`emi_fake_eng_store`（违例注入）、`emicen_addr2dram`。

**判决**：
1. **可抄的路径找到了，但抄到的不是"关闭引擎"**：厂商自己的代码里也**没有任何写 DFX 簇**的路径
   —— 0x10239520 家族在所有可持有镜像中都是只读/硬件默认值。**DRM_DEBUG_CTL 的写入协议(魔术位)
   是唯一被破译的厂商调试控制面**，已可照抄（从 EL1 按下述协议写）。
2. **可复制写公式**：`写 0x10005030 = (读值按掩码改) | 0x55000000`；`写 0x10005034 = … | 0x59000000`。
   preloader 自己只用来清 bit12-14（当前运行时值 0x8303 下为 no-op）——说明**"关调试"的旋钮存在，但没人拧过**。
3. **下一步设备实验（可逆、带串口记录）**：(a) 按协议把 0x10005030 逐位清/置做 λ 对照；(b) 调
   `mtk_emicen_emi_monitor_stop` 的 λ 对照。任何一项若使 λ 塌 → 我们自己就复制出了"关闭"；若全部
   不动 → 引擎在更深层，"无本机手柄"结论再获证据。
