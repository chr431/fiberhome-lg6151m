# U-P · busybox 稳定性判决与修复：v5 误补 va_list 拷贝 → v6 验证子集（2026-11-06 夜）

> 时段：2026-11-06 21:05–22:05（+0800）｜授权：用户"确认 busybox 到底是否稳定，若不稳定则修复它"。
> 零 Oops/WDT；一次计划内重启（rc19 v2.42 持久化验证）；设备终态 3 挂载（libc/busybox/wpad）。
> **一句话**：p5 busybox **不稳定且可确定性复现**——`ls/cat/tar` 的错误路径 4/4 SIGSEGV
> （stock 0/6），根因是 v5 shape-B 把 3 条 `stp q0,q1` **va_list 拷贝**误判为变参保存区并
> nop（0x408c68..70），vswprintf 读到未初始化 va_list；同轮还发现 ip-full 的 p5 把两条
> `stp q0,q0`（memset 类）误补，`ip neigh` 周期性 SIGSEGV。修复 = **v6 严格校验器**（函数
> prologue + vr_offs + 首 call 前 + 已加载 q 寄存器拷贝排除），并只部署 **v5∩v6 验证子集**：
> busybox 58 站点（保留错误函数 q2..q7，剔除拷贝/awk 引擎）、libc 140（与 p4 逐字节相同）、
> wpad 24（与 p5 相同）、ip-full **0**（回滚 stock）。p6s 电池：13 组功能输出逐字节一致
> （含 `awk %.3f`/`printf %f`）、8 类错误路径 ×30 双栏 **0 信号**、重启后 ×20 复验 0 信号。

## 1. 事故链（p5 busybox）

### 1.1 复现表

| 命令 | p5 busybox | stock busybox |
|---|---|---|
| `ls -l /tmp/<missing>` | **4/4 SIGSEGV**（far=0x48） | 0/6 正常报错 |
| `cat /tmp/<missing>` | SIGSEGV（far=0x0） | 正常报错 |
| `tar -cf x /tmp/<missing>` | SIGSEGV（far=0x0） | 正常报错（无文件） |
| 同窗 NE 行 | 21:10:42–21:10:56 共 4 条 P/busybox ls 行，exe=/data/stealth/stab/P/busybox | 无 |

### 1.2 核心与帧链

崩溃 core 7406（1793970656）：`far=0x48`，`pc=libc+0x51ffc`；帧链
`libc+0x53408 → libc+0x539d4 → libc+0x560cc → BB+0x8c78 → …`。BB+0x8c78 位于
busybox 的 printf 辅助函数（`0x408bcc` 函数体内，`bl 0x4059f0` 返回点），该函数在调用
libc 前把 va_list 复制三份：

```
0x408c50  ldp  q0, q1, [x24]        ; load 32B va_list from caller
0x408c68  stp  q0, q1, [sp,#0x60]   ; copy #1   <-- v5 nop
0x408c6c  stp  q0, q1, [sp,#0x80]   ; copy #2   <-- v5 nop
0x408c70  stp  q0, q1, [sp,#0xa0]   ; copy #3   <-- v5 nop
0x408c74  bl   #0x4059f0            ; libc vsnprintf
```

三份拷贝被 nop 后，vsnprintf 的 va_list 是未初始化栈；`far=0x48` 即 `[va_list]` 读出的
`__stack` 值。反汇编核对：p5 二进制 0x408c68/6c/70 全为 `nop`，stock 为三条 `stp q0,q1`。

### 1.3 v5 漏判原因

v5 shape-B 的 copy-pattern 只检查 cluster 前 `prev/prev2` 两条指令；本例 `ldp q0,q1,[x24]`
在 cluster 前 6 条（中间有 `add/mov/sxtw`）。且 v5 的 shape-B 不要求 `vr_offs` 签名——
真正的变参保存区（8×`str q`，0x408e40..68）与这三条 va_list 拷贝在形态上不可区分。

## 2. ip-full p5（同轮发现）

NE 台账（p5 挂载期，系统 `ip neigh` 由 vendor 脚本周期执行）：

```
1793970936  ip  sig=11  exe=/usr/libexec/ip-full  args=ip neigh  far=pc=0x1001200000028
1793970989  ...  1793970993  ...（同签名重复）
```

v5 在 ip-full 只命中 2 站点——`0x449e88 stp q0,q0,[sp,#0x20]`、`0x449e90 stp q0,q0,[sp,#0x40]`，
**同寄存器双写**是 memset/复制形态，不是变参保存区；nop 后结构未初始化。v6 严格校验
（无 vr_offs）判为 no-vr-offs，交集为 **0** ⇒ ip-full 回滚 stock。

**诚实修正（21:34）**：回滚 stock 后仍观察到 stock `ip neigh` SIGSEGV
（NE 1793972045，far=0x32e52，pc=libc）；且台账有 **40 条部署前（stock）历史**
（1793689702、1793786370…），说明该命令的崩溃面是**既有 vendor 家族**，不是 p5 独有。
p5 的拒绝依据是**静态确定的 2 条 memset 误补**（交集 0），不是"p5 致崩"的单一因果；
stock 的间歇崩溃保留为既有开放项。`cat /proc/mtketh/phy_info` 同样有 2 条部署前历史
（far=0x2b059/0x2e435），本轮 1793973589 的 p6s 行属于同一既有家族。

## 3. v6 校验器与交集

### 3.1 规则（tools/oneoff/varpro_patch_v6.py）

1. **prologue 内**：从候选向前 ≤96 条找 `stp x29,x30,[sp,#-]!` / `sub sp,sp,#` /
   `stp x19,x20,[sp,#-]!`，其间不得有 `bl`/`ret`；
2. **vr_offs 签名**：`mov/movz/movn w?,#-0x80` 在 ±窗口内（musl va_list 特征）；
3. **首次 call 前**：prologue 到候选之间不得有 `bl`（变参保存在入口完成）；
4. **拷贝排除**：候选存的是「最近 24 条内从任意基址 `ldr/ldp q` 加载过的 q 寄存器」→ 跳过
   （va_list 拷贝/结构复制）；
5. **组条件**：≥4 个不同 q0..q7、目的偏移严格升序；
6. **可选 save-area reload**：若函数稍后从**同一保存区偏移**回读 q，则跳过（printf 引擎
   自消费 FP 变参；保住 `%f`）；
7. **交集模式**：`--only <v5 站点表>` 只落 v5 已验证过的地址，不新增站点。

### 3.2 交集结果

| 目标 | v5 | v6 | v5∩v6 | 动作 |
|---|---|---|---|---|
| busybox_dyn | 106 | 110 | **58** | 新 p6s（保留 0x408e50..68 错误函数 q2..q7；剔除 0x408c68..70 拷贝、0x40a82c.. awk 引擎、其余未验证 shape-B） |
| libc | 140 | 186 | **140** | **与现挂 p4 逐字节相同**（md5 dc38797e），不动 |
| wpad | 24 | 24 | **24** | 与现挂 p5 逐字节相同（ad381d37），不动 |
| ip-full | 2 | 16 | **0** | **与 stock 逐字节相同**（b8be55d1），回滚 |

p6s busybox md5 = `af5f1d752a2ab321827f74a2fd85f7c8`；0x408c68/6c/70 保持原 `stp q0,q1`，
0x408e40..68 的 q2..q7 为 `nop`（q0/q1 保留——v5 行为，错误消息最多 2 个 FP 参数仍正确）。

## 4. 验证与部署

### 4.1 电池

- **功能等价**：13 组命令（sh/awk/sed/grep/sort/cut/md5/seq/expr/tar/wc/ls/printf）P6S vs stock
  输出+stderr 逐字节一致；`awk %.3f`=3.142（p6 全集曾输出 0.000，证明必须用交集）；
  `printf %f`=2.500000；applet 列表一致。
- **错误路径**：ls/cat/tar missing、ls /proc 混合、grep、printf、exit 3、true 共 8 类 ×30 次，
  P[ok/err/sig] 与 S 完全同计：全 0 信号。
- **重启后复验**：同电池 ×20，全 0 信号；服务 hostapd×2+dnsmasq 存活。
- **grep 专项**：vendor 管道 `cat /tmp/mtketh_esw_cnt | grep PSE_OQ_STA3` 200× 双栏 0；
  30 个 8KB 随机二进制 + 10 个构造输入（长行/无换行/0xff）差分 0。
- **残余**：开机 149s 一条 grep SIGSEGV（§0 表），不可复现；不归因 p6s，保留开放。
  另有 1 条 `cat /proc/mtketh/phy_info`（1793973589，far=0x31f3）属**既有 vendor 家族**
  （该命令 2 条部署前 stock 历史：far=0x2b059/0x2e435）。

### 4.2 持久化与验收

- rc19 **v2.43**（部署 md5 见设备 `/data/gw/rc19.sh`）在 boot **t=25s** 自检后挂载，并写
  持久标记：`1793973483 25 libc=1 bb=1 wpad=1`（`/data/stealth/boot.log`）；
- 重启后：`/lib/libc.so=dc38797e`、`/bin/busybox=af5f1d75`、`/usr/sbin/wpad=ad381d37`；
  **无 ip-full 挂载**（stock b8be55d1）；`/bin/busybox md5sum /proc/self/exe` = af5f1d75
  （生产 shell 确为 p6s）；
- **20 分钟生产 soak**：2 路日志 × 各 2 个 worker（共 4 进程），每进程 **1192 次**混合命令，
  全部 `SOAK_END ... sig=0`；soak 窗口无 p6s NE 行；
- **T0 = 1793973483**（标签 `T0_UP_p6s_boot`，取最终 boot 标记 epoch）；acc_report **v6**
  （3 挂载 + boot.log）基线：mount 1/1/1、ip 0、服务 3、`since T0` 仅 2 条既有家族（phy_info + gw 静态 watchdog）。

## 5. 三栏

**[A] 已核实**
1. p5 busybox 确定性错误路径崩溃（4/4）与根因（3 条 va_list 拷贝被 nop；核心/帧链/反汇编）。
2. ip-full p5 的 `stp q0,q0` 误补与 `ip neigh` SIGSEGV；交集 0 ⇒ 回滚 stock。
3. v6 规则与交集表；libc/wpad 与在役件逐字节相同。
4. p6s 功能/错误路径/重启/ grep 专项电池全绿；reboot 3 挂载 dmesg。

**[B] 未核实/边界**
1. p6s 只保留 58/106 站点：v5 的 48 条 shape-B 站点被安全放弃（含可能的真实保存区），
   覆盖是**保守子集**，不是最大覆盖。
2. libc 的 printf 引擎（reload 型）仍未补——`%f` 正确性优先；其 FP 保存突发仍在，
   写者仍可能命中（grep 残余即此形态的候选解释）。
3. gw 静态 busybox 未补（U-O 拒部署延续）；本轮 21:30–31 它仍被写者击杀（awk/led_mgr
   NE 行），是独立于 p6s 的残余面。
4. 一处 grep 崩溃不可复现，无法归因到具体机制（瞬时输入 vs 写者）；一条 phy_info
   崩溃属既有 vendor 家族（2 条部署前历史）。
5. `/data` 水位 88%（cores 轮转占用）；不在本轮处置范围，验收前如需可清旧 core。

**[C] 下轮入口**
1. 静态 busybox 的 v6 交集补丁（同样先 `--only` 验证；当前 0 站点的 ip 经验可供参照）。
2. libc printf 引擎的"保 FP 变参 + 去突发"折中（部分 q 保存/替代 shim）。
3. 24h 验收：`acc_report.sh` v6（3 挂载 + boot.log），判据 = 3 mount 每 boot、服务、selftest ≥102/105、
   NE 有效行分布（预期 busybox/wpad 类死亡不因补丁上升）。

## 6. 对总档的落点

- VERDICT §27（C-318..C-323）；CLAIMS 追加；00_STATE 指针；13_BLOCK_PATHS T5 注记更新。
- 关键结论一句话：**"补丁器命中数"不是覆盖指标——必须对每条落点做语义验证；v5→v6 的
  交集把 busybox 从"106 站点但确定性崩溃"修成"58 站点且功能等价"。**
