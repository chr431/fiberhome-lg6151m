## 2. logread SIGSEGV 家族（长期异常）

### 2.1 现象

- aee 的 `db_history` 自 10-05 起累计 164+ 次 NE；近 24h 去重后 **117 次** core 事件，
  其中 `logread` 占 ~45%，其余 `awk`(19)、`ip`(18)、`grep`(7)、`sh`(6)、`pgrep`(6)、
  `hostapd`(2) 等。
- 单次 aee 转储约 **4 秒 / 500KB**；转储自身会跑 `ps/df/mount/logread/ip/awk`，
  偶发同族崩溃会再触发转储，形成放大（12:00 时段曾出现 400 条/小时的尖峰，含镜像重复）。
- 无数据损坏：受害进程以“读数据/解析”型短命工具为主，崩溃即退出。

### 2.2 机制与取证细节：见 SIGSEGV_ANALYSIS.md

本节的机制、证据（DABT 行读法、三份 core 签名、栈缓冲内容、16KB 截断）与实验矩阵，
已于 2026-10-22 **统一迁入** `docs/SIGSEGV_ANALYSIS.md`：

- 机制与判据：§0.5 总表、§1 统一签名、§2 logread 侧、§10 logc、§12/§13 printf 类；

## 3. eth0 显示误报（16:26 起）

### 3.1 事实：eth0 完全正常

```
carrier=1  operstate=up  speed=1000  duplex=full
inet 110.65.x.x/25
default via 110.65.x.x dev eth0
```

### 3.2 因果链

```
wan_agg 子命令连续 SIGSEGV（/tmp/wagg.out 十余条 "Segmentation fault"）
  → wan_agg.sh 退出（16:26）
  → /tmp/wan_alive 停更（home=1 cell=1 ts=16:26:44）
  → led_mgr.bb_data_alive(): ts 超过 30s → "未知=不亮" → WAN 灯灭
  → api_sys.sh: _fresh=0 → ETH_DP=0 → GUI 有线线路状态"离线"
```

关键设计（不是 bug，是“宁可灭灯也不谎报”的既有约定）：

- `led_mgr.sh` 注释：`ts 过期(>30s, 守护异常)按"未知=不亮"处理 —— 宁可灭灯也不谎报"已连接"`；
- `api_sys.sh` 注释：`ts 过期(>30s, 守护异常)时按"未知"处理(0), 不用旧值猜`。

问题不在判据，而在 **wan_agg 死后无人拉起**。

### 3.3 修复与验证

- **watchdog v1.19**：`wan_agg` 从“只 check”改为“死则按启动配方拉起”。
- 受控验证：`kill <wan_agg>` → 17:38:23 `EVT restart wan_agg` → 新 pid 30853 →
  `wan_alive` 恢复新鲜 → WAN 灯 `brightness=1` → 自检 `WAN 指示灯反映家宽数据面 ✓`。
- 现场恢复后：`wan_led=1`、`wan_alive=home=1 ts=…`、`ETH_DP` 判据恢复为 1。

## 4. hostapd 崩溃（本轮前一段，简述）

- 12:41:41 hostapd SIGSEGV；此后 ra0/rai0 仍发信标（驱动 apcfg），但无 EAPOL，
  客户端 `authorized:no` → `reason=3` 自断重试。
- 判据：`iw dev rai0 station dump` 的 `authorized: no` + hostapd 控制套接字只剩
  `global` 桩 + hostapd 日志 0 字节。
- 修复：`wifi_up.sh` 在线重应用（MLO 必须先下电到冷启动等价态），17:30:19 完成；
  手机 17:30:18 握手 + DHCP 192.168.9.123。
- **watchdog v1.18**：hostapd 自愈（存活 + `state=ENABLED` 双判据，下电等价态重启，
  限频 3 次/小时）。受控杀进程实测 13 秒恢复。

## 5. watchdog 硬化（v1.19 → v1.21）

| 版本 | 变更 | 触发原因 |
|---|---|---|
| v1.19 | wan_agg 自愈 | 16:26 静默死亡 → WAN 灯/GUI 误报 |
| v1.20 | `alive()` 双判据（pgrep + 锁文件 pid + `/proc` cmdline 复核）；看门狗自身单实例锁；fan_mgr 自愈；用户态 fault 计数 WARN | SIGSEGV 会打死 pgrep → 重复拉起（3×wan_eth / 2×log_keeper / 2×watchdog）；fan_mgr 只检不拉（现场 PWM 停在 60） |
| v1.21 | fault 计数移出 `$STATE` → `/tmp/watchdog_faultcount` | selftest 把 `faults=1` 当“未恢复故障” |
| selftest v2.43 | 5G 灯测试只数常驻 led_mgr（排除 `--dry-state`） | `daemon=2` 假阳性（测试自身的一次性进程被计入） |

实测：第二个 watchdog 实例启动即 `already running pid=…` 退出；fan_mgr 被杀后
watchdog 立即拉起；自检 **83 pass / 0 fail**。
