## 1. 关键工程记录

1. **验证方法教训（本轮最大方法收获）**：二进制补丁的正确性验证必须是"**三态对照电池**"
   （stock / 补丁 libc+原应用 / 补丁 libc+补丁应用，30 命令组 diff）——单命令冒烟不足；
   且**已知设备怪癖必须先建档**（grep -r 的 stock 崩溃差点被误判为补丁缺陷）。
2. **v4 补丁器**（tools/oneoff/varpro_patch_v4.py）：shape-A 需 ≥1 GP 保存对前置 + 后随
   600 指令内无 q 回读；libc 140 站点（v2 191，排除 51）。
3. **持久化实现**：rc19 v2.40 插入点= PATH 设置后（t≈27s，早于守护启动）；自检失败即跳过
   并记 kmsg；DISABLE 文件=一次性禁用开关；回滚=`umount /lib/libc.so`（新进程即恢复）。
4. **未覆盖原因（诚实）**：busybox/wpad/dnsmasq 的自身变参路径需二进制补丁；当前补丁器对
   优化二进制存在过匹配风险（gw 静态 busybox 事故 + busybox 挂载态偶发）——24h 窗口以
   稳定性优先，二进制补丁留待"补丁器 v5（逐函数语义复核）+ 沙箱"后再上。
