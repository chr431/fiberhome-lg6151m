# 02 · 调查方法论（唯一方法源）

> 目的：让下一轮调查**可预注册、可复核、可撤回**，避免“每轮换一个叙事、旧结论继续被引用”。
> 本文件是规则，不是建议；与旧文档冲突时以本文件为准。

## 1. 证据分级

| 级别 | 定义 | 允许的表述 |
|---|---|---|
| **E0** | 猜想/单次未对照观察 | “假设/可能”，不得写“已证实” |
| **E1** | 单次对照观察，或有一个正对照但覆盖有限 | “观察到”，不得外推 |
| **E2** | 有正/负对照、覆盖明确、可复现一次 | “在本实验条件下成立” |
| **E3** | 独立重复（不同窗口/样本/仪器）一致 | “已确立（在所述范围内）” |
| **E4** | E3 + 机制级证据（PC/指令/字节级）+ 正负对照 | “机制已确立” |
| **X** | 已撤回 | 只允许出现在 tombstone/历史 |
| **?** | 未决 | 不得被引用为事实 |

规则：

- 每条结论在 `01_CLAIMS.tsv` 占一行；**没有行 = 没有结论**。
- 一个“0 命中”最多 E1，除非同时给出 **N + 检出下限（LOD）** 和正对照；满足才可 E2。
- “已证实”只能用于 E3/E4；E0/E1 只能写“观察到/提示”。
- 同一结论被新证据推翻时，旧行改 `retracted`，填 `supersedes`/原因；**不删除**。

## 2. 预注册模板（每个实验必须先填）

复制 [TEMPLATE_EXPERIMENT.md](TEMPLATE_EXPERIMENT.md)，至少包含：

1. **问题**：一句话，可判决。
2. **假设**：H1（要检验的）与 H0。
3. **预测**：H1 为真时，哪个仪器、哪个读数、什么方向、多大。
4. **判据**：通过/失败/无效的**数值**边界；无效条件（例如 60s 内自崩）。
5. **样本量/功效**：预期事件数、过散假设、能检出的最小效应；不足则写“探索性”，不得写“无效应”。
6. **混杂**：时间、流量、温度、负载、模块、受害者数量、handler 递归；如何随机化/分层/配对。
7. **停止规则**：什么情况下提前停（设备坏、自动回滚、安全性）。
8. **分析计划**：主终点、次终点、统计模型、是否看中期。
9. **变更记录**：实验后只追加“结果/判决/偏差”，不改预注册正文。

## 3. 探针有效性清单（每个探针必须回答）

| 项 | 问题 |
|---|---|
| **测量对象** | 它测的是写入、崩溃、页签名、还是代理量？ |
| **覆盖** | 哪些函数/上下文/CPU/地址范围？漏了什么？ |
| **正对照** | 故意触发一次，仪器是否能记录？记录字段是否完整？ |
| **负对照** | 不触发时是否为 0？噪声底是多少？ |
| **arming** | 从 insmod 到实际生效的窗口？是否所有 CPU 可见（icache/TLB）？ |
| **饱和** | 计数器/ring/日志是否有上限？上限到了会怎样？ |
| **观察者效应** | trampoline 栈、dump_stack、pin、PTE 改动、日志 IO 是否改变现象？ |
| **独立性** | 两个“证据”是否其实来自同一次观测/同一个 handler？ |
| **日志完整性** | 时间戳、boot id、pid、comm、CPU、参数、是否有丢行？ |
| **检出下限** | 0/N 时，N 是多少？在预期速率下，LOD 是多少？ |

**硬规则**：没有正对照的探针，其阴性只能标 E1；没有 LOD 的 0，不能写“排除”。

## 4. 统计方法（阵发/过散过程）

### 4.1 先看过散

对同一状态的崩溃间隔/窗口计数：

- 计算方差/均值比（dispersion）。若 > 1.5，**不要用 Poisson**。
- 用负二项回归/置换检验；报告 `rate ± CI` 与过散参数。
- 不允许用“0/71，Poisson p=2e-5”这种单点 p 值作为强结论；必须说明过散下的敏感性。

### 4.2 A/B 设计

- **随机化/交错**：A/B/A/B 按窗口交错，或按受害者随机分组；禁止 A1→B1→A2→B2 的顺序臂。
- **同窗对照**：同一时间窗、同一 fleet、同一流量状态；至少一对同时进行的臂。
- **预注册样本量**：按预期事件数和最小可检效应算；每臂 <20 起时，只能写“探索性”。
- **TTC/生存分析**：有 censoring 时用 Kaplan-Meier/log-rank，不用均值 t 检验。
- **中期看数据**：要么不看，要么预注册 alpha spending；不得看到显著就停。

### 4.3 零结果

- 写 `0 / N`，并给出 LOD：
  - 页扫描：`pages × rounds × 每页写入概率`；
  - 时间窗：`rate × exposure`；
  - hook：`calls × 命中率`。
- 例：`uw` 20s 窗口、写者 ~1/min，则 LOD ≈ 0.33 次；0 命中不能排除 1/min。
- 例：`cth` 的 `g_hit` 上限 4000；若窗口内 32B copy >4000，0 命中可能是截断，不是没有。

### 4.4 多重比较/子组

- 主终点预注册；子组（家族/受害者/模块）只做探索，标 E1。
- 热点/空间分析：桶间空间相关；扫描截断时低址前缀偏置；用全量/随机顺序 + FDR。
- 任何“按家族拆分后显著”的结论，必须报告拆分前的总体和拆分理由。

## 5. 样本来源（每个数据集必须记录）

| 字段 | 例 |
|---|---|
| 受害者二进制/哈希 | `vsurv3` sha256、build id |
| 构建/部署 | 编译命令、zig/gcc 版本、部署 md5 |
| ASLR | 开/关；栈地址是否固定 |
| handler | 是否安装、是否 async-signal-safe、是否 SA_NODEFER |
| core/栈转储方式 | core_pattern 管道/文件、栈页数、是否 post-handler |
| 时钟 | `date +%s` vs `/proc/uptime`；`ntp_synced`；boot id/btime |
| 模块/参数 | `lsmod`、模块参数、vermagic |
| 流量/负载 | WiFi/eth/ccmni 状态、吞吐、fleet 数量 |
| 排除规则 | 自测进程、kill -SEGV、comm=?、unsync |

**规则**：不同来源的数据不得直接合并算速率；先按 `family × victim × state` 分层。

## 6. 家族分离

| 家族 | 签名 | 样本 | 因果状态 |
|---|---|---|---|
| **A** | `{r180|r094, r1e0, bat_va, bat_pa+8}` | 3/7 cores | 记录在 fault-time va_list；dpmaif 源 |
| **B** | `{A,0,{len,ip},0}` 或 `{B,0,A',0}` | 103/106 canary dumps | 记录在 fault-time va_list；网络流源 |
| **C** | 其它小值/自指 | 3/106 | 未定 |
| **D** | 非记录自然崩溃（awk poison/NULL/负偏移） | 自然 core 样本 | 独立 bug |

规则：

- **A/B/C 不得合并**算“记录率”；**D 不得混入记录家族**。
- 任何“总崩溃率”必须写成 `rate_A + rate_B + rate_C + rate_D` 或注明混合比例。
- 报告“记录导致”的比例时，必须同时给“记录在场但不因果”的计数（如 `sh.core`）。

## 7. 变更控制（设备侧）

1. **一轮一个变量**；其余参数冻结并记录。
2. **可回滚**：模块/脚本必须有一键回滚；改内核 text 的探针必须有 auto-revert + 用户态确认。
3. **安全网**：串口/物理断电通道；不要依赖被改代码的 SSH/Web。
4. **部署**：走 `deploy.py push/put`；exec 型脚本 `chmod 755`；部署后 `doctor` + 冷启动验证。
5. **manifest**：构建哈希、vermagic、模块参数、起止 uptime、`lsmod` 前后 diff、boot id。
6. **事故**：任何 Oops/重启先保全 `console-ramoops`/串口原始日志，再继续。

## 8. 文档规则

- `00_STATE.md`：一页纸，只写“现在该信什么/下一步”；每周或每个实验后更新。
- `01_CLAIMS.tsv`：唯一结论表；新增/撤回都改这里。
- `05_LOG/`：每轮一个文件；预注册在实验前写；结果/判决追加；不删旧内容。
- 旧 `docs/SIGSEGV_*.md`：只归档，不静默改；顶部加“历史/已撤回”头。
- 任何报告/部署/对外说明引用结论时，必须带 `C-xxx` ID。

## 9. 复核节奏

- **每个实验后**：更新 `01_CLAIMS.tsv` + `00_STATE.md` 的“下一步”；在 `05_LOG` 写判决。
- **每周**：抽查 3 条 E2+ 结论，确认证据文件仍在、数字可复算；失效则降级。
- **每月**：检查一次“旧结论是否仍在被引用”；tombstone 是否完整。
- **任何新叙事出现时**：先问“它推翻了哪条 C-xxx？证据是什么？旧行改了没有？”

## 10. 反模式清单（出现即停）

- 用单窗 A/B 宣布“无效应/有效应”。
- 用 `hits_now`/饱和计数器当人口。
- 用页尾 0xfc0 的采样代替全页。
- 用“0 命中”排除一个没有正对照的机制。
- 把 canary 的崩溃率/记录家族外推到自然 NE。
- 把“记录在栈上”当成“记录导致本次崩溃”。
- 把两个家族混成一个“总速率”。
- 把“修好了”与“看不见了”混为一谈。
- 在同一个窗口改两个变量。
- 用聊天/轮次文档里的数字，不回查原始台账。
