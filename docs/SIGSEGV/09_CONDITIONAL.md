# 09 · 命中的条件分布（R4，2026-11-01）

前置（见 [08_CORRELATION.md](08_CORRELATION.md)）：写入者锁定在**有线端口共用 EDMA RX 的「每 RX 包一次机会」路径**，
速率 1.3 ± 0.2 命中/千包；具体时序窗口未定位。

本文回答：**命中在时间、记录字段、流量形态上的条件分布是什么？**

## 方法

- 数据：设备 `/data/repro/h4_*.bin` 全量 **2554** 份（canary 转储，每份 120B 头 + 8×4KB 栈页）。
- 提取：`/data/repro/h4_meta.sh` → 每文件一行 `file ts pid hit x2 top fault_addr`（`fault_addr` = 记录 word0）。
- 拉取：分页 + **行数断言 2554 == 2554**（规避"大输出截断"坑）。
- 分析脚本：主机侧 `_local/evidence/crash-root/h4_meta.txt`。

## 结果 1：命中在时间上**成簇**，且存在「同秒多 canary 中招」

2322 次近期命中（ts > 1793000000）分布在 **1350 个不同秒**。

| 同秒内**不同 pid** 数 | 秒数 |
|---|---|
| 1 | 1057 |
| 2 | 273 |
| 3 | 19 |
| 4 | 1 |

- **293 秒（21.7%）有 ≥2 个不同 canary 在同一秒中招** → 存在「一次事件影响多页 / 共享物理页」的机制，
  不只是各 canary 独立受害。
- 同一 canary 相邻命中间隔：**p10 = 0 s**、p50 = 2 s、p90 = 33 s、p99 = 2232 s、max = 6382 s。
  p10 = 0 意味着 **10% 的相邻命中落在同一秒内** → 强突发性，**不是泊松稳态**。

**含义**：若写入是"每包独立、每页独立"的均匀过程，同秒多 pid 命中会稀少；实测 21.7% 的秒出现多 pid，
说明存在**突发窗口**（例如一批 RX 完成/一次环操作在极短时间内连续写多页）。

## 结果 2：记录 word0（故障地址）**既不是包长也不是环槽位**

- 1723 / 2322 的 word0 < 1 MB；**1604 个不同取值**。
- 高频重复值：`58511 (0xE48F) ×44`、`55439 (0xD88F) ×33`、`2103 (0x837) ×19`、`76943 ×8`、`252555 ×4`。
- 落在「包长区间 [0x500, 0x700]」的只有 **2 / 1723** → **word0 不是包长**。
- 取值范围 2103–85403，远超 512 项 RX 环的索引范围（0–511）→ **不是环槽位索引**。
- 但**同一取值反复出现**（0xE48F 出现 44 次）→ 更像**计数器 / 序列号 / 时间戳类字段**，而不是地址。
- 附带确认：`top - x2` 在 **2322/2322** 恒等于 **912 (0x390)**（与既有 C-052 一致）。

## 结果 3/4：包长相关性与 CPU 相关性 —— 待流量形态实验

设计（各 60 s，比较「命中/千包」）：

| 臂 | 工具 | 形态 |
|---|---|---|
| L 大包 | `_local/lan_rx_gen.py --rate-mb 2` | ≈1400 B/包、~1500 pps |
| S 小包 | `_local/lan_pkt_flood.py --pps 20000 --size 64` | 64 B/包、20k pps |

- 若 S 臂「命中/千包」显著高于 L 臂 → **小包（高包率、低字节）更容易触发** → 指向"每包固定概率"而非"每字节"。
- 若两臂相同 → 与"每包一次机会"一致，包长无关。
- CPU 相关性：采样器已记录 per-CPU softirq，可在命中密集时对比各 CPU 的 NET_RX 增量。
