# U-G9 · 自我关断实验:DRM 页 NS 写保护 + emicen 监视器 = 两条候选全部出局

> 时段:2026-11-06 00:53–01:05(+0800)｜授权:"开下一轮,测试这些点……遇到必须手动重新上电的情况就停下来"
> 结果:**两次复位,全部自愈(无需手动上电)**——#22 自伤(未对齐 MMIO 读,对齐故障 Oops)、#23 emicen init 总线挂死;
> 两次死亡 dump 均被串口捕获。设备收尾健康、无残留。

## 0. 一页结论

| 测试点 | 结果 | 等级 |
|---|---|---|

## 1. 实验链(时间序)

1. **00:53 预检**:设备 up 1:07;三 kmod 就位;无 KASLR(运行时=本地 kallsyms);基线 CTL=0x8303、companion=0x02ff;
   emicen drvdata: global=0xffffffc009232aa0→heap;ch=2/rk=1;enable(+0xf8)=0。
2. **00:54 基线窗**:受害者+2400pps;λ=33 命中/90s(≈22/min);SQL 写入者活跃。
3. **00:55–00:56 DRM 魔术写四连**(每次读回):B 原值(0x55008303)→0x8303;C1 清 bit15(0x55000303)→0x8303;
   B16 置 bit16(0x55018303)→0x8303;companion 0x10005034(0x590002fe)→0x02ff。**全部不变**⇒ 页写保护。
4. **00:57 崩溃 #22(自伤)**:peek MMIO base+0xf04 用 8 字节未对齐读 —— Device 内存要求对齐,触发
   `Unable to handle kernel paging request at ffffffc009afdf04` + `Oops 96000021`(=DFSC 0x21 对齐故障),
   WDT 复位;ATF dump 捕获(K:4275,DDRPHY+0x1520=0x8008)。**教训已入 AGENTS**。
5. **00:58 恢复**:设备自愈(up 1 min,启动门过);重载 kmod、重启受害者(λ=26 命中);重取新 drvdata。
6. **00:59 崩溃 #23**:`call mtk_emicen_emi_monitor_init(2)`(厂商 API,经 emiuctl)→ SSH 当场断线;
   串口显示无 Oops、纯挂起、WDT 复位(K:179 dump,DDRPHY+0x1520=0x8008)。设备再次自愈,无启动环。
7. **01:01–01:05 收尾**:设备健康(启动门 `wifi_up done`)、受害者/kmod 随复位清零、/data/tmp 只余 5 件仪器;
   受害日志与串口全量归档 `_local/evidence/b4b/ug9/`。

## 3. 对判决的影响

- **"自己关掉引擎"的路线正式关闭**:DRM 页(唯一破译了写协议的调试控制面)对 NS 只读——厂商 OTA 若靠它,
  必须走安全固件;**emicen 监视器在写者活跃时本来就是关的**,且启动即挂死——不可能是写者的手柄。
- 写者行为在两次复位窗口内**持续存在**(λ>0,含 init 调用前的窗口),再次与"无可达手柄"一致(C-266/C-272 不变)。
- 残余唯一路线不变:厂商文档/EL3 调试固件/边界事务截获——本机不可达。
