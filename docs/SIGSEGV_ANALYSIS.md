# SIGSEGV 崩溃家族：结论汇总（v3 重写版，2026-10-27；§11 身份判定 2026-10-28）

> 本文只保留两类内容：**经实测确认的结论** 与 **已被证据否证的假设**。
> 2026-10-22 至 10-27 之间的 14 轮调查过程不入正文，见 §9 归档说明。
> 正文中 `…` 包裹的是文件名、函数名、寄存器或代码片段。

## 1. 机制（已验证）

| 环节 | 结论 | 状态 |
|---|---|---|
| 污染存在 | 空闲页里持续出现 16/32B 结构化记录；全量扫描密度约 **0.15%**（439 页 / 269k 空闲页） | 已证实 |
| 落在空闲页 | 约 66% 曾被签名的 PA 在多次扫描中反复出现 | 已证实（口径见 §2.3） |
| 落在用户页 | 绊网在用户 anon 页上活捉到记录；core 里的故障地址就是被覆盖后的 va_list 指针 | 已证实 |
| **写入者不在 AP 可达范围** | AP 侧三条可测通路都不产生陈旧 PA，见 §3 | **已证实（阴性）** |
| 受害者差异 | 按污染块落在哪个结构上而不同：va_list 崩溃 / NULL 解引用 / .bss 指针损坏 | 已证实 |

**关键不等式**：printf 家族只是**最高频的污染内存解引用路径**（选集效应），不是缺陷所在。
musl 的 `pop_arg` 本身健康；坏的永远是外部写进去的值。

## 2. 已验证判据（照抄使用，不要自己发明）

### 2.1 注入块签名

- **长度型 16B 块** `{small, 0}`：small ∈ [0x2710, 0x40000] ∪ {0}，非单调；
- **指针型 16B 块** `{0x9xxxxxxx, 0}`：值域落在 RAM 段（如 0x92d7a600 族）——与长度型是**两类**，
  识别现场时两类都要查；
- **32B 块** `{small, 0, 0x????????_0000_06xx, 0}`：低 32 位落在 0x6xx / 0x1180 族；
- 同页可多块（16B 节距）；页尾 0xfc0 起（word 504+）**高发**——但见 §7.5 的取样偏差说明；
- **禁止用 magic 值当指纹**：高 32 位在现场间会变，只能作个案旁证。

### 2.2 va_list 健康判据

- 三个指针字段（`__stack / __gr_top / __vr_top`）应落在用户态可访问范围；
- **`*_offs == 0` 不是坏值**：第 9+ 个变参正常走 `__stack`；
- 健康基线三个指针都指向栈，offs 为负的小常数。

### 2.3 速率口径（引用时分子分母缺一不可）

- 计数器 `distinct` 是**累计新增 PA 数**，必须用**平台期速率**，不能用启动瞬态；
- `hits_now` **不是人口测量**（见 §7.1）；
- 引用任何速率必须写清：来源台账、观测窗口、排除规则、过滤状态。

### 2.4 内核 fault 行读法

arm64 是 `unhandled exception: DABT`，方括号里是**故障指令所在 VMA**，不是数据地址。
用户态 NE 只认 `/data/gw/logs/ne_events.tsv` 与 `aee_exp` 目录 mtime——**console 与 syslog 都不收**。

## 3. 写入者：已证实到哪一步

三条可测通路，全部在**真实蜂窝 RX 满载**下测过：

| 通路 | 条件 | 结果 |
|---|---|---|
| dpmaif PIT 环（16B 项） | 31.5 ms 同刻配对，821 次描述符改写 | **0** 次写入已释放页 |
| dpmaif BAT 表（8B 项，真正的 PA 表） | 满载 4900 次/秒 churn，**98 万次**改写 | **0** 次写入已释放页 |
| MD 共享内存（66 MB + 1 MB，经驱动 vmap） | 全量 9 轮，严格 2 KiB 对齐判据 | **没有地址表**；命中率**低于随机基率** |

第三行的方法值得记：若 MD 维护缓冲页 PA 列表，它应当稠密。实测对齐 PA 形字只占
**0.0048%**；且真命中的页 **73.9% 空闲基率下只有 1.81% 落在 buddy**，比随机**低 40 倍**
——说明它们指向的页比随机更常被持有，不是悬空引用。

**结论**：写入目标是一个 **AP 完全不可观测的地址集合**（稳态与运行态翻转下均然；
FRG 表 qctx+0x4500 经 2026-10-27 夜 dpscan9 审计：2048/2048 项非零、全部指向持有页——
该缺口已补测，见 §10）。

写作时注意区分两件事：
- 「写入者在 MD 侧」是**排除法结论**（AP 三条通路都干净），**不是**直接观测；
- 「写入内容与 DPMAIF 环记录同族」的原始读数（同值两次注入两个不同用户页、活 PIT 环尾值）
  **没有主机落盘**，只能作旁证。

## 4. 已被证据否证的结论（勿再引用）

| 结论 | 否证依据 |
|---|---|
| 家族根因 = musl printf / stdio 的 va_list 缺陷 | 坏值由外部注入；1465 次 TX dma_map 零坏页 |

| ip `filter.label` 独立越界写缺陷 | 同上（.bss 整页 16B 节距喷射 = 主机制） |
| 「驱动把用户页交给 DMA（栈上构造描述符）」 | findpa 自命中扫描器自身内核栈；1465:0 反证 |
| 崩溃率与蜂窝流量同窗 | ccmni0/3 近零仍命中；写环记录与 PDP 流量无关 |
| 静态化 / 换组件 = 根因修复 | 静态件同崩 |
| 静态链接使崩溃路径物理消失 | 同上 |
| 硬化 vfprintf 「彻底消除崩溃」 | 它只是拦截；guard 会误伤长参数列表 |
| 拨号可复现注入 | 重复拨号 0/0；非确定性 |
| `md+0x4098` / `md+0x4520` 字段模型 | 两次猜错，已放弃 |
| 「活 BAT/PIT 表与全部 dpmaif 寄存器零陈旧」 | 全称否定被单点反例推翻（+0x180 曾指向已回 buddy 的页）；且原测法是一次性快照、每窗仅前 0x200、PA 上限截在 0xa0000000、未跨 stop/start |
| 「陈旧缓冲页集合约 400 个固定 PA、不增长」 | 自身台账 distinct 242→809→3720 已证伪「不增长」 |
| 「任一时刻只有约 48 张空闲签名页」 | `hits_now` 是 `maxhits` 饱和值（48/64 随参数变）。归档全量计数：一个 boot 的异常低值 101，其余 394–453（§8.24 表）；不存在「200–250」的测量出处 |
| 「污染集中在 0xa4000000–0xa6000000 这 32MB」 | 扫描在命中 maxhits 后即停，报出的是**扫描路径前缀** |
| 「污染页空间上弥散聚类」 | 分母取错列：439 页只落在 **56** 个 4MB 块（非 322），均 7.8 页/块，最大块 38 页 = 8.7% |
| 「dpmaif stop 路径先归还 RX 页、后等 ack」 | 反汇编实测为**先等 ack 再还页**（disable_irq → stop_hw → stop_tx_sw → stop_rx_sw） |
| 「PIT 项里放的是 PA」 | PIT 项是 **16-bit BAT 槽号 + u16 长度**；PA 只在 BAT / FRG 表里 |
| 「活跃环任何时刻有 195–247 条描述符指向 buddy 页」 | 那是「像 PA 的字」，不是描述符；PIT 项不含 PA |
| 「MD 共享内存 AP 结构性不可读」 | 线性映射读不到 ≠ 不可读：驱动为它建了 vmap，66 MB 全部可读 |
| 「MD 共享内存里有陈旧 PA 列表」 | 严格对齐判据下密度 0.0048%，命中率低于随机基率 40 倍 |
| 「dphook ringwatch 24 分钟零写入」 | 判变化用页尾 8×u64 xor 折叠，对同值重写天然失明；且只读基址那一页的 48B |
| 「dpclamp whits = 0 说明写入者安静」 | 同一读数被用来同时支持「拦截有效」与「写入者无剧集」两个相反结论；仪器三处失明 |

## 5. 已被实验排除的修复方向

| 方向 | 排除理由 |
|---|---|
| dpquar / dpclamp 页隔离栈 | 无实测收益（`held=0/16384`，42,310 次钩子调用）+ 三次内核级事故；已整体退役 |
| 牺牲页池（用户态扣住页） | 前提「列表固定 ~400 页」被否定；且唯一指标被饱和仪器污染，只能算「未测出变化」 |
| memmap 预留热点区 | 依赖「失效 PA 跨重启稳定」，实测跨 boot 仅约 12 页重合；且当时的热点结论本身已作废 |
| 分配时检查 / 分配时擦洗 | 内核在 **分配时就把匿名页清零**（`alloc_zeroed_user_highpage_movable`），交付路径上扫签名必为 0 |
| 周期自扫长期持有的页 | injcount 单窗 20 s×16,384 页，按 injwatch4 实测速率期望命中 ≈0.2，「0」基本无信息量（违反 §7.1 自己的 0/N 纪律）；该批页还是新分配页而非老页。方向可能仍对（成本论证独立成立），但证据降级为不足 |
| 扣住空闲页 | 前提未立，且判据不可靠 |
| 在 AP 侧加/减负载 | 六重独立排除：churn 突发、spawn 突发、守护舰队全停、WiFi 停、跳过定时重启、负载内存相关性 |

## 6. 仍未解决

1. **写入目标地址的来源**。⟦2026-10-28 凌晨（§11）身份已判：写入控制在 **MD modem 侧**
   （驱动 unbind 后照写、EPOF 后全停、引擎未编程时关闭、引擎实时读表消费 canary）。
   剩余未解只是 MD 域内部的细分，AP 侧不可分：⟧
   - MD 固件自行维护的目标页列表/游标（受害页 ∉ 环形缓冲池，目标散布全 DRAM）；
   - dpmaif 引擎在 MD 指挥下的 DMA（内容含 {BAT 基址, 生产指针} 活值对，引擎状态可及）；
   - MD 内部 RAM（非共享内存部分）参与的路径。
   ⟦注：「注入内容 = 实时读 AP 寄存器」已由 §11 收窄——活值对与引擎/MD 内部副本不可分。⟧
2. **剧集触发条件**（原目标）。AP 可观测范围内已穷尽。
3. **加频重启是否有效**。预登记判据写的是「崩溃继续 ⇒ 累积效应成立」，实测正是继续
   （5.12/h vs 3.40/h），但比值 95% CI 0.57–4.02 含 1，**功效不足**，该候选**未被否证也未被验证**。
4. **跨 boot 稳定性**：只有 2 个 boot 的样本。
5. **§8.16 解引用前指针闸门**是否真能拦住：形态上高度可行（注入值 0x1698c / 0x????????_0000_06xx
   离合法栈指针极远），但**没有拦截率实测**。这是目前唯一有证据支撑的 AP 侧缓解方向。

## 7. 仪器与读数边界（本轮最大的方法论产出）

**任何「零」都必须写成「0 / N 次观测，检出下限 X」。** 以下每条都曾导致过错误结论。

1. **`hits_now` 是 `maxhits` 饱和值**，不是人口测量。且 `maxhits` 截断的是**遍历**：
   每轮从最低址重来、凑满即停，于是 `distinct` 是**低址前缀速率**。
   **全量扫描只要 0.09 秒**（min 0.07 / max 0.11），没有任何理由用截断值。
2. **用摘要判变化 = 对同值重写失明**。页尾 8×u64 的 xor 折叠会漏掉「写相同值」，
   而那正是本项目记录的主要写入形态。判「零写入」必须**比内容**，不许比摘要。
3. **`copy_from_kernel_nofault` 不防 SEA**。它的 nofault 只覆盖能经 extable 修复的普通缺页；
   Synchronous External Abort 直接走 `do_sea → die`。**2026-10-27 19:56 我们因此重启过一次设备。**
   判断依据必须是「这块映射是否已被证实可读」，不是「我用了 nofault 函数」。
4. **vmalloc 地址跨重启不稳定**。驱动 vmap 的 VA 必须运行时从 `/proc/ccci_dump` 解析后传入。
5. **只在页尾取样会制造偏差**。历史上两台仪器都只在 +0xfc0 读，所以「页尾高发」里有取样位置贡献。
6. **计数器先查上限，再谈「噪声 ≈ 0」**。饱和计数器给出的「恒定值」是最有欺骗性的一类读数。
7. **每次运行必须落 manifest**：构建哈希、vermagic、全部模块参数、起止 epoch、`/proc/uptime`
   前后值、`lsmod` 前后 diff；数据文件第一列恒为 wall_epoch。
8. **时间基准**：`date` 与 `/proc/uptime` 是两个 fork，重载下会跨秒；用 uptime 重建排序键。
9. **热路径 O(1)**：内核钩子在锁内做 O(n) 扫描会二次方不可抢占 → panic_on_rcu_stall 重启。
10. **设备侧命令串禁止出现 `$`**：会被本机 bash 展开。已因此出过一次把聚合模式切错的事故。
11. **写循环边界必须与目标数组容量当场核对**（2026-10-27 dpscan9 v2 事故）：`for (off=0x4400; off<0x6000; off+=8) g_dump[i++]`——注释写 0x4400..0x4600/64 项，循环写到第 889 项越界踏出模块映射页 → Oops 整机重启。pstore console-ramoops + kern_an.py 反汇编 `copy_from_kernel_nofault+0xa8` 三分钟定位（WnR=1、dst=&g_dump[889]）。nofault 本身无辜——错在自己的写目标越界。
12. **生产指针不能当代际判据**：dpmaif `+0x094` 随流量持续走位，若进 generation-change 触发集会制造 retire/reuse 洪水（dpscan9 v3→v4 修正）。寄存器入触发集前先看它是否单调游走。
13. **`initcall_blacklist` 在本 vendor 内核失效**（2026-10-28 B1 轮实测）：参数确认进入
    `/proc/cmdline` 但目标 initcall 照常执行、无 blacklisted 日志。平台级阻断不能依赖该机制。
14. **buddyscan 累计 `distinct` 在无重写场景 = 陈旧页显现**（2026-10-28 A2 轮证明）：
    写入者已被独立证据判停时 distinct 仍以 ~10/min 爬升（allocator churn 暴露上 boot
    签名）。判「写入活性」只能用**新清零页命中**（injwatch mmap 轮换）或**值变化**，
    累计数爬升一律不采信。
15. **仪器日志必须带时间戳**：injwatch4 命中行无时刻，本轮只能靠 log mtime + 事件锚
    反推（A 轮命中恰好以 mtime 判入 exec 后侧）。新仪器落地时时间戳是第一列。
16. **内核 ring 的 drain 读指针防下溢**（2026-10-28 下午 pitfull/pitctl 轮）：
    `cur < g_seq - RING` 在 `g_seq < RING` 时 u64 下溢为巨值，**读一次即把读指针永久
    推到 seq 之外**，此后一切 drain 返回 0——两台仪器全部明细记录（~46k 条）因此丢失，
    只余 SUMMARY 计数。判据：done 报 `drops≠0` 而 `seq<RING` 即是此 bug。正确写法
    `cur + RING <= g_seq`。**任何带 ring 的仪器首读必须先验此路径。**
17. **msleep 实际节拍受负载挤压**：本机 `msleep(25)` 实测 ≈ 名义 6.1×
    （100s 名义 → 613s 墙钟；300s → 615s）。内核轮询仪器的时间预算必须按墙钟估，
    否则窗口会被低估 6 倍。
18. **后台 `insmod … &` + 轮询循环会并发第二实例**：模块加载串行化，第二个 insmod
    阻塞占住模块引用 → rmmod 失败、proc 文件被未知持有者钉住。装载必须单实例守卫
    （先 `lsmod | grep` 再装），清理时按 `/proc/<pid>/fd` 扫持有者。

## 10. 补充实验：运行态翻转阴性扩大 + 写入内容 = 实时寄存器快照（2026-10-27 夜）

仪器：`tmpfiles/repro/dpscan9.c`（表页全生命周期监视：基址寄存器 250 ms 轮询、
表页**全页内容比对**（非摘要、不限页尾）、释放即退役、退役页写入事件带写入时刻
页态；FRG 表顺带审计）。原始台账：设备 `/data/repro/bw9_{main,state,iw,trig}*` 与
`/data/repro/bw9b_*`；manifest：`tmpfiles/repro/bw9_manifest.txt`。

**轮一（稳态，uptime 785→1942 s）**：四级触发——`AT+CFUN=1,1`、`AT+CFUN=0`
（MD 下电 90 s）、`AT+CFUN=1`、`ccmni0 down/up`——BAT/PIT 基址寄存器、
bat_va/count 全程不变（GEN=0），表页从未释放（RETIRE/STALE=0），
退役页写入 0。同窗注入活跃：~40 签名页/轮、injwatch4 5 次用户页命中，
其一的值嵌**当 boot** 的 BAT 基址 0x90660000。

**轮二（抓开机，uptime ~70→1310 s）**：覆盖 MD 附着/承载建立。GEN=0

## 11. 写入者身份、行为与止写（2026-10-28 凌晨，串口+破坏性授权轮次）

仪器与台账：`tmpfiles/repro/bw10.py`（串口轮次驱动：sysrq-b → Ctrl-C 弹幕抓 LK →
`kcmdline append init=/bin/sh` → raw shell 早期装载 → 静默相 → `exec /etc/preinit` 续正常启动）、
`bw10_boot.sh` / `bw10_unbind.sh` / `bw10_canary.sh` / `bw10_mdstop.sh`（设备侧自驱）、
`holdwatch`（用户态 canary 持有/监视器，zig musl 静态）、`dpwr.ko`（/proc/dpwr MMIO 写）。
数据：设备 `/data/repro/bw10_{A,B1,U1,C1,D2,A2}_*`；预注册与逐轮判决：
`tmpfiles/repro/bw10_manifest.txt`。

### 11.1 身份：MD modem 侧（四轮交叉判定）

| 轮次 | 操纵 | 注入响应 | 判定 |
|---|---|---|---|
| U1 | sysfs unbind `10011000.dpmaif`（rc=0，driver symlink 确认消失） | r094 同速率前进、表页 live_chg 持续涨、注入照写（12 命中，含 unbind 后 r094 **活值**），速率同量级 | **AP 内核驱动不是开关** |
| D2 | `AT+EPOF`（返回 OK；r094 前进 ~0xe0 后冻结） | MD 死窗 12+min × 256 MB（65536 新清零页）**零新命中**（若继续期望 ~7，p≈1e-3） | **MD 断电 = 全停** |
| A2 | `init=/bin/sh` 不续启（无用户态；r094 恒 0、表未建） | 71 轮 × 65536 页 **0 命中**（期望 ~10.7，p≈2e-5） | **引擎未编程时关闭** |
| C1 | BAT 表尾 4 槽写 canary | **20 s 内被消费**：canary 页整页 RX 载荷 DMA（t=20s 起，t=173s 复填） | 引擎**实时读表**取项并按项 DMA |

结论：写入控制在 **MD modem 侧**（固件，或受其指挥的 dpmaif 引擎 DMA）。
注入活跃 ⟺ r094 前进（引擎已编程且在产出）；驱动绑定态无关。
物理写代理是「MD 固件 CPU 经 DBB 直写」还是「引擎 DMA」在 AP 侧不可分，
但两者都在 MD 电源域、同受 EPOF 控制——对止写而言等价。
（B1 附带发现：`initcall_blacklist=cci_hif_dpmaif_init` 进入了 cmdline 但本 vendor
内核**不拦截**，dpmaif 照常 probe——该机制在本平台不可用。）

### 11.2 行为：写什么 / 写哪里 / 何时写

- **内容**（word 504 起，16/32B，三轮 + U1 22 命中普查）：
  (a) `{BAT 基址, 生产指针}` **活值对**——lo32 恒 = 当 boot r180，hi32 落在当轮 r094
  观测区间内（B1 一命中恰等于观测值 0x92fa0010）；
  (b) 小值计数（0x15fb7..0x2bac0 族）；
  (c) 字节递增序列（`0x0605040302010000` = 字节 00,01,02,03,04,05,06）及旧 32B 形态。
  **同值重写直接观测**：同 PA 七轮重复同值（每轮 mmap 新清零页，非零即新写）。
- **目标**：受害页**不是**环形缓冲页——同 boot 13/13 命中页 ∉ 当 boot 16384 项表
  PA 集（池 0x8f870040..0xa0d77840 跨 277 MB，受害页散布 0x8f-0xb5 全 DRAM），
  固定页尾 0xfc0。目标来源仍属 MD 内部状态（§6.1 保留项）。
- **时机**（boot 时间线，串口 initcall_debug 全程留档）：LK 0.96 s 装 md1rom →
  内核 2.24 s dpmaif probe（**仅驱动初始化，表未建**——修正 §10 之前的默认）→
  表建立推迟到 rcS（正常 boot <164 s；`init=/bin/sh` 时被推迟到 exec 后 ~5 s，
  A 轮实测 327 s，gen 1→2 仅一次）→ 建表+流量触发新受害页**爆发**
  （+300/min × ~2 min）→ **稳态** +40~55/min 持续不封顶。
- **静默相缓增（+10/min）= 陈旧页显现**：A2 证明写入者关闭时 distinct 仍以同速率
  爬升（allocator churn 暴露上 boot 签名）——buddyscan 累计口径在无重写场景不可作活性判据。

### 11.3 止写

- **已验证彻底停止：`AT+EPOF`（MD 断电）**——代价 WAN 死；作诊断闸门/
  干净窗口手段（如崩溃敏感操作前）。
- 已验证**无效**：驱动 unbind（U1）、`AT+CFUN` 翻转（§10 轮一，MD 不死）、
  `initcall_blacklist`（本内核机制失效）。
- 未试候选（留档）：ccci sysfs MD reset 节点、dpwr 写引擎/MD 复位寄存器、
  LK 期阻止 MD 镜像装载。
- 写入绕过 MMU，**内核侧不可拦截**；长期解决在 MD 固件（平台 vendor 域，超出本仓能力）。

## 13. 写入机制收口：SCP/MEDMCU 的陈旧 PIT 页（2026-10-28 中午，现场轮）

> 本节把 §11 的“MD modem 侧”从**排除法结论**推进到**格式级 + 直接页观测**：
> 写入者不是 AP 内核/驱动，也不是 MD 应用 CPU，而是 **MEDMCU/SCP（RISC-V RV33）
> 的 PIT transfer 路径**；写入记录就是 **16B 的 PIT 表项**，落在旧 PIT 页的
> 最后一个表项偏移 `0xfc0`。证据硬度：**已证实**（格式/页写）/ **强推断**（任务级身份）。

### 13.1 SCP 身份与代码面（已证实）

- `/dev/block/medmcu_a`：容器 `0x58881688` + `tinysys-medmcu-RV33_A`；
  载荷为 **RISC-V RV32 + RVC**（`0x15d03b56` 处 `wfi`）。
- 设备树：`scp_sramSize=0x20000`（128KB SRAM @ `0x15d00000`）；
  `lk_medmcu_reserved=0xAFF00000+0x40000`；
  `lk_medmcu_reserved_desc=0x9FCB0000+0x340000`。
- SCP 固件/运行日志含 `med_dl_pit_transfer`、`med_dl_pit_transfer_task`、
  `med_dl_pit_cfg_hw`、`med_dl_pit_trigger`、`med_dl_pit_release_flow`、
  `drv_mdma_dl_set_tx_desc_ctx_idx`；`/dev/medmcu` 每 60s 打印
  `pit(med_w/r, dpmaif_w/r)`、`bat(...)`、`tx_desc(...)`。
- SCP SRAM 内的 AP 环表（`0x15b1c`）含 `PIT 0x9ff3edc0(0x80f80)` 等
  (AP 地址, size) 对，说明 SCP 直接管理 PIT/BAT/DRX 环。

### 13.2 直接观测：旧 PIT 页在热重启后仍被写（已证实，本轮最关键）

- PIT base 每 boot 重新分配：冷启动 `0x8fa20000` → 热重启1 `0x8ff40000`
  → 热重启2 `0x8fb20000`。
- 热重启2 后，`pitwatch` 在**更早 boot 的旧 PIT 表**（`0x8fa20000`）内
  `0x8fa49000/0xfc0` 直接抓到 16B 写入：
  `{0,0x5e}`、`{2,0xffffffff}`；写后读回该页为全零（free 页被写后又被清零/回收）。
- 同一时刻当前 PIT 页 `0x8fb20000/0xfc0` 是正常表项 `{0x92cf2600,0}`、
  `{0x92cf1e80,0}`。
- **判定**：SCP/PIT 引擎在 AP 重新分配 PIT 表后，仍按**更早 boot 的旧 PIT base**
  往旧 PIT 页写 16B 表项；旧页已释放，写入落在页尾 `0xfc0`。这就是注入的直接来源。

### 13.3 记录格式 = PIT 表项（强推断，格式级已证实）

- live PIT 表项 16B：`{u64 PA, u64 0}`；4KB 页 256 项，最后一项在 `0xfc0`。
  ⟦2026-10-28 下午 §14 降级：本 boot 活 PIT 区 540s 全页监视 **0 次内存写**（med_w 同窗
  +394 次），且新捕获样本值形态不符——「注入记录 = PIT 表项」**降为存疑**，勿单独引用。⟧
- 历史注入块：16B `{small,0}` / `{0x9xxxxxxx,0}` 是单个 PIT 表项；
  32B `{small,0, 0x????????_0000_06xx,0}` 是两个连续 PIT 表项；
  `{BAT base, producer}` 对应 PIT 表项的 `{PA, flags}` 语义。
- BAT 表项是 8B `{PA,0}`，与注入的 16B 节距不同；PIT 是唯一同构的 16B 表。
  故 §11 的“任意 free/anon 页页尾 0xfc0”应改为
  **“陈旧 PIT 页的第 256 个表项”**——页尾不是随机选择，而是 PIT 节距的必然结果。

### 13.4 控制点与启停（已证实）

| 操作 | 结果 |
|---|---|
| AP dpmaif 驱动 unbind（U1） | 注入照写、r094 继续 → AP 驱动不是开关 |
| `dpmaif_stop(0)`（模块） | `CCCI_DPMAIF_EVENT_STOP` → `scp_sys_full_reset` → AP 重启 |
| `medmcu` platform driver unbind | AP 重启 → SCP 是关键路径 |
| `AT+EPOF`（D2） | 注入全停（12min×256MB 零命中）→ MD/SCP 电源域是总开关 |
| `init=/bin/sh` 不建表（A2） | 71 轮×65536 页零命中 → 表未编程时写入者关闭 |
| `scp_A_db_test=666` | SCP AED dump，AP 不重启；`scp_A_reg_status` 可读 PC/LR/SP |

**热/冷启动差异**：冷启动（sysrq-b/LK）后 pfcanary 0/4 崩溃；热重启
（`reboot -f`，跳过 LK）后 1/12s；更早的正常运行 boot 4/4 在 8s 内。
热重启保留 SCP/引擎状态，冷启动/EPOF 清除——与“陈旧 PIT base 跨启动保留”一致。

### 13.5 修正 §11 与剩余未决

- §11 的“写入者 = MD modem 侧（固件或受其指挥的 dpmaif 引擎 DMA）”方向正确，
  但粒度太粗。当前分层：
  1. **MEDMCU/SCP RISC-V 固件（`med_dl_pit_transfer_task`）**：最强嫌疑；
  2. **dpmaif PIT 引擎硬件**：消费者/可能的写代理；
  3. **MD 应用 CPU**：无直接证据，降为次要。
- 未决：SCP 内部保存旧 PIT base 的**具体变量/寄存器**（PIT base 影子 / 页链表
  next / 页池游标）尚未定位；物理写代理是 SCP CPU store 还是 SCP MDMA/FDMA
  描述符写也未区分。两者都在 SCP/MD 域、同受 EPOF/冷启动控制，对“止写”等价。
- 收口实验：多 boot 记录 PIT base 并监控旧 PIT 页；用 `scp_A_db_test`/
  `scp_do_tbufdump` 在 pfcanary 崩溃瞬间抓 SCP PC/LR；修法验证 =
  重新分配 PIT 表前先 `dpmaif_stop`/SCP reset，或在 SCP 启动时清零 PIT 页指针。

**现场记录**：`tmpfiles/sigsegv_scp_20261028.md`（本轮完整读数与产物索引）。

### 14.1 已证实

1. **单样本写入捕获**（pitwatch 60s @ 旧 PIT base A `0x8fa20000+0x40000`）：

   | 区 | PA | 页态 | hits（轮1/轮2） |
   |---|---|---|---|
   | 旧 PIT base A | 0x8fa20000 | **slab** | 25754 / 38366 |
   | 旧 PIT base B | 0x8ff40000 | slab 族 | 4239 / 7352 |

4. **受害页不必空闲**：旧 PIT base 区现为 slab 页；写入落在页复用后的现役数据上——

5. SCP SRAM（`mmdump` 128K）：`0x15b04` 起 8 对 (PA,size) 全指 SCP DRAM

### 14.2 结论修订

- **活 PIT 区零内存写 vs med_w 持续推进** ⟹ SCP 的 PIT 计数与 AP 内存 PIT 表脱钩；
  §13.3「注入记录 = 16B PIT 表项」**降级为存疑**（§13.3 已加⟦⟧标注）。
- r0/r1 的 ~40k 命中**不能整体归因写入者**：旧区现为 slab 页，命中与普通 slab 活动
  不可分（明细因 §7.16 全部丢失）；"陈旧 PIT 页仍在被写"目前只有 §14.1.1 单样本硬证据。
- SCP 固件静态反汇编**未推进**：relocatable 镜像（auipc/addi 未链接、字符串引用经运行期
  重定位），静态定位 `med_dl_pit_transfer` 写循环失败。需运行期插桩或带符号镜像。

## 15. SCP 固件静态收口 + 当前静默态（2026-10-28 下午第二轮）

> 本轮把 §14 遗留的「SCP 固件静态反汇编未推进」彻底做通，并给出一条**硬负结论**：
> 字节级写入不是 RV33 代码做的。同时给出当前设备状态的第一手读数：注入已静默。
> 报告全文：`tmpfiles/md/scp_re_report.md`；仪器：`tmpfiles/repro/{injwatch5,pairfind,pair64,pit2}.c`。

### 15.1 固件按 base 0 链接（推翻 §14.2 的"relocatable 不可静态解"）— 已证实

- 载荷 `1_tinysys-medmcu-RV33_A`（92192 B）**按 0 基址链接**：`lui+addi` 绝对寻址的结果
  等于**文件偏移**；188 个指针字与字符串/全局精确对齐；24940 条指令全静态可解。
- 全镜像 104 个 `lui` 立即数**没有一个**落在 0xaff 窗口，载荷里 `0xaffxxxxx` 指针 0 个 ——
  §13.1 的「0xaff00000 是 SCP 视角」是 AP 侧头部另一视角造成的错觉。
- §14.2「relocatable，静态定位写循环失败」作废：可以用 base 0 直接反汇编。

### 15.2 地址窗口换算：AP 0x90000000 ↔ SCP 0xf0000000 — 已证实

- 固件 0x124e4 处有换算表：`0x90000000→0xf0000000`、`0x10000000→0x60000000`
  （后者与 `0x6022d000 = AP dpmaif 0x1022d000` 吻合）；运行期 SRAM `0x15d1250c..0x15d12528`
  实测存在 `0xe0000000`/`0xf0000000` 两个窗口基址。
- 推论：**在 SCP 内存里搜 AP PA 必须加 0x60000000**。此前所有"SCP 侧无 PIT base"的搜索
  （§13.2/§14.1.5）都用了裸 AP PA，方法上无效——但**换算后重搜仍然为 0**（见 15.3）。

### 15.3 硬负结论：SCP 代码不写 AP DRAM — 已证实（store 指令级）

- 全镜像 2336 条 store 中**没有一条**的地址落在 AP DRAM 窗口（0x80000000–0xffffffff）；
  唯二常量高地址 store 是 `0xc0000010/0xc0000014`（复位/看门狗寄存器）。
- 没有 `base + index*16` 的 store 循环；没有 0xfc0 / 0x1000 / 0xfff 掩码；索引是 `remu` 取模回绕
  （模数 `ctx+0x08`），producer 索引存 `ctx+0x0c`。
- SCP 对 AP 地址的全部"知识"只有：运行期表 `0x15b04` 的 8 组 `{AP 基址, 长度}`
  （与 AP 驱动自己 `/proc/medhw/dram` 打印的 RX_DESC/PIT/DRB 段首**逐一相等**，由运行期消息填入），
  以及常量 `0xf0040000`（= AP 0x90040000）+ 长度 `0x40000` 写进 `ctx+0x2c/+0x30`，
  随后只被镜像进 MED-view 寄存器 `0x38028124/0x38028128`，**从此不再当指针用**。
- **判决**：物理写代理是 SCP 编程的 MDMA/PIT 引擎（**强推断**），不是 RV33 的 store。
  与既有控制点完全自洽：引擎未编程（A2）不写、EPOF 全停、AP 驱动 unbind 照写。

### 15.4 页内偏移 0xfc0 的算术解释 — 强推断

PIT 缓冲区基址 `0x9ff3edc0`（SCP DRAM）页内偏移是 **0xdc0**；16B 步进下**每 256 条必有一条**
落在页内 0xfc0（另有一条落在 0xff0）。⇒ 「页尾 0xfc0 高发」是**16B 节距 + 非页对齐基址**
的算术结果，不需要任何"页对齐/页尾"代码。此前把 0xfc0 当"第 256 个表项"的解释不必再假设。

### 15.5 方法论更正：`med_dl_pit_*` 字符串不是函数身份 — 已证实

这些字符串只是 LOG 的 `__func__` tag：`med_dl_pit_transfer`(0x10fed) **零引用**，
0x91a4–0x9ef6 一个大函数里同时打了 5 个 tag。§13.1/§13.5 用字符串给"任务级身份"定级**无效**。

### 15.6 当前设备实测：注入已静默（2026-10-28 15:46–16:15）

| 仪器 | 窗口 | 结果 |
|---|---|---|
| injwatch5 256 MB（全页逐 8B 扫描，非页尾取样） | 600 s | **0 / 65536 页** |
| injwatch5 384 MB（热重启后，1301 轮全扫） | 420 s | **0 / 98304 页** |
| injwatch5 768 MB（884 轮全扫，占 RAM 44%） | 480 s | **0 / 196608 页** |

零写入。**新鲜度探针**（pairfind）是本节最强的一条：BAT base 每 boot 变化
（`0x90040000→0x8fb00000→0x90980000`），因此"某页在 +0xfc0 持有本 boot 的 base"只可能

> 命中即本 boot 有注入；0 命中即静默。比 arena 监视便宜（0.1 s）。

### 15.7 活值对不是"活体环状态结构" — 已证实（全 RAM 8B 扫描）

`pair64` 全 RAM 搜 `{BAT base, r094}`（当 boot 实时值）：命中 3 处，全部落在
**printk/IRQ 栈帧**（上下文含 `el1h_64_irq_handler`/`_printk` 返回址）。
⇒ 该 8B 对是内核某处调试打印的**两个连续 vararg**，不是常驻结构；
"AP 侧存在一个被 SCP 镜像的环状态结构"假设**无证据**。
另：`pairfind` 按页偏移扫全 RAM，**没有任何页在 +0xfc0 持有 BAT base** ——
写者当前没有"活体落点"。

### 15.8b 更正 §11.1：「注入活跃 ⟺ r094 前进」不再成立 — 已否证

本 boot 实测：r094 在 256 KB PIT 环内**完整绕圈**（`0x909e0010 → 0x909c1fa0`，前进 ≥256 KB），
ccmni3 有真实流量（≈17 pkt/s），**同窗 anon 监视 175 M 页·秒零命中 + 新鲜度探针全 RAM 0 命中**。

⇒ 「引擎在产出」是**必要不充分**条件。§11.1 由「注入 ⟺ r094 前进」推出「引擎已编程即注入活跃」的
那一步降级为**未定**；把"引擎状态"当活性开关的推理不能再用。活性还取决于某个本 boot 不成立的状态。

### 15.8c 由目的地址形态可推的两条硬约束（本轮新增，已证实）

1. **不是"陈旧连续环"**：若环基址陈旧且连续，受害页必是该 256 KB 区间内的连续页；
   实测受害页**互相独立、遍布 DRAM**，页内偏移恒为 0xfc0/0xff0 ⇒ 地址源是**页粒度**
   （页指针列表/页表/逐事件页），不是"基址 + 连续下标"。
2. **不是搬数据**：受害页里只有 0xfc0（或 0xff0）一处变化，页内其余全零 ⇒ 写的是**单个
   8/16B 状态槽**，不是把 payload DMA 进缓冲。结合"内容含当前寄存器值"，
   形态最像**"往每页一个的状态槽里写回环状态"**。
