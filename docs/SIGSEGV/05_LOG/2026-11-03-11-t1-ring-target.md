## 1. 问题

C-197 已实证 mtk_warp 的两个 tuple 入口（`wifi_tx_tuple_add` / `wifi_rx_tuple_add`）
在中性态以 ~10.7 次/s 调用，且 `ctx+0x700` 指向的 ops 表三项回调 live 解析为
`mtk_wed+0xf8`（tx_fill）/ `+0x374`（rx_fill）/ `+0x3a4`（wo_rxcnt，本 build 为空桩）。
本实验回答：

> **tuple 填充路径的 store 目标（填充回调自身的写入目标，以及填充之后 tuple 消费者
> 写入的环目标）是否被污染成用户页——即是否为「线性别名且其 PA 属于 canary 栈页」
> 或直接的「用户 VA」？** 若是，则环项被写进用户栈页的机制被点名；若全部目标都是
> 内核环区/内核栈，则 H_ring 不成立。

## 2. 静态事实与措辞修正（开窗前已定，N2 E3 + 本机 objdump 复核）

1. **填充回调的自身写入目标是调用者的内核栈 scratch，不是环**：
   - `wifi_tx_tuple_add` @0x735c：`ldr x0,[x0,#0x700]`（ops）→
     `stp xzr,xzr,[sp,#0x40]` / `stp xzr,xzr,[sp,#0x50]`（清零 32B）→
     `add x1,sp,#0x40`（dest）→ `ldr x2,[x0,#0x18]` → `x0=pkt_info` → `blr x2`。
   - `wifi_rx_tuple_add` @0x727c：`add x1,sp,#0x20`（dest）→ 同样经 ops+0x50 调用。
   - `tx_fill`（.text+0xf8，首条 `ldr x2,[x0,#0x10]`=0xf9400802）向 `[x1]` 写
     `+0..0x1d`（30B，`str/strb`，源为 pkt_info 内层结构字段）；`rx_fill`
     （.text+0x374，首条 `ldr x2,[x0,#8]`=0xf9400402）向 `[x1]` 写 `+0..0xa`（11B）。
   - ⇒ **填充回调本身不可能把环项写进用户栈**（它的目标恒为内核栈 scratch）；
     H_ring 的原始措辞（「填充回调把环项写进用户栈」）在结构上不成立。
2. **真正的环写入发生在填充之后的 tuple 消费者**：
   - `wifi_rx_tuple_add` 0x72c4：`x0 = [scratch+0] = B`（B=[pkt_info+8]）→
     `ldp x2,x1,[B,#0xc0]`（cursor/end）→ 在 `[B+0xc0]`、`[B+0xc0]+4` 做 4B RMW，
     另在 `[B+0xc0]+[B+0xbc]-6`、`[B+0xc0]+[B+0xb8]-6` 做 4B RMW。
   - `wifi_tx_tuple_add` 0x739c 同构：B=[[pkt_info]+0x10]，`[B+0xc0]` 为 cursor，
     `[B+0xbc]/[B+0xb8]` 为偏移，`[B+0x74]` 为门控字。
   - ⇒ **环目标 = `[B+0xc0]`**（B 由 pkt_info 派生）；若该指针被污染成用户页的
     线性别名，消费者就会把环项 RMW 进用户栈页——这才是 H_ring 的可测形态。
3. **对任务措辞的修正**：`ctx+0x700` 是 ops 指针（不是环基址）；环基址在
   `[B+0xc0]`，B 在回调入口由 x0=pkt_info 派生（tx: `[[pkt_info]+0x10]`；
   rx: `[pkt_info+8]`）。仪器按此实现（方案 a：回调入口解析，不做 store 点双钩）。

## 3. 假设（先写死）

- **H_ring（主）**：填充回调入口处由 pkt_info 派生的环目标 `ring_ptr=[B+0xc0]`
  是**线性映射别名**（`0xffffff8000000000 ≤ ring_ptr < 0xffffffc000000000`），且
  `ring_ptr - 0xffffff8000000000` 的页号属于**canary 栈页 PA 集合**（patrace 实测）；
  或 `ring_ptr` 直接是用户 VA（`< 2^39`，VA_BITS=39）。⇒ 陈旧/污染环基址点名，
  tuple 消费者的 RMW 写进用户栈页；`ring_ptr` 处 32B 内容应与记录族同族。
- **H_ring_direct（次）**：填充回调自身 store 目标 `dest=x1` 是用户 VA 或
  「线性别名且 PA ∈ canary 栈页」。
- **H_ring_false**：窗内全部目标都是内核页（`dest` = 内核栈/vmalloc；`ring_ptr` =
  内核 linear/vmalloc 环），且没有任何目标的 PA 落在 canary 栈页集合；按
  §6 给出分布与上界。

## 4. 仪器（tuphook v1.6，v1.5 基础上增量）

- **保留** v1.5 的两个 tuple 入口钩（mtk_warp+0x7330/0x7268，记录 x0..x3/skb len/ip/
  cntvct）与全部安全构造（nofault、per-cpu 环、guard、stop_machine 文本窗口）。
- **新增两个填充回调入口钩**：替换 `tx_fill` 首条（0xf9400802）与 `rx_fill` 首条
  （0xf9400402）为 `B` 跳板；跳板保存 x0..x3/x8/x30/x19/x20，调用
  `tuphook_fill_probe(pkt_info, dest, is_rx, slot, lr)`，随后原样执行被替换的
  `ldr` 并跳回入口+4（paciasp 在原位执行，SP 已还原）。
- **每调用记录**（128B/条，per-cpu 256 条，head 仅在记录完整后推进，防撕裂）：
  `pkt_info, dest, lr, B, ring_ptr, ring_end, b8/bc, flag74, q0..q3(ring_ptr 处 32B),
  ts(cntvct_el0), src0..src2(填充将写入的源值), meta(读成功位 + 三类地址分类位)`。
- **地址分类**（VA_BITS=39）：user `< 2^39`；linear `[0xffffff8000000000,
  0xffffffc000000000)`；vmalloc/module `≥ 0xffffffc000000000`；null=0；gap=其余。
- **dryrun=1 正对照**：定位 ops / 三回调；打印 `ctx/ops/tx_fill/rx_fill/wo_rxcnt`；
  断言 tx_fill 首字 0xf9400802、rx_fill 首字 0xf9400402、二者同页、
  `sprint_symbol` 含 `mtk_wed`；**不写一字节**。
- **live 正对照**：`/proc/tuphook` 头 `PATCHED`；两个 tuple 入口读回 = 我们写入的 B；
  两个填充入口读回 = 我们写入的 B；填充记录数在窗内增长 > 0。
- **canary**：`vsurv5`（md5 af0b6f87c5ee17e571d50751ffc4154b）≥4 实例；开窗/收窗各用
  `patrace.ko` 把每个 canary 的 8 个栈页（start_stack−k·4096，k=1..8）翻成 PA，
  形成 canary 栈页 PA 集合；崩溃 h5 dump 的 x2 也翻 PA 复核。

## 5. 窗与有效性门禁（任一不满足 ⇒ 该窗 INVALID）

1. `boot_id` 窗内不变；无 oops/panic/BUG；无计划外重启。
2. dryrun 输出与 §4 的 ops/回调/首字/同页断言逐项一致；不一致 ⇒ 拒绝加载。
3. live `/proc/tuphook` 头 `PATCHED`；填充记录总数 `N_fill ≥ 1000`（按 ~10.7/s ×
   1800s 的期望，功效下限；若实际调用率低，按实测率给出上界，不硬判 INVALID）。
4. canary 窗内 ≥1 实例存活；开窗与收窗的 patrace 栈页 PA 集合非空且可解析。
5. 采样：每 5 s 读一次 `/proc/tuphook`（maxread=64/CPU），PC 侧落原始输出；
   窗起/窗止记 `date +%s`、`/proc/uptime`、`boot_id`。
6. 收窗：`rmmod tuphook` 后两个 mtk_warp 入口与两个 mtk_wed 入口读回原始字
   （0xd503233f / 0xf9400802 / 0xf9400402），`TRY_A=0`，0 个我方模块（dieblx/patrace
   也卸），canary 全部 kill。

## 6. 判据（预写死，不改）

- **命中定义**：某条样本的 `ring_ptr`（主）或 `dest`（次）满足
  ① 类别 = user；或 ② 类别 = linear 且 `(target - 0xffffff8000000000)` 的页号
  在 canary 栈页 PA 集合内。
- **H_ring 成立**：主端点 `ring_ptr` 出现 ≥1 命中。点名样本的 `ts/seq/target/PA/
  canary pid`，并报告 `q0..q3` 是否与记录族同族（A0B2/B0A2）。
- **H_ring_direct 成立**：次端点 `dest` 出现 ≥1 命中。
- **H_ring 不成立**：主端点 0 命中且 `N_fill ≥ 1000`；给出 95% 上界 `3/N_fill`
  与完整分布（user/linear/vmalloc/null/gap/不可读），并分别给 tx/rx 与 dest/ring_ptr。
- **内容对照**：对全部样本与命中样本分别统计 `q1==0 && q3==0 && q0!=0` 且
  `len∈[0x40,0x4000]`、ip 首字节非 0/127/224..255（A0B2），或
  `q0!=0 && q1==0 && q2∈[0x1000,0x100000] && q3==0`（B0A2）的条数。
- **INVALID**：任一 §5 门禁失败；不得用 0 命中下结论。

## 7. 停止规则

1. 仪器缺陷导致崩溃 ≥2 次 ⇒ 弃该路径，停工报告（不第 3 次尝试）。
2. 每次崩溃后先读 `TRY_A`（misc p1 offset 2060，期望低字节 0x0f 且 `[1]=0`）；
   >0 且未清 ⇒ 暂停并报告（不擅自写 misc）。
3. **8 分钟 lgssh 不可达红线** ⇒ 停工，如实报告（不擅自重启、不等待用户）。
4. 窗内非计划重启：该窗 INVALID；恢复后只允许重跑 1 次（同一缺陷计 2 次）。
5. 安全红线：不写 p25/p38/p39；不碰 bootctrl；misc 只读；设备写一律经 deploy.py。
6. 18:45 硬停；18:30 前设备回中性。
