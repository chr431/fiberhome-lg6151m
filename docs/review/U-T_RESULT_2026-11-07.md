## 1. 洪水 λ 杠杆与相位

- 无洪水（host mode，双匿名栈）：lam1 130s **6** 真实 appear（2.8/min）；lam2 120s **3**（1.5/min）。
- 洪水（3×800pps→37777）：lam3 190s **18**（10.4/min）；unpinned_ctl 240s **A=24 R=24**（≈22/min）；
  ABAB 的 4 个 unpinned 臂 26/68/35/40 events/60s（记录里 ip=192.168.9.1、len=321/1601）。
- 判读：λ 随**设备面向的处理活动**走（C-297 同向），洪水把"活动"拧到高档；**记录内容就是洪水包**，
  这是第一次在受控输入下把"内容→记录"链路钉死。
- 注：C-338 的"port 9 / 37777 合成洪水无效"是低相位 boot + 当时实验条件的结论；本轮同一 ug1 脚本
  可复现 7–68/min。**跨 boot 比较仍按 C-288 纪律**。

## 2. 真实 p11 受害者栈上的 32B 记录（端到端闭环）

- 事件：`grep -q to 192.168.9.0/24 lookup main`（wan_eth.sh 子进程）在 1793985809 死亡，
  pc=0x4c8728（vgetopt32）、far=0x263cd；core_meta 落盘 stack 65592B（md5 fc34d6d1…）。
- 解码：0xf3c8 处 32B = `cd 63 02 00 00 00 00 00 | 00… | 41 01 00 00 c0 a8 09 01 | 00…`
  = `{A=0x263cd, 0, {len=0x141, ip=192.168.9.1}, 0}`；0xf3e8 紧邻是**未被覆盖的 va_list**：
  `{0x7fc0b5d480, 0x7fc0b5d480, 0x7fc0b5d450, 0xffffffd8, 0xffffff80}`。
- 判读：①记录载荷=洪水包（len/ip）；②记录精确替换一条 va_list（word0→__stack=A，va_arg 读 A→far=A）；
  ③p11（q2..q7 全掩蔽）仍死在同一 vgetopt32 家族；④相邻 va_list 完好 ⇒ 写者是**逐槽精确**命中，
  不是整页涂画。

## 3. p13（va_list 值重基）判决

**设计**：写者写入前校验槽内"活 va_list 内容"（K9）。若校验依赖规范字面值（vr_top=FP save top、
vr_offs=-0x80），则把 vr_top+16、vr_offs-16（有效 FP 实参地址不变）可让校验失败而功能不变。

**实现**：
1. 二进制补丁 `tools/oneoff/varpro_rebase_vr.py`：识别 GCC（`mov wN,#-0x80; str wN`）与 clang
   （`movk xOFF,#0xff80,lsl#32`+`add xVR,xBASE,#0x80`）两种惯用法；静态 busybox 37 站点、
   scanary_exile 4 站点；qemu/设备功能电池（echo/awk printf/printf %f/sh 算术）全等。
2. C 级验证 `reb_test`：真实编译器变参函数 va_start 后用 C 改 vr_top/vr_offs，va_arg 消费 3 个
   long 返回 6（rc=6）⇒ 重基语义正确。
3. **判决臂 basereb**（vamorph：真实编译器 prologue + C 重基，与 base 同调用）：
   base **121** events/300s（A6+C115）、basereb **114**（A3+C111），RR=**0.94**。
   合成台长臂同向：natfp 180/600s vs rebv 69/248s（同量级）；短臂差异是相位噪声。
4. 旁证：scanary_exile 的真实命中槽仍是 -0x80（4 个 movk 站点未覆盖第三种惯用法），说明
   "打到哪个站点"与"值是否重基"是两件事；但 basereb 已用真实 prologue 直接证伪该假说。

**结论**：写者的活内容校验**不依赖 va_list 的规范字面值**（或只校验有效地址/结构可解性，
重基保持这些）。**p13 关闭**。

## 4. per-CPU pin：50× 隐身假象与放大器定性

### 4.1 scanary ABAB（60s 臂，洪水常开）

| 臂 | 事件（APPEAR+REWRITE/CHANGE） |
|---|---|
| u1 unpinned | 26 |
| p0 CPU0 | **0** |
| u2 unpinned | 68 |
| p1 CPU1 | **0** |
| u3 unpinned | 35 |
| p2 CPU2 | **0** |
| u4 unpinned | ~27（未满窗截断） |

p0 的 STAT/EXIT：passes=11719、exit reason=duration、crash=0 ⇒ 进程正常工作，零命中不是假象。
abab2：p3 CPU3=0；p01（0,1）=2；p012（0,1,2）=12（49s 时被本轮的 kill 扫描误杀）；
u5=13、u6=29、u7=15。⇒ **可见性随 CPU 集大小单调上升**，单 CPU 集=0，全 4 CPU=13–68/min。

### 4.2 真实单线程受害者的反证

- **mini**（真实编译器变参、无扫描线程、紧循环）：nopin 0、pin 1、bounce（taskset -p 每分钟迁移 60 次）1 条记录/60s。
- **mini2**（同变参 + 10ms nanosleep，栈槽稳定驻留）：nopin **1**、pin **1** 条记录/60s（洪水常开）。
- 对比：scanary 的 20–70 events/min 高 20–70 倍。scanary 与 mini 的结构差 = **扫描线程每 5ms 读
  受害者栈**（跨 CPU 时造成栈缓存行一致性流量）。
- **判读**：scanary 的 λ 是**仪器放大**的：扫描线程的跨 CPU 读栈把"栈行被多 CPU 访问"这一信号
  持续喂给写者；pin 把全部线程压到一个 CPU，放大器消失 ⇒ 0 命中。**单 CPU pin 不能外推为真实
  服务的缓解**（mini2 证明被动单线程进程 pinned/unpinned 同率 ~1/min）。
- 这同时解释了 U-H/U-I 的高 λ（scanary/vamorph 都是多线程+扫描）与 p11 部署后真实死亡仍稀疏。

### 4.3 放大器排除实验（wb / 迭代数 / 独立 reader）

| 实验 | 结果 | 排除/保留 |
|---|---|---|
| **迭代数对照**（pinned vs unpinned EXIT） | itA/itE≈5908–5937/60s、passes≈11719–11794、scan_us_avg≈3.58–3.62ms，两端**一致** | 排除"pin 后扫描器抢 CPU 导致工作负载下降" |
| **writeback**（safe vs none，ABAB） | safe：A=11/R=17、A=8/R=18；none：A=15/R=0、A=26/R=0 ⇒ 哨兵 32B 写回只制造 REWRITE，**不改变 APPEAR 基率** | 排除"哨兵写回是主放大器" |
| **独立 reader 进程**（/proc/pid/mem 每 5ms 读受害者栈，pin 到另一 CPU；含修正窗口） | mini2 无 reader 1 条 vs 有 reader 1 条（两轮，含把读窗修正为栈顶 64KB） | 排除"跨进程跨 CPU 读栈" |

| **同进程跨 CPU reader 线程**（mini5：300 层递归各带一个**活且不被覆写**的 va_list 槽 + reader 线程；none/same CPU0/cross CPU1 三臂，60s） | 三臂栈内**均 0 条记录**（跨 ~150 个活槽、60s） | **否证"同 ASID 跨 CPU 栈访问"假说**（stride 64 的读已触到每一缓存行） |

**判读**：scanary 的 APPEAR 基率（15–26/60s）在同迭代数下被**单 CPU pin 打到 0**；但它既不是
哨兵写回、也不是跨进程读栈、也不是同进程跨 CPU 的稀疏/行级读（mini5 0 记录）⇒ **放大器机制未定**。
剩余候选：①scanary 的 printf 重负载（每调用多次 32B va_list 拷贝）与 pin 后同 CPU 交错的时序差；
②scanary 的 pthread mmap 栈布局/poison/sentinel 内容；③扫描器的**密集扫描时序**（每 5ms 扫
0x220 窗口 × 200 次/秒）与受害者 store 的耦合。**无论机制如何，pin 已不能作为真实服务缓解**：
被动多帧变参受害者（mini5）在 60s 内连一条记录都没有，说明 scanary 的 20–70/min 不可外推。

**对真实服务的含义**：真实单线程进程没有同进程跨 CPU 栈访问；其攻击率只能由"同进程多线程共享
栈"或迁移产生。mini2 的栈快照只能证明"死亡/停止时刻栈上有 1 条记录"，**不能测速率**（紧循环会
覆写槽）；真实速率需停顿采样或连续检测器，是下轮要解决的方法学问题。

## 5. 隐身天花板：p11 残余 32B q 事务

- `bb_p11` 普查：`str q→[sp]` **162**、`stp q→[sp]` **9**、`stp q→非 sp` **363**（绝大多数是
  va_list 拷贝，如 `stp q0,q1,[x1]`）；stock 为 399 条 q→[sp]。
- U-H/U-I：写者指纹 = **32B q-pair 保存/拷贝序列**（natfp 加 4×stp q→0.86；nat/strb/split 全 0；
  8×str q = 0.55）。⇒ p11 掩蔽了 q2..q7 的 16B/32B 保存，但 **363 条 32B va_list 拷贝 + 9 条
  stp q0,q1 保存**仍在，写者仍有指纹。
- 真隐身 = 把这些 32B 事务拆成 16B/8B。1→2 指令无法原地展开，需 **trampoline（bl+两 str+ret）**
  或**编译器级 va_start/struct-copy 改造**；363 站点+ELF 手术是可做的下一轮工程，但不是本轮可交付。

| 路径 | 状态 | 依据 |

**根修复结论**：写者是存储子系统内 post-MPU 固定功能引擎（C-266）。本轮把最后两个"本机可达
控制面"关掉：MED IPI 主路径是复位握手（force_stop 分支窗口 >1s 可达，但停数据面、不可归因），
ATF SMC 全表无手柄。**本机不存在可用的写者关断手柄**；T4 的技术前提（SBC 关、BL31 可重签）已
具备，但**关引擎载荷未知**（bit15 盲写 DRAMC/DFX、DDRPHY+0x1520 不可读、无 p24/p37 回滚），
按"关引擎"目标判不推荐上机，等 T7 位定义或 DDRPHY 读法；只剩 T7（厂商）是干净路径。

**[B] 未核实/边界**
1. scanary 放大器的微观机制（扫描线程跨 CPU 读 vs 其他多线程效应）未用"独立 reader 进程"直证；
   mini2 的 1 条记录统计量小（1 vs 1，不能排除 <2/min 的差异）。
2. 被动进程的真实攻击率只测了 60s 窗（~1/min）；长窗（小时级）未测。
3. per-CPU pin 对真实多线程服务（wpad？）的效果未测。
4. T4 的载荷位定义未定（bit15 置位者/语义、DDRPHY+0x1520 读法）；force_stop 的 ACK 必达性/
   MED WDT 行为/DDR 数据面停摆后的写者 λ 未测。
5. p13 只测了 vr 重基 + 完整 gr/vr 重基（合成长臂）；其他结构伪造（word0/word1 重基）未测。

**[C] 下轮入口**
1. **放大器直证**：独立 reader 进程（/proc/pid/mem 每 5ms 读受害者栈）能否把 mini2 的 ~1/min
   拉到 scanary 量级；若能，则"跨 CPU 栈行访问"就是写者的目标捕获触发器（机制级收口）。
2. **真实多线程服务 pin 实验**：wpad/dnsmasq 等有跨线程/跨 CPU 栈访问的进程，pin 后 NE 率是否下降。
3. **32B 拆宽工程**：trampoline 方案（bl+2×str+ret）处理 363 条 va_list 拷贝 + 9 条 stp q0,q1；
   或在自研 musl/busybox 源码层消除 va_list 拷贝。
4. T4：SBC 已实测为关、BL31 可重签（C-348）；下一步不是重签本身，而是**载荷位定义**——bit15
   的置位者/语义、DDRPHY+0x1520 的读法，或等 T7 厂商位定义；p24/p37 回滚管线需先做备份-写回-
   冷启动演练。未拿到位定义前不做盲写。
5. p13 的 word0/word1 重基变体（__stack/__gr_top）可作最后的结构伪造子因。
6. **T4 载荷位定义**：确认 bit15 的置位者/语义与 DDRPHY+0x1520 读法（或等 T7 厂商位定义）；
   做 p24/p37 备份-写回-冷启动演练后再谈重签 BL31。
7. **force_stop 路径 B（若要做）**：EL1 kmod 在同一回调内"写 needforcestop=1 + 发 chan13"，
   ACK 后清 0；先 kallsyms 两路偏移互验 + `scp_A_status` ready 门禁；预期数据面停摆、λ 不可归因。

## 8. 对总档的落点

- VERDICT §31（C-339..C-345）；CLAIMS 追加；00_STATE U-T 指针；13_BLOCK_PATHS：
  T1b/T2 追加"关闭"注记、T5 追加"p13 关闭/32B 拷贝天花板"、per-CPU 注记改为"scanary 放大器"。
- 一句话：**根修复本机无手柄（T1/T1b/T2/T3 全关，T4 未交付）；p13 关闭；p11 封顶于 363 条 32B
  va_list 拷贝；洪水是可靠的 λ 放大器，scanary 的 per-CPU 隐身是仪器放大器效应，不是真实缓解。**
